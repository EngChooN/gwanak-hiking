# 변경기록 2026-11-11 — 릴스 장면 자동 녹화·편집 (산개발)

상위 업무: 인스타 릴스 온라인 등산 소개 영상 · 4/4단계. 기준 문서: `docs/릴스-콘티.md`, `docs/릴스-장면위치.md`, `docs/릴스-사용조건.md`.

## 결과물
- `artifacts/reels/gwanak-reels.mp4`: 1080×1920, 30fps, H.264 High와 AAC 48kHz 192k로 만든 **40.0초** 영상입니다. 소리는 −16.6 LUFS로 맞췄습니다.
- `artifacts/reels/cover.png`: 표지입니다. 훅 장면 1.4초 지점 화면에 문구가 들어가 있습니다.
- `artifacts/reels/reels-timeline.json`: 장면별 시작·끝 시각, 원본 녹화 구간, 자막, 캡처 fps, 콘솔 오류 수를 적었습니다.
- `artifacts/reels/raw/`: 장면별 원본 녹화본입니다(mp4·wav·json). `artifacts/reels/edit/`에는 자막 PNG와 중간 파일을 두었습니다.

## 다시 만들기
```sh
cd ~/gwanak-hiking && . ~/.nvm/nvm.sh && nvm use 24
npm run reels                  # 녹화 → 편집을 한 번에(개발 서버 5173·함께 걷기 서버 8787이 꺼져 있으면 잠시 켰다가 끕니다)
npm run reels -- --edit-only   # 편집만 다시
npm run reels -- multi,bino    # 일부 장면만 다시 녹화하고 편집
```
ffmpeg는 Homebrew로 설치했습니다(`/opt/homebrew/bin/ffmpeg` 9.0.2).

## 만든 방식
- **녹화(`scripts/reels-record.mjs`)**
  - 장면마다 휴대폰 세로 화면(360×640 ×3) 새 창을 엽니다. 자리·시간·계절·시선 값은 `reels-scenes.json`에서 읽습니다.
  - 화면은 CDP 스크린캐스트로 받습니다. 프레임마다 시각이 붙어 와서 30fps로 고르게 다시 뽑습니다. 실제 캡처는 약 60fps였습니다.
  - 소리는 게임의 AudioContext 출력을 `MediaStreamDestination`으로 갈라 `MediaRecorder`로 녹음합니다. 발소리·환경음·효과음·라디오가 모두 이 한 곳으로 모입니다. 그래서 효과음 파일을 따로 덧깔지 않았습니다.
  - 장면 json에 조작 시각을 남깁니다. 편집은 이 시각을 기준으로 영상을 자릅니다.
- **편집(`scripts/reels-edit.mjs`)**
  - 콘티 §1의 12장면을 이어 붙입니다. 장면 사이는 0.2초 교차 페이드로 넘기고, 훅→산 고르기는 컷으로 넘깁니다.
  - 엔딩은 0.3초 페이드인으로 시작해 3초 동안 보입니다.
  - 자막은 콘티 §5 규칙대로 HTML로 그려 투명 PNG로 얹습니다. 서체는 Apple SD Gothic Neo ExtraBold이고 크기는 76/44px, 훅만 96px입니다. 바깥선은 8px이고, 이모지는 Apple Color Emoji로 씁니다.
  - 자막이 안전 영역(x 64~912, y 250~1500)을 벗어나면 스크립트가 멈추도록 했습니다.
  - 배경음악은 넣지 않았습니다.
- **소리**
  - 들어간 소리: 발소리(흙·포장·나무계단), 숲·새·계곡·바람·도시 환경음, 라디오 99.1 「숲과 바람」(CC0)입니다.
  - 능선 발소리(Yo Frankie!, CC BY)는 능선 위를 걷지 않아 들어가지 않습니다. 라디오 91.9(Kevin MacLeod)도 쓰지 않았습니다. 따라서 소리 쪽 크레딧은 필요 없습니다.
  - HUD 출처 줄(Open-Meteo·OSM)이 보이는 컷이 있으니, 캡션에 출처 문장을 넣어야 합니다(콘티 §6, 사용조건 문서).

## AI Office 앱 화면
- `screencapture -l`로 앱 창 하나만 찍는 것은 됩니다(다른 창·메뉴 막대 없음).
- 다만 찍을 때 앱이 사무실 화면이 아니라 설정·직원 업무 기록 화면이었습니다. 사용량(%), 비용($), 업무 내용도 보여 영상에 쓰지 않았습니다. 찍은 파일도 지웠습니다.
- 대표님 창을 제가 직접 바꾸지도 않았습니다.
- **넣는 법:** 대표 확인을 받은 앱 창 캡처를 `artifacts/reels/office/ai-office.png`로 두고 `npm run reels -- --edit-only`를 실행하면, 35~37초에 카드로 자동으로 들어갑니다.

## 게임 코드 수정
- **`src/ambient-audio.js` `attach()`**
  - 게임이 이미 진행 중일 때 처음 소리를 켜면 환경음 버스 음량이 0에 머물렀습니다. 그래서 바람·새·계곡 소리가 들리지 않았습니다. 이제 버스 음량을 1로 올립니다.
  - 이 문제는 산 고르기 화면을 건너뛰고 들어오는 `?pick=off` 주소, 자동화 브라우저, 첫 터치가 게임 시작 뒤인 경우에 생겼습니다.
  - 산 고르기에서 ▶ 오르기를 누르는 보통 흐름에서는 생기지 않았습니다.
- 확인 결과: `npm test` 821개가 모두 통과했습니다.

## 11-14 대표 지적 반영 (산기획) — 산스장 상호작용·쌍안경 남산·롯데타워
- **지적:** 산스장에서 역기 드는 등 상호작용이 거의 안 보이고, 쌍안경으로 롯데타워·남산타워 보는 장면이 제대로 안 나옴.
- **원인:** 즐길거리 장면은 '산스장 들르기' 버튼을 누르고 2.6초 만에 끝나 역기 장면이 없었다. 쌍안경은 63빌딩 쪽(328°→346°)만 비췄다.
- **장면표(40초 유지):** 입구·계곡·계단 4→3초. 즐길거리 4초 → `autowalk` 2초(들르기 버튼) + `gym` 4초(역기 연타 1/10→10/10, "득근!!", 산스장 득근 도장 알림). 쌍안경 4초 → `namsan` 2.6초(N서울타워 10.3°, 8→10배) + `lotte` 2.4초(롯데월드타워 58.6°, 8배).
- **녹화(`scripts/reels-record.mjs`):** 역기 자리에 서면 카메라를 정면 쪽으로 80° 돌린다(뒤에서는 타이어가 화면 아래를 가림). 들어 올리기 버튼을 0.26초 간격으로 10번 누르고 득근 이벤트가 안 오면 실패로 멈춘다. 쌍안경은 배율만큼 시선이 덜 돌아가서 지금 방위를 읽으며 목표 방위로 맞춘다(aim·tilt). 영상에서만 렌즈를 가리는 설명 카드·'이름표' 버튼·한강 이름표를 숨긴다(타워 이름표는 그대로).
- **게임 수정(`src/interaction-ui.css` `.ix-focus`):** 휴대폰에서 쌍안경 설명 카드가 화면 절반 폭으로 눌려 세로로 길게 늘어나 렌즈를 가렸다. `width:max-content`로 글 길이만큼 넓히고 94vw에서 줄바꿈한다. 카드가 렌즈 아랫부분과 조금 겹치는 것은 남아 있다.
- 확인: `npm test` 837개 통과. 영상 40.00초, 장면 14개, 녹화 오류 0. 프레임으로 역기 연타·득근 도장·남산타워·롯데타워 이름표와 실제 탑 모양을 봤다. 비교 그림 `artifacts/reels/수정-2026-11-14-산스장-쌍안경.png`.
