# after13 — 길가 연속 그늘 띠 축소

산개발 / 2026-11-03. 구현 제출, 실행 검수 대기.

## 변경

- 바위 밑면 반경 `b = max(변환된 밑부분 상자 X폭,Z폭)/2`로 계산한다. 음영 반경은 `clamp(b + min(0.5,b×0.4),0.45,4)m`, 차폐율은 `0.36×min(1,b/0.8)²`다. 작은 rock_09에 일괄 적용되던 최소 1.2m·36%를 제거했다. 예: b=0.15m → 0.45m·1.27%, b=0.4m → 0.56m·9%, b=1m → 1.4m·36%. b≥1.25m는 종전 반경·차폐율과 동일하다. 0.8~1.25m는 36%를 유지하며 반경만 조금 좁아진다.
- 식생·노면 보호 폭 0.15m·셰이더·지도 해상도·중첩 최댓값 정책·계단 형상·접지 계산은 수정하지 않았다. 큰 바위의 실제 15~40단계 유지와 40 초과 0은 캡처로 확인해야 한다.
- `baseRadius`를 contactProbes에 포함한다. 회귀 테스트에 작은/중간/큰 바위의 반경·차폐율 차이를 추가했다.

## 왼쪽 아래 얼룩 추적

10차 `route-surfaces/results.json`의 third.contactProbes를 (460,680)까지 화면 거리로 정렬하면 가장 가까운 개체는 `rock_09`, world=(590.57956,275.19351,2442.45408), 화면=(443.62,598.65), 반경=1.2m, 차폐율=0.36, visible=true다. 다음 가까운 rock_09 접촉점은 (556.44,464.31), (266.39,878.20)이다. 첫 개체의 넓은 그늘이 후보지만 **중심 투영만으로 해당 화소의 원인이라고 확정할 수 없다.** visible은 LOD 조상 표시 여부이며 지형/개체 가림 판정이 아니다.

`hiking.contactPixelProbe(460,680)`는 해당 화소 광선과 지형·노면의 첫 교차점을 찾고, 그 지점을 실제로 덮는 접촉 음영 후보를 weight 순으로 반환한다. weight는 텍스처 필터·노면 보호 전의 원형 스탬프 기여율이므로 최종 화소 차이와 같지는 않다. 계단 캡처의 `contacts.third.lowerLeftProbe`에 자동 기록한다. 이 결과의 id·world·baseRadius와 전후 화면을 대조하면 작은 돌의 과대한 그늘인지, 화면 밖/가려진 물체인지 구분할 수 있다. 이번 수정은 후보를 임의 삭제하지 않고 작은 밑면에 맞게 그늘을 축소한다. 원인 확정은 새 캡처 전까지 보류한다.

## 길 가장자리 띠 지표

바위/숲 `comparisons[].routeEdgeBand`, 계단 `contacts.first/third.routeEdgeBand`에 기록한다. 1440×900 고정 캡처의 24px 간격 표본을 지형으로 역투영하고, 경로 선분까지 거리에서 노폭 절반을 뺀 값이 0~2m인 표본만 남긴다. 모든 접촉 후보의 밑면 반경 안은 제외한다. 음영 끔/켬 이미지의 휘도 감소를 0 이상으로 제한해 평균·최댓값·40 초과 표본 수·3단계 이하 권장 충족 여부를 기록한다. 표본 0이면 평균과 판정은 null이다. 평균을 낮추는 밝아짐 상쇄는 없다.

이는 **화면 기반 보조 지표**다. 위쪽 25%, 좌우 80px, 아래 80px는 제외하지만 UI와 물체 가림을 완전히 제거하지 않는다. 반경은 실제 밑면 외접 상자 근사이며 원형으로 제외한다. 표본·세계 좌표를 mask에 남겨 오염을 재확인한다. 임의 UI 변화와 등산객 자세 차이는 최종 검수에서 구분해야 한다. 진단은 캡처에서만 호출하며 프레임 루프·벤치에는 추가하지 않았다.

## 가정

기존 CC0 모델·임시 배치 기반 근사다. 밑면 반경 제곱을 작은 돌 차폐율의 면적 비례 근사로 사용했다. 큰 돌은 기존 36%를 유지하면 기존 목표 명암을 보존할 것으로 가정하나 시각 합격은 미확정이다. 약 0.72m/텍셀 지도보다 작은 음영은 약해지거나 사라질 수 있으며 해상도/성능 정책은 유지했다.
