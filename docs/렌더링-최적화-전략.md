# 렌더링 최적화 전략 — "다 그리지 않고, 그렇게 보이게"

작성: 산기획 · 2026-11-03
배경: 대표 질문 — 실제 관악산 재현(고해상도 지형·실제 수종 숲·시설)을 전부 그래픽으로 넣으면 프레임이 떨어지지 않나? 순례길 걷기 게임들은 왜 안정적인가?

## 핵심 원리

순례길·워킹 시뮬레이터류가 안정적인 이유는 **모든 것을 같은 정밀도로 그리지 않기** 때문이다. 플레이어가 길을 따라 천천히 걷는다는 특성을 이용한다.

1. **거리별 정밀도(LOD)** — 발밑 10m만 고정밀, 100m 밖은 단순 모델, 1km 밖은 그림 한 장.
2. **보이는 것만 그리기(컬링)** — 화면 밖·능선 뒤·멀리 있는 것은 아예 계산하지 않는다.
3. **같은 것은 한 번에(인스턴싱·병합)** — 나무 1만 그루도 수종별 1회 그리기.
4. **미리 구워두기(베이크)** — 그림자·조명·원경은 실행 중 계산 대신 미리 만든 사진/텍스처.
5. **필요한 곳만 불러오기(스트리밍)** — 코스가 정해져 있으니 다음 구간만 미리 읽어둔다.
6. **프레임 예산 고정 + 자동 화질 조절** — 목표 fps 미달 시 해상도·그림자 거리를 자동으로 낮춘다.

## 우리 프로젝트에 적용할 기법

| # | 기법 | 내용 | 현재 상태 | 기대 효과 |
|---|---|---|---|---|
| 1 | 나무 4단계 LOD + 임포스터 | 0~40m 실제 모델 / 40~120m 단순 모델 / 120~400m 십자판 / 400m+ 임포스터(여러 각도에서 찍은 나무 사진판) / 1km+ 숲 질감을 지형 텍스처에 굽기 | 3단계 LOD(0·48·110m)까지 | 숲 삼각형·드로우콜 대폭 감소 |
| 2 | 지형 CDLOD(거리별 격자) | 고해상도 DEM(5m)은 발 주변에만, 멀리는 단계적으로 성긴 격자. 능선 실루엣은 노멀맵으로 세부 표현 | 64m 청크 2m 격자 + 상시 8m | 5m DEM을 넣어도 삼각형 증가 억제 |
| 3 | 바위·암릉 디테일 = 노멀맵/시차맵 | 암릉 세부를 폴리곤이 아니라 텍스처로 표현, 가까운 대표 바위만 실제 메시 | 일반 바위 | 실제 같은 표면, 비용 작음 |
| 4 | 원경 서울·한강 = 스카이박스/원경판 | 정상 전망은 고정 시점이 많아 원경을 파노라마 사진판으로 대체 | 3D 원경 | 원경 비용 거의 0 |
| 5 | 그림자 계층(Cascaded) + 원거리 베이크 | 실시간 그림자는 30~60m만, 그 밖은 지형에 구운 그림자 | PCFSoft 단일 | 그림자 패스 비용 감소 |
| 6 | 컬링 강화 | 청크 경계상자 절두체 컬링 + 능선 뒤 가림(지형 기준 가시성 미리 계산) + 작은 물체 거리 컬링 | 기본 절두체만 | 드로우콜 감소 |
| 7 | 시설(연주대·계단·데크) 병합·LOD | 시설은 재질별로 병합한 청크 메시, 멀리선 단순 형태 | 없음 | 시설 추가 비용 억제 |
| 8 | 코스 기반 스트리밍 | 코스 진행 방향 다음 구간 자산을 Worker에서 미리 준비 | 카메라 기준 청크 생성 | 경계 통과 끊김 제거 |
| 9 | 텍스처 압축(KTX2/Basis) + 아틀라스 | GPU 메모리 1/4~1/6, 로딩 속도 개선 | 미적용 | 메모리·로딩 |
| 10 | 자동 화질 조절(동적 해상도) | 최근 프레임 시간이 목표 초과 시 렌더 해상도·그림자 거리·SSAO 단계를 자동 하향, 여유 생기면 복귀 | 수동 화질 3단계 | 어떤 기기에서도 fps 안정 |
| 11 | 알파 오버드로 제한 | 풀·잎의 투명 겹침을 알파 테스트(+디더)로, 바닥 풀은 근거리만 | 미측정 | GPU 병목 완화 |

## 원칙: "측정 → 병목 확인 → 적용 → 재측정"

- 위 기법은 효과가 큰 순서대로 적용하되, 반드시 `scripts/benchmark-performance.mjs`로 전후 수치를 남긴다.
- 기준: 높음/M 시리즈 Mac 평균 55fps 이상, 균형/CPU 4배 30fps 이상, 50ms 초과 프레임 1% 이하(기존 `성능-측정과-렌더링-예산.md`).
- 실제 관악산 재현 자산(산풍경)은 이 LOD·임포스터·병합 형식으로만 넘긴다. "고해상도 원본"과 "화면용 자산"은 항상 분리한다.

## 우선순위

1단계(가장 효과 큼): #10 자동 화질 조절, #1 나무 임포스터, #6 컬링, #5 그림자 범위
2단계(실제 재현 자료 들어올 때 함께): #2 지형 CDLOD, #3 암릉 노멀맵, #7 시설 병합, #9 KTX2
3단계: #4 원경판, #8 코스 스트리밍 Worker, #11 오버드로 정리

## 가정

- 엔진은 현재 three.js(웹) 유지. 언리얼 같은 엔진 교체는 비용 대비 이득이 불확실해 보류.
- 순례길 게임 수준의 안정성을 목표로 하되, 품질 비교는 산디자인의 실제 사진 비교 검수로 확인.
