# 로딩 화면 · 흐림/노을 조명 보정 · 광장 안내 — 산디자인

## 1. 로딩 화면
- 새 파일: `src/loading-screen.js`, 마크업·스타일은 `index.html` 맨 위(스크립트가 뜨기 전에도 보이도록 인라인). 짙은 녹색 카드, 직접 그린 SVG 능선·소나무 실루엣(외부 사진 없음).
- 제목 '산길 · 관악산 서울대 계곡 코스', 진행 막대(%), 단계 칩(지형 → 숲·바위 → 시설 → 등산객 → 날씨·환경 → 첫 프레임 안정), 5초마다 바뀌는 안내 9개(산리서치 문서 §8의 8개 + 조작 팁 1개).
- 진행률은 `hiking:loading`의 `progress`만 읽는다. 시간으로 차오르는 값 없음. 준비 전에는 최대 99%.
- **시작 방식 결정**: 사용자가 누르는 순간이 곧 시작이어야 소리 재생이 허용되므로 버튼 방식을 유지한다.
  - 복장 선택 카드가 뜨는 일반 접속: 카드를 고르는 것이 '출발하기'다. 버튼을 두 번 누르게 하지 않으려고, 로딩 화면은 카드가 뜨는 순간 부드럽게(0.8초) 걷힌다.
  - `?startMode=manual`(카드 없음): 준비 완료 때 '출발하기' 버튼을 보이고, 누르면 `hiking:start`를 보내 걷힌 뒤 시작한다.
  - 자동 시작(`?outfit=` 또는 자동화 브라우저): 준비되면 바로 걷힌다. 캡처 스크립트는 그대로 동작한다.
- 실패·정체: `stage:'error'`이면 즉시, 마지막 진행 신호 뒤 30초가 지나면 안내 문구와 '다시 시도'(새로고침). 규약대로 처음부터 30초를 재지 않는다(정상 로딩이 35초 안팎).
- 모바일: 390×844 가로 넘침 없음, 세로 540px 이하 가로 화면은 능선을 숨기고 카드를 가운데로. `prefers-reduced-motion`이면 전환 없음.
- 로딩 중 입력 차단·걸은 시간 0초는 산개발 구현을 그대로 사용(준비 직후 elapsed 0 확인).

## 2. 조명 보정 (흐림·비·안개·오후·노을)
수치와 이유는 `docs/실시간날씨-기준.md` §6-4 표에 적었다. 요약:
- 원인: ① 그늘을 채우는 반구광이 항상 푸른 #CFE0F5 ② 구워 둔 환경광(IBL)이 맑은 낮 푸른 하늘이라 날씨와 무관 ③ 흐림에서 하늘·연무를 너무 어둡게 탈색.
- `src/daytime.js`: 반구광 색을 흐림 때 중성 회색, 해 고도 14° 이하일 때 따뜻하게. 회색도·탈색 후 밝기·노출 보정 조정. IBL 중성화 비율(`neutral`) 추가.
- `src/rendering.js`: IBL 몫을 `(1 − 0.7×neutral)`로 줄이고 반구광을 `(1 + 2×neutral)`로 키움. 시험용 `?envcut=`·`?hemiboost=`.
- `src/weather.js`: 환경광 배율, 흐림·비·안개 회색도.
- 맑은 낮(고도 14° 이상, 회색도 0)은 같은 값: 15시 맑음 노출 1.5754 전후 동일, 반구광 색 테스트로 고정.
- 16:14 흐림 광장 바닥 평균: RGB (46,56,68) → (77,73,68), 채도 0.32 → 0.11, 파랑−빨강 +22 → −8. 그늘 쪽 (24,48,67) → (59,60,62). 숲(왼쪽) 밝기 57 → 69.
- 측정: `scripts/measure-regions.mjs`(고정 영역 평균).

## 3. 광장 첫 화면 UI
- `src/plaza-banner.js` + `index.html`의 `#plaza-banner`: `hiking:state`의 `zone==='plaza'`일 때만 '출발 전 · 광장 / 일주문으로 걸어가면 산행이 시작됩니다'를 **아래 가운데**에 표시(일주문은 화면 가운데 위쪽이라 가리지 않음). 광장 동안 기존 `#resume-note`는 숨겨 안내가 겹치지 않게 했다.
- 왼쪽 위 '연주대로 가는 길' 카드는 일주문과 겹치지 않음(1440×900 캡처로 확인).
