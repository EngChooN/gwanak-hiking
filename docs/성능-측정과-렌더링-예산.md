## 현재 변경

- 발 접지의 `surfaceHeight`는 원래 등산로 전체 Raycaster 대신 4m XZ 격자에서 실제 Float32 삼각형의 높이를 구한다. 앞면/뒷면, 가장 높은 교차면, 원점 아래 20m 범위를 유지한다. 경로 높이 자체를 단순 보간하여 대신하지 않는다.
- `floorHeight`의 최근접 경로 검색은 336개 선분 전수 검사 대신 AABB 트리로 수행한다. 표고 보정·어깨 절삭식은 유지한다.
- 64m 지형 청크의 필요 목록은 카메라 청크 좌표가 바뀔 때만 다시 만든다. 가까운 순서로 프레임당 최대 한 개 생성한다. 대기 중에는 기존 8m 지형이 유지된다. 빠른 이동 시 대기열은 새 위치 기준으로 다시 만든다.
- 3인칭 카메라 충돌은 기존 5개 광선을 유지하되 붐 주변의 경로 조각·지형 청크만 검사한다. 매 프레임 숲 전체 `updateMatrixWorld(true)` 강제 호출을 없앴다.
- 기존 나무 InstancedMesh 및 GLB 공유 캐시는 유지한다. 인스턴스 생성은 24청크 묶음 대신 약 4ms 작업 후 이벤트 루프에 양보한다. 단일 청크 생성 자체가 4ms를 넘는지는 실측이 필요하다.
- `window.__hikingMetrics.performance`에 프레임 백분위·50ms 초과 수·CPU 단계별 평균·드로우콜·삼각형·텍스처 수를 남긴다. `window.__hikingPerformance.reset()` 및 `.report()`로 측정 구간을 분리한다.

## 재현·측정

Node 24 환경에서 아래를 실행한다. 전후 동일한 Mac, Chrome, 창 크기·DPR·전원 조건을 유지하고 GPU가 하드웨어 가속인지 확인한다. CPU 4배 감속은 GPU 감속이 아니다.

```sh

npm run dev -- --port 5176
# 별도 터미널: 수정 전 소스 서버를 대상으로 먼저 실행
LABEL=before HEADED=1 node scripts/benchmark-performance.mjs
# 수정 후 소스 서버에서 같은 명령 실행
LABEL=after HEADED=1 node scripts/benchmark-performance.mjs
node scripts/compare-performance.mjs
npm test
npm run build
```

수정 전 원본 중 변경 대상 5개 파일은 `/private/tmp/hiking-performance-before`에 보존했다. 기준 측정 서버는 일반 개발 서버를 종료한 뒤 `node scripts/performance-server.mjs before`로 실행한다. Vite의 load 훅으로 보존한 원본만 제공하며 작업 트리를 덮어쓰지 않는다. 종료 후 `npm run dev -- --port 5176`으로 현재 소스를 측정한다. 최초의 화질 토글도 원본 스냅샷에 포함되어 있다. `geo.js`의 기존 함수는 유지했으며 기준 소스는 추가된 색인을 사용하지 않는다. 임시 폴더가 사라지기 전에 전후 측정 아티팩트와 함께 보존해야 한다.

측정 스크립트는 실제 Chrome/CDP를 사용한다. 모든 자산 준비 및 15초 안정화 후 높음 3인칭 정지·W·S·A·D·자동 걷기, 높음 1인칭 W, CPU 4배 균형 3인칭 W를 각 20초 기록한다. A/D는 길 폭 끝에 닿으면 실제 이동이 멈추므로 거리 변화도 함께 확인해야 한다. 편차가 있으면 측정 순서를 바꿔 재검사한다. 20초 보행만으로 64m 경계 전환을 충분히 검증할 수 없으므로 별도로 경계 앞에서 시작하여 2분 자동 걷기를 기록한다.

## 산풍경 전달용 예산 — 실측 전 임시 상한

이 수치는 구현 계약의 초안이다. 현 장면이 상한 내에 있다는 뜻이나 성능 보장이 아니다. 실제 프레임·GPU 측정 후 수정한다. 통합 장면 기준으로 적용하며 새 자산은 아래 예산 안에서 기존 자산을 교체해야 한다.

| 항목 | 높음 | 균형 | 집계 범위 |
|---|---:|---:|---|
| 삼각형 / 프레임 | 250만 이하 | 150만 이하 | SSAO·그림자 등 모든 패스 합계 `renderer.info.render.triangles` |
| 드로우콜 / 프레임 | 800 이하 | 500 이하 | 모든 패스 합계 `renderer.info.render.calls` |
| 상주 자산 텍스처 | 256MiB 이하 | 192MiB 이하 | GPU 전개 크기 및 mip 포함, 공유 텍스처는 한 번 집계 |
| 렌더 타깃·깊이·그림자 | 별도 192MiB 이하 | 별도 96MiB 이하 | 뷰포트·DPR에 따라 증가, 자산 예산과 합산 관리 |
| 카메라 주변 정밀 지형 | 64m 청크 × 최대 49개, 2m 격자 | 동일 | 고해상도 원자료 해상도와 화면 메시 해상도는 별도 |
| 개별 CPU 생성 작업 | 목표 2ms 이하 | CPU 4배에서 4ms 이하 | 초과 시 청크 세분·Worker 전처리 |

텍스처 수(`renderer.info.memory.textures`)는 메모리 바이트가 아니다. RGBA8 비압축은 `폭×높이×4×4/3`이 mip 포함 근사 크기이며, 2048² 한 장은 약 21.3MiB이다. PBR 3장 세트는 약 64MiB다. KTX2는 실제 GPU 선택 포맷의 블록 크기와 각 mip 합으로 계산한다. HDR 및 렌더 타깃은 픽셀 형식·면 수·mip 수를 반영한다.

산풍경 자산 전달 계약:

- 수종·재질별 InstancedMesh 유지. 나무별 Object3D/GLB 복제 금지. 지형·시설의 정적 메시도 재질별 청크 병합.
- 식생 청크 최대 128m, 근경 디테일 청크 64m 이하. 각 청크에 경계 상자·LOD별 삼각형·재질 수·인스턴스 수·예상 GPU 텍스처 바이트를 함께 제공.
- 원경 숲은 낮은 폴리곤 또는 사진판 LOD를 제공하고 알파가 겹치는 면적을 제한한다. 총 나무 수만으로 성능을 판단하지 않는다.
- 고해상도 DEM은 원본 보존 후 화면용 LOD와 충돌용 높이 격자를 별도로 만든다. 등산로 높이·좌표·경계 봉합을 유지한다.
- 텍스처는 공유 아틀라스 우선, 근경 2K 이하·원경 1K 이하를 기본으로 한다. 예외는 비교 화면과 메모리 증가량을 제시한다. KTX2 추가 시 디코더/트랜스코더를 프로젝트에 고정하고 실제 Mac·모바일 지원 및 로딩 피크를 검증한다.
- 새 숲·시설 반영 때마다 같은 W 자동 걷기·청크 경계 시나리오를 다시 측정한다. 통합 장면에서 55fps/30fps 기준 미달이면 투입 전 LOD·밀도·재질·오버드로를 줄인다.
