# 함께 걷기 서버 운영 안내

작성: 산개발 · 2026-11-08 (같은 날 메타버스 통합으로 체험 구분, 이어서 채팅·흡연장 열기 추가) · 상태: 로컬 완성, **실제 서버는 올리지 않았습니다**

## 대표가 서버 켜는 법 (11-11)
1. 맥 터미널에서 `cd ~/gwanak-hiking && . ~/.nvm/nvm.sh && nvm use 24 && npm run multi:up` → 「터널 열림」「gh-pages에 올림」이 나오면 켜진 것입니다(1분쯤 뒤 사이트에 반영).
2. 사람들은 그냥 https://engchoon.github.io/gwanak-hiking/ 로 들어와 서버 카드를 누르면 됩니다. 창은 켜 둔 채로 두세요(맥이 잠들지 않게 `caffeinate`가 같이 켜짐, 뚜껑은 열어 두기).
3. 끌 때는 그 창에서 Ctrl+C → 공개 파일이 '꺼짐'으로 바뀌고 사이트는 '서버가 꺼져 있어요' + 혼자 하기를 보여 줍니다.

### 서버 주소 공개 파일 `multi-server.json` (11-11)
- 위치: gh-pages 브랜치 맨 위 = `https://engchoon.github.io/gwanak-hiking/multi-server.json`. 모양 `{"state":"on","url":"wss://….trycloudflare.com","updated":"ISO 시각"}`, 끄면 `{"state":"off","url":"",…}`.
- 올리는 쪽: `scripts/multi-publish.mjs`(`npm run multi:publish -- wss://…|off|--show`). `node_modules/.cache/gwanak-pages.git`(파일 내용 없이 목록만 받는 partial clone)에서 지금 gh-pages 커밋 + 이 파일 하나로 새 커밋을 만들어 push합니다(강제 아님, 사이트 다시 빌드 없음, 몇 초).
- `npm run deploy`는 gh-pages를 새로 만들어 강제 push하므로, 배포 직전에 지금 올라 있는 이 파일을 읽어 그대로 이어 붙입니다. 그래도 겹쳐서 지워지면 `multi:up`이 5분마다 확인해 다시 올립니다.
- 사이트(`src/server-link.js`)가 고르는 순서: `?server=` → 빌드 변수 `VITE_MULTI_SERVER_URL` → 이 파일(`?t=시각`을 붙여 매번 새로, 3초 제한) → localStorage에 기억한 값(파일을 아예 못 받았을 때만). 파일이 '꺼짐'이면 기억한 옛 주소로 붙지 않습니다. `?server=`가 옛 `*.trycloudflare.com` 주소인데 파일에 다른 켜진 주소가 있으면 파일 주소를 쓰고 주소창에서 `?server=`를 뺍니다. 사이트는 이제 주소창에 `?server=`를 붙이지 않습니다.
- `multi:up`이 설정하는 `ALLOWED_ORIGINS` = `https://engchoon.github.io`, `http://127.0.0.1:4173`, `http://localhost:4173`, `http://127.0.0.1:5173`, `http://localhost:5173`. `cloudflared`는 PATH·`~/.local/bin`·`/opt/homebrew/bin`에서 찾고(없으면 설치 안내 출력), `CLOUDFLARED=경로`로 바꿀 수 있습니다. 시험용으로 파일을 올리지 않으려면 `npm run multi:up -- --no-publish`.
- 점검: `PAGE_URL=https://engchoon.github.io/gwanak-hiking node scripts/verify-server-file.mjs`(서버가 켜진 상태에서, `?server=` 없이 두 브라우저가 서버 카드로 들어와 서로 보이는지 등산·흡연장).

## 한눈에 보기
- 서버는 `server/multi-server.mjs` 하나입니다. Node 내장 기능만 쓰므로 **새 패키지를 설치할 필요가 없습니다**(Node 22 이상).
- 서버는 **http(ws://)로만 엽니다.** 배포 사이트가 https라서 실제로 쓰려면 앞단에서 **wss://(TLS)** 를 붙여야 합니다. 앞단은 Cloudflare 터널이나 클라우드 부하분산기가 맡습니다. 그래서 서버를 옮겨도 코드는 그대로 씁니다.
- 설정은 모두 **환경 변수**로 받습니다. 코드 안에 맥 경로나 주소는 없습니다.
- 게임은 `?server=` → 빌드 변수 → 공개 파일 `multi-server.json` 순으로 서버를 고릅니다(위 11-11). **터널 주소가 바뀌어도 코드를 고칠 필요가 없고, 링크에 `?server=`를 붙이지 않아도 됩니다.**
- **서버 하나를 체험 여러 개(지금 온라인 등산·온라인 흡연장)가 같이 씁니다.** 방은 `체험:방이름`으로 나뉩니다(§3-1). 채팅(`c`)은 두 체험 공통이고, 서버는 흡연장 위치·채팅·담배 상태를 받습니다. 흡연장 화면 연결은 산풍경 작업입니다(§3-2).
- 대표 결정(11-08): 1차 시험은 **내 맥 + Cloudflare Quick Tunnel**로 합니다. 아래 §5 절차를 따르세요.

## 1. 실행
```sh
cd gwanak-hiking
export PATH=$HOME/.nvm/versions/node/v24.22.2/bin:$PATH   # 기본 PATH에 node가 없음(이 맥 기준)
npm run server                 # = npm run multi:server, 기본 포트 8787
PORT=9000 DATA_DIR=/tmp/multi ALLOWED_ORIGINS=http://127.0.0.1:5173 npm run server
```
- 뜨면 한 줄짜리 JSON 로그 `{"event":"start","port":8787,...}`가 나옵니다.
- 상태 확인: `curl http://127.0.0.1:8787/health` → `{"ok":true,"rooms":1,"clients":2,"total":2,"uptime":35,"experiences":{"hiking":{"rooms":1,"clients":2},"smoking":{"rooms":0,"clients":0}},"servers":{"hiking":[{"id":"1","name":"관악산 1서버","count":2,"max":30},{"id":"2",…},{"id":"3",…}],"smoking":[{"id":"1","name":"옥상 1서버","count":0,"max":30},…]}}` (항상 200). `servers`·`total`은 서버 고르기 창이 5초마다 읽습니다(11-08).
- 끄기: Ctrl+C 또는 `kill <pid>`(SIGTERM). 붙어 있던 사람에게 close를 보내고 정상 종료합니다.

## 3. 게임에서 서버 주소 넣기
- **주소창:** `?multi=방이름&server=wss://주소` (가장 우선). `https://…`로 붙여 넣어도 `wss://`로, `http://…`는 `ws://`로 바꿉니다. 스킴 없이 `abc.trycloudflare.com`만 적으면 `wss://`로 봅니다.
- **빌드 변수:** `VITE_MULTI_SERVER_URL=wss://주소 npm run build`. 주소창에 `server`가 없을 때 씁니다.
- **공개 파일:** 둘 다 없으면 `multi-server.json`(npm run multi:up이 올림)을 새로 받아 씁니다. 못 받으면 기억한 값.
- **둘 다 없거나 `?server=off`:** 예전처럼 같은 브라우저 창끼리만(BroadcastChannel) 연결합니다.
- `multi` 없이 `server`만 주면 처음엔 혼자 걷습니다. HUD에서 참가하면(`hiking:multi-join`) 그 서버로 붙습니다.
- 등산 주소는 `/hiking/`입니다. 예전처럼 사이트 맨 위(`/gwanak-hiking/?multi=…&server=…`)로 보내도 허브가 쿼리 그대로 `/hiking/`로 넘깁니다.

## 3-1. 체험 구분 (메타버스 통합, 11-08)
한 서버를 온라인 등산과 온라인 흡연장이 같이 씁니다. 같은 방 이름이라도 체험이 다르면 서로 보이지 않습니다.

**접속 인사(hello)**
```json
{"t":"hello","exp":"hiking","room":"관악산-1","name":"하늘","resume":null}
```
- `exp`는 체험 id입니다. 허용 목록은 `src/multi-protocol.js`의 `EXPERIENCES`(`hiking`·`smoking`)이고, 서버는 `parseExperience`로 읽습니다.
- **하위 호환:** `exp`가 없거나 `null`·빈 문자열이면 **`hiking`** 으로 봅니다. 그래서 이미 배포된 등산 클라이언트(체험 id를 보내지 않음)는 새 서버에서도 새 등산 클라이언트와 같은 방에 들어갑니다.
- **목록 밖 값**(`golf`, 대문자 `HIKING`, 숫자 등)은 `{"t":"reject","reason":"experience"}`를 보내고 닫습니다(close 1008, 로그 `reject-experience`). 전송 계층(`createWebSocketTransport`)은 이 거절을 받으면 다시 시도하지 않고 '끊김'(offline)이 됩니다. 잘못된 값을 등산 방에 몰래 섞지 않으려고 거절로 정했습니다.
- 환영 인사에도 체험이 실립니다: `{"t":"welcome","id","exp":"hiking","room":"관악산",…}`. `room`은 방 키가 아니라 **방 이름만** 보냅니다(화면에 그대로 씀).

**방 키 = `체험:방이름`** (`server/rooms.mjs`의 `roomKey`)
- 예: `hiking:관악산`, `smoking:옥상`. 방 이름에는 `:`가 들어갈 수 없어(`sanitizeRoom`) 키가 겹치지 않습니다.
- 끝의 자동 번호는 원래 규칙대로 뗀 뒤 키를 만듭니다. 그래서 `?multi=관악산-1`은 `hiking:관악산`, 흡연장 `옥상-1`은 `smoking:옥상` 방입니다(기획서 예시 `hiking:관악산-1`은 실제로 이 키가 됩니다).
- **체험별로 그대로인 것:** 30명이 차면 `방이름-2`, `-3`(체험마다 따로 셈), 위치·기타 메시지 속도 제한, 신고 3명 → 숨김·같은 체험 안의 다른 방으로 재배정, 60초 재접속(resume).
- **체험을 넘지 않는 것:** 신고는 같은 체험 사람만 할 수 있습니다. 다른 체험의 resume 토큰으로는 같은 ID를 받지 못합니다(새 ID).
- **서버 전체로 세는 것:** 전체 동시 접속 `MAX_CLIENTS`, 같은 곳 `MAX_PER_IP`, 신고 숨김의 IP 해시(숨김 24시간은 체험과 상관없이 그 사람에게 이어짐).
- 신고 기록의 `room`은 방 키(`hiking:관악산`)로 남겨 어느 체험인지 보이게 했습니다. 11-08 이전 줄은 방 이름만 있고, 모두 등산입니다.
- `/health`의 `experiences`에 체험별 방 수·접속자 수가 나옵니다.

**서버 목록과 정원 (11-08 서버 고르기, 11-13 체험마다 3서버·정원 30)** — `src/multi-protocol.js`의 `SERVERS`
- 줄 하나 = 서버 하나 = 서버 쪽 방 하나: 등산 `관악산 1·2·3서버`(`관악산-1` → `hiking:관악산`, `관악산-2` → `hiking:관악산-2`, `관악산-3` → `hiking:관악산-3`), 흡연장 `옥상 1·2·3서버`(같은 규칙). 서버를 더 늘리려면 `SERVERS`의 `['1','2','3']`에 번호를 더합니다.
- '서버'는 실제 컴퓨터가 아니라 **한 서버 프로그램 안의 방**입니다. 컴퓨터 한 대(지금은 대표 맥)가 두 체험 × 3서버 × 30명 = 최대 180명을 받습니다(`MAX_CLIENTS` 400 안).
- 터널(`npm run multi:up`) 뒤에서는 모든 접속이 127.0.0.1로 보이므로 `multi:up`이 `TRUST_PROXY=1`·`HOST=127.0.0.1`로 서버를 켭니다(11-13). 전에는 같은 곳 제한(`MAX_PER_IP` 32)에 전체가 묶여 두 체험 합쳐 32명까지만 들어갈 수 있었습니다.
- 서버 방은 정원(`MAX_PER_ROOM`, 기본 30)이 차면 `-2`로 넘기지 않고 `{t:'full',reason:'full'}`로 거절합니다(다른 서버로 자동으로 보내지 않음, 사용자가 서버 카드에서 고름). 목록에 없는 번호(`?multi=관악산-7`)·끝 번호 없는 이름은 1서버로 봅니다. welcome에 `server:'1'`·`'2'`·`'3'`이 붙습니다.
- 서버 방에서 신고 3명으로 숨겨진 사람은 옮길 방이 없어 같은 방에서 이름만 익명으로 보입니다.
- 클라이언트는 서버 고르기 창(`src/server-pick.js`)에서 줄을 골라 그 `room`으로 hello를 보냅니다. full을 받으면 창이 '방금 꽉 찼어요'로 다시 뜹니다(30초 뒤 다시 시도하지 않음).

**체험별 메시지 종류** (`EXPERIENCE_MESSAGES`, hello 뒤 메시지. 11-08 채팅·흡연장 열기)
| 종류 | 등산 `hiking` | 흡연장 `smoking` |
|---|---|---|
| 공통 `j`(이름 묻기)·`report`(신고)·`b`(나가기)·**`c`(채팅)** | 받음 | 받음 |
| `s` 위치 | 받음 | 받음(등산과 같은 검사) |
| `g` 인사·`a` 동물 놀람·`sr`/`sa`/`sd`/`se` 같이 셀카 | 받음 | 버림(등산 전용) |
| `lounge:smoke` 담배 상태 | 버림 | 받음 |
| **`act` 행동 상태**(11-10) | 받음(등산 칸) | 받음(흡연장 칸) |
| `lounge:chat` | 버림 | 버림 (예약안이었으나 공통 `c`로 바꿈) |
- 체험에 열리지 않은 종류는 서버가 버리고 `stats.wrongExperience`를 하나 셉니다. 다른 체험의 메시지가 섞여 들어오지 않게 하는 장치입니다. 예약 목록(`RESERVED_MESSAGES`)은 모두 열려서 없앴습니다.

**채팅 `c` (두 체험 공통)**
- 보내기 `{"t":"c","text":"안녕하세요"}` → 서버가 정리해 **보낸 사람을 포함한** 같은 방 모두에게 `{"t":"c","id":"서버가 정한 ID","text":"…"}`. 보낸 사람이 되돌려 받는 것이 전달 확인입니다. 이름은 싣지 않습니다(받는 쪽이 `j`로 아는 이름, 모르면 익명 이름).
- 정리(`sanitizeChat`): 80자에서 자르기, 제어·방향 전환 문자 제거, 공백 정리, 금칙어는 대소문자 구분 없이 `***`로 가림. 비면 버립니다.
- 속도 제한(`createChatLimiter`): **2초에 1번, 10초에 4번.** 넘으면 보낸 사람에게만 `{"t":"c-limit"}`(글은 중계하지 않음). 기타 메시지 초당 20회 제한도 함께 걸립니다.
- **채팅은 디스크·로그에 쓰지 않습니다.** 사람마다 최근 3줄만 메모리에 두고, 그 사람이 신고되면 신고 기록 한 줄의 `chat` 칸에 그 3줄만 남깁니다(근거: 산리서치 채팅 운영 정책). 로그 `report`에는 방 키·사유만 나갑니다.
- 신고로 이름표가 숨겨진 사람의 채팅도 중계됩니다. 이름은 받는 쪽에서 익명(`등산객XXXX`·`손님XXXX`)으로 보입니다.

**흡연장 위치 `s`·담배 상태 `lounge:smoke`**
- 위치는 등산과 같은 `{t:'s',q,z,x,y,h,v,f}`, 같은 검사(초당 15회, 12m/s·여유 2m, 순간이동은 `FLAG.jump` 1초 1번)입니다. 옥상은 `z:0`, 자리 옮기기(`lounge:spot`)처럼 순간 이동하면 `FLAG.jump`를 붙입니다.
- 담배 상태 `{"t":"lounge:smoke","state":"smoking","lit":true}` → 서버가 `state`를 허용 목록(`SMOKE_STATES` = `src/lounge/smoke.js`가 내는 상태 `idle·out·ready·lighting·smoking·inhale·exhale·flick·finished·dispose·done·trick`)으로, `lit`을 참/거짓으로 검사하고 다른 사람에게 `{t:'lounge:smoke',id,state,lit}`로 중계합니다(보낸 사람에게는 안 돌려줌, 다른 칸은 버림). 새로 들어온 사람은 방 사람들의 마지막 담배 상태를 받습니다. 연기·불씨는 받는 쪽이 그립니다. 시험이 `smoke.js`의 상태 이름과 목록이 같은지 확인합니다.

**행동 상태 `act` (두 체험 공통, 2026-11-10)**
- 보내기 `{"t":"act","a":{…}}`(바뀔 때만) → 서버가 체험별 칸만 남겨(`sanitizeAct`·`ACT_SCHEMA`, 목록 밖 칸·값은 버림, 남는 칸이 없으면 버림) 다른 사람에게 `{t:'act',id,a}`로 중계합니다(보낸 사람에게는 안 돌려줌).
  - 흡연장: `p` 자세 `stand·lean·sit` · `b` 벤치 번호 · `can` 캔커피 `0` 없음·`1` 뽑는 중·`2` 들고 있음 · `sip` 한 모금 횟수(늘면 받는 쪽이 한 모금).
  - 등산: `p` 자세 `stand·sit·tea` · `g` 기구 `none·binoculars·phone` · `sf` 셀카 `0·1` · `x` 지금 동작 id(영문 소문자·숫자·`-` 24자, 없으면 빈 값) · `n` 동작 횟수 · `v` 보조 값(역기 횟수). 정수 칸은 0~65535.
- 서버는 사람마다 마지막 `a`를 메모리에 두고 **새로 들어온 사람·이름 묻기 `j`의 답·다시 접속(resume, 같은 ID 이어 받기 포함)** 때 다시 줍니다(담배 상태와 같은 방식). 디스크에는 쓰지 않습니다.

**익명 이름·내 컴퓨터 모드**
- 익명 접두어 `ANON_PREFIX`: 등산 `등산객XXXX`, 흡연장 `손님XXXX`(`anonymousName(id, 체험)`). 서버도 이름이 비었거나 숨김일 때 체험에 맞는 이름을 씁니다.
- BroadcastChannel 채널 이름 `gwanak-multi:체험:방`(`broadcastChannelName`). **등산은 예전 이름 `gwanak-multi:방`을 그대로** 씁니다(옛 탭과 이어짐). 방 이름의 `:`는 빼서 등산 방 이름으로 흡연장 채널에 들어갈 수 없습니다.
- 내 컴퓨터 모드에서도 채팅은 서버와 같게 동작합니다: 전송 계층이 보낼 때 속도 제한(넘으면 내게 `c-limit`)·정리하고 나에게도 되돌려 주며, 받은 글도 다시 정리합니다. 이때는 채팅에 `id`(내 ID)를 붙여 보내야 합니다. 금칙어 목록은 서버에만 있습니다.

- 새 체험을 더할 때: `EXPERIENCES`에 id, `EXPERIENCE_MESSAGES`에 받을 종류를 더하면 서버가 방을 따로 만듭니다. 서버 이미지에 들어가는 파일은 그대로입니다(체험 목록이 `src/multi-protocol.js` 안에 있음).

### 3-2. 클라이언트 연결 방법 (등산 완료 · 흡연장은 산풍경이 이 계약대로)
**등산(완료, `src/multi-client.js`)** — 채팅 HUD(산디자인)는 window 이벤트만 씁니다.
- 보내기: `hiking:chat-send` `{text}` → 서버로 `{t:'c'}`.
- 받기: `hiking:chat` `{id, name, text, me, remote:true}`. 내 글도 서버가 되돌려 준 것을 받아 `me:true`로 옵니다(이걸로 '보냄' 표시). 차단한 사람 글은 오지 않습니다.
- 제한: `hiking:chat-limit` `{reason:'rate'}`(2초 1번·10초 4번 넘음) 또는 `{reason:'offline'}`(서버 모드인데 아직 연결 전·다시 연결 중이라 보내지 못함).

**흡연장(11-08 붙임, `src/lounge/multi.js`·`multi-ui.js` — 아래는 그때 쓴 계약)** — 전송 계층은 그대로 쓰면 됩니다. 메시지를 손대지 않고 주고받는 것을 시험이 확인합니다(`tests/multi-chat.test.mjs`).
```js
import {createWebSocketTransport,createBroadcastTransport,multiServerUrl} from '../multi-transport.js';
import {anonymousName,FLAG} from '../multi-protocol.js';
const url=multiServerUrl(location.search,import.meta.env.VITE_MULTI_SERVER_URL);   // ?server= → 빌드 변수 → null
const room=new URLSearchParams(location.search).get('multi')||'옥상-1';
const t=url?createWebSocketTransport(url,{experience:'smoking',room,name})
           :createBroadcastTransport(room,undefined,{experience:'smoking'});
t.onmessage(m=>{ /* m.t: 'welcome'{id,room,name} · 'j'{id,n,h?} · 's' · 'c'{id,text} · 'c-limit' · 'lounge:smoke'{id,state,lit} · 'act'{id,a} · 'b'{id} · 'moved' · 'reject' */ });
t.onstatus?.(s=>{ /* 'connecting'|'online'|'reconnecting'|'offline'|'full' (서버 모드만) */ });
t.send({t:'j',id:myId,n:name});                       // 들어오면·3초마다 이름 알림(서버 모드에선 id 무시)
t.send({t:'s',id:myId,q,z:0,x,y:z좌표,h,v,f});        // 10Hz, 순간 이동이면 f|=FLAG.jump
t.send({t:'c',id:myId,text});                          // 채팅(내 컴퓨터 모드는 id 필수)
t.send({t:'lounge:smoke',state,lit});                  // 상태가 바뀔 때만(내 smoke.js의 lounge:smoke 이벤트에서 isPlayer일 때)
t.send({t:'act',a:{p,b,can,sip}});                     // 자세·캔이 바뀔 때만(spots.act(), 11-10)
```
- 받은 `c`는 기존 이벤트 `lounge:chat` `{id, name, text, remote:true}`로 흘립니다(`remote`로 NPC 대사와 구분). 내 글은 지금처럼 `id:'me'`로 바로 그리고, 서버가 되돌려 준 내 글(`m.id===welcome.id`)은 다시 그리지 않으면 됩니다. 이름은 `j`로 받은 이름, 모르면 `anonymousName(id,'smoking')`.
- 서버 모드에서는 `welcome.id`가 내 ID입니다(접속·재접속 때 바뀔 수 있음). 내 컴퓨터 모드는 직접 만든 임시 ID를 씁니다.

**흡연장 연결 결과(11-08, 산풍경)**: 위 계약 그대로 붙였고 서버·전송 계층은 고치지 않았습니다.
- 내 컴퓨터 모드에서는 담배 상태에도 `id`(내 ID)를 붙여 보냅니다(서버는 자기가 정한 ID로 바꿈).
- 받은 위치에 `FLAG.jump`가 있으면 보간 기록을 비우고 바로 옮깁니다(옥상은 좁아 25m 순간 이동 기준에 걸리지 않음).
- 화면 이벤트: `lounge:multi-status` `{state,room,count,transport,joined}`, `lounge:multi-note` `{text}`. 콘솔 `lounge.multi.status()`.
- 확인: `scripts/verify-multi-chat.mjs` 흡연장 칸 통과, `scripts/capture-smoking-multi.mjs`(두 브라우저 캡처·점검).

## 4. 내 컴퓨터로 시험 공개
설치나 실행은 아직 하지 않았습니다. 아래는 명령만 적어 둔 것입니다.

### ① 같은 와이파이(집·사무실 안 휴대폰)
```sh
ipconfig getifaddr en0                       # 맥의 와이파이 IP 확인. 예: 192.168.0.5
ALLOWED_ORIGINS=http://192.168.0.5:5173 npm run server
npm run dev -- --host 0.0.0.0                # 다른 터미널. dev 스크립트는 기본이 127.0.0.1이라 휴대폰에서 못 엽니다
```
휴대폰 사파리: `http://192.168.0.5:5173/hiking/?multi=우리방&name=하늘&server=ws://192.168.0.5:8787`
- **배포 사이트(https://engchoon.github.io/…)에서는 `ws://`가 막힙니다.** https 페이지에서 암호화 안 된 ws://로 붙는 것을 브라우저가 거부하기 때문입니다(혼합 콘텐츠). 그래서 같은 와이파이 시험은 **로컬 vite 주소(http)로 열어야 합니다.**
- 맥 방화벽이 "node의 들어오는 연결 허용" 창을 띄우면 허용해야 휴대폰이 붙습니다.
- 와이파이 밖에서는 안 됩니다. 공유기 포트 열기(포트포워딩)는 집 IP가 드러나고 TLS도 따로 필요해 권하지 않습니다.

### ② 바깥 사람(인터넷 너머): Cloudflare Quick Tunnel
```sh
brew install cloudflared                                   # 한 번만(아직 설치하지 않았음)
TRUST_PROXY=1 HOST=127.0.0.1 ALLOWED_ORIGINS=https://engchoon.github.io npm run server
cloudflared tunnel --url http://localhost:8787             # 다른 터미널. https://xxxx-yyyy.trycloudflare.com 주소가 나옴
```
들어올 주소: `https://engchoon.github.io/gwanak-hiking/hiking/?multi=우리방&server=wss://xxxx-yyyy.trycloudflare.com`

| 장점 | 단점 |
|---|---|
| 계정·도메인·인증서 없이 바로 **wss://** 주소가 생깁니다. 배포 사이트(https)에서 그대로 붙습니다 | **맥이 꺼지거나 잠자기에 들어가면 끊깁니다**(게임은 혼자 걷기로 계속되고 '다시 연결 중'이 뜹니다) |
| 들어오는 사람에게 **집 IP가 드러나지 않습니다**(Cloudflare를 거쳐 나감). 공유기 포트를 열 필요가 없습니다 | **주소가 실행할 때마다 바뀝니다.** 바뀐 주소를 다시 알려 줘야 합니다(코드 수정은 필요 없음) |
| 무료이고, 끄면 바로 닫힙니다 | 시험용 기능이라 가동 보장이 없습니다. Cloudflare 문서에 동시 요청 수 제한(약 200개)이 적혀 있습니다(**확인 필요**) |

## 5. Quick Tunnel 시험 절차 (1차 시험, 대표 결정 11-08)
1. 맥을 전원에 연결하고 잠자기를 막습니다. 서버를 띄우는 터미널에서 `caffeinate -s npm run server` 처럼 앞에 붙이면, 그 명령이 도는 동안 잠자기에 들어가지 않습니다(전원 연결 시). 뚜껑을 닫으면 잠들 수 있으니 열어 둡니다.
2. 터미널 1: `TRUST_PROXY=1 HOST=127.0.0.1 ALLOWED_ORIGINS=https://engchoon.github.io DATA_DIR=$HOME/gwanak-multi-data caffeinate -s npm run server`
3. 터미널 2: `cloudflared tunnel --url http://localhost:8787` → 나온 `https://….trycloudflare.com` 주소를 복사합니다.
4. 확인: 브라우저에서 `https://….trycloudflare.com/health` → `{"ok":true,…}`
5. 함께할 사람에게 보낼 주소: `https://engchoon.github.io/gwanak-hiking/hiking/?multi=방이름&server=wss://….trycloudflare.com` (HUD 참가 화면이 생기면 `multi=` 없이 `server=`만 붙여도 됩니다)
6. 끝나면 두 터미널을 Ctrl+C로 끕니다. 신고 기록은 `DATA_DIR`에 남습니다.
- 주의: 배포 사이트에 이번 변경이 아직 올라가지 않았습니다(배포는 대표 지시 뒤). 그 전에는 **로컬 vite 주소 + 터널**로 시험합니다. 이때는 `ALLOWED_ORIGINS`에 로컬 주소도 넣습니다.

## 6. 클라우드로 옮길 때 바꿀 것
| 항목 | 내 맥 + Quick Tunnel | 클라우드 |
|---|---|---|
| 서버 주소 | 실행마다 바뀌는 `wss://….trycloudflare.com` | 고정 도메인(예: `wss://multi.도메인`). `VITE_MULTI_SERVER_URL`로 빌드에 넣으면 `?server=` 없이 붙습니다 |

| 상태 확인 | `curl …/health` | 같은 주소를 부하분산기 상태 검사·외부 감시에 등록(Dockerfile에 HEALTHCHECK 있음) |

### Render 무료로 올리기 (무료 1차 시험용)
저장소 맨 위 `render.yaml`에 설정을 넣어 두었습니다(싱가포르, 무료 플랜, `/health` 검사). 아직 가입·배포하지 않았습니다.
- 무료 한계: 15분 동안 접속·메시지가 없으면 잠듭니다. 다음 사람이 오면 깨는 데 약 1분 걸리고, 그동안 칩은 '다시 연결 중'입니다(저절로 붙음). 잠들면 방이 비워지고, 디스크가 없어 신고 기록도 재시작 때 사라집니다.
1. GitHub에 push(render.yaml 포함) → render.com에 GitHub 계정으로 가입
2. New → Blueprint → `EngChooN/gwanak-hiking` 선택 → `render.yaml` 그대로 적용
3. 확인: `curl https://gwanak-multi.onrender.com/health` (이름이 겹치면 Render가 붙인 주소를 씀)
4. 게임 주소: `https://engchoon.github.io/gwanak-hiking/hiking/?multi=관악산-1&server=wss://gwanak-multi.onrender.com`, 버튼만으로 붙게 하려면 `VITE_MULTI_SERVER_URL=wss://gwanak-multi.onrender.com npm run deploy`

### Fly.io 도쿄에 올리기 (유료 추천 1안, `docs/멀티-서버-호스팅-비교.md`)
저장소 맨 위의 `fly.toml`에 설정을 넣어 두었습니다(도쿄 `nrt`, `/health` 검사, 신고 기록 볼륨, 접속이 없어도 꺼지지 않음). 아직 가입·배포하지 않았습니다.

1. 설치·로그인: `brew install flyctl` → `fly auth login` (결제 카드 등록 필요)
2. 앱 만들기: `fly launch --no-deploy --copy-config` — 이름 `gwanak-multi`가 이미 있으면 다른 이름을 고르고, 아래 주소의 이름도 같이 바꿉니다.
3. 신고 기록 볼륨: `fly volumes create gwanak_multi_data --region nrt --size 1`
4. 배포: `fly deploy --ha=false` — **반드시 1대**. 방 상태가 서버 메모리에 있어 2대가 뜨면 같은 방 사람이 서로 안 보일 수 있습니다. 이미 2대면 `fly scale count 1`.
5. 확인: `curl https://gwanak-multi.fly.dev/health`
6. 게임 주소: `https://engchoon.github.io/gwanak-hiking/hiking/?multi=관악산-1&server=wss://gwanak-multi.fly.dev`
   - `?server=`까지 빼려면 빌드할 때 `VITE_MULTI_SERVER_URL=wss://gwanak-multi.fly.dev npm run deploy` 로 넣습니다. 그러면 수첩의 `👋 함께 걷기` 버튼만으로 서버에 붙습니다.

## 7. 재시작·로그
- **로그:** 한 줄에 JSON 하나씩 표준 출력으로 냅니다. `start`·`stop`·`signal`·`report`(방 키·사유만, 채팅 내용 없음)·`reject-origin`·`reject-experience`·`summary`(1분마다, 바뀌었을 때만: 접속 수·방 수·받은 위치·버린 수·순간이동 거부·중계·동물·신고·숨김·채팅 수·채팅 제한 수·담배 상태 수 — 내용은 없음)·`warn`·`error`. **IP는 로그에도 디스크에도 쓰지 않습니다.**
- 파일로 남기려면 `npm run server >> multi.log 2>&1`, 도커는 `docker logs -f gwanak-multi`.
- **재시작:** 서버를 다시 켜면 메모리 상태(방·위치·숨김 목록)는 비워집니다. 게임은 0.5초부터 최대 15초 간격으로 저절로 다시 붙습니다. 신고 기록 파일은 남고, 90일 정리를 한 뒤 다시 읽습니다.
- 끊긴 사람이 60초 안에 다시 붙으면 같은 임시 ID·같은 방으로 돌아옵니다(재접속 토큰, 메모리에만 있음).

## 9. 직접 만든 WebSocket인가, `ws` 패키지인가 (판단)
**1차는 직접 만든 쪽이 맞다고 판단합니다.** `ws` 패키지는 지금 필요하지 않습니다.
- **필요한 범위가 작습니다.** 메시지는 모두 4KB 이하 JSON 텍스트입니다. 압축(permessage-deflate)·바이너리·조각난 메시지가 필요 없습니다. 핸드셰이크·마스킹 해제·길이 3종·ping/pong·close만 있으면 되고, 이 부분은 약 100줄입니다(`server/ws.mjs`).
- **시험으로 확인했습니다.** RFC 6455 예시 키, 1바이트씩 쪼개 들어오는 프레임, 길이 125·126·65535·70000, 마스킹 없는 프레임·너무 큰 프레임·조각난 제어 프레임 거부를 단위 시험에서 봤습니다. 실제 서버에 Node 내장 WebSocket 21개를 붙이는 통합 시험과, 크롬 브라우저 2개를 붙이는 확인도 통과했습니다.
- **배포가 단순합니다.** `npm install` 없이 파일 4개로 돕니다. 도커 이미지에도 의존성이 없습니다.
- **`ws`로 바꿀 때:** 공개 규모가 커지거나(수천 명), 바이너리·압축이 필요하거나, 외부 보안 점검에서 검증된 구현을 요구할 때입니다. `ws`는 의존성이 없는 작은 패키지입니다. 방 로직(`rooms.mjs`)은 소켓과 분리되어 있어서 `multi-server.mjs`의 업그레이드 부분 20줄만 바꾸면 됩니다.
- **직접 구현의 남은 위험과 대책:** 받지 못하고 쌓이는 느린 접속은 1MB를 넘으면 끊고, 20초 ping에 두 번 답이 없으면 끊고, 10초 안에 첫 인사(hello)가 없으면 끊고, 4KB 넘는 프레임은 닫습니다. 퍼징 같은 대규모 비정상 입력 시험은 하지 않았습니다.

## 10. 알려진 한계
- 실제 인터넷·실제 휴대폰에서는 시험하지 않았습니다. 확인한 것은 이 맥의 127.0.0.1과 헤드리스 크롬입니다.
- 서버 1대 구조입니다. 여러 대로 늘리려면 방을 서버에 고정 배정하는 앞단이 필요합니다.
- 체험별 인원 상한은 없습니다. `MAX_CLIENTS`(400)를 등산·흡연장이 나눠 씁니다. 한쪽이 몰려 다른 쪽이 못 들어오는 일이 생기면 체험별 상한을 더합니다.
- 순간이동 거부는 "표시 없는 큰 이동을 3초 동안 버림"입니다. 정상 클라이언트가 표시를 빠뜨려도 3초 뒤에는 다시 맞춥니다. 대신 악용하는 사람도 3초마다 한 번은 순간이동할 수 있습니다.
