# 변경 기록 — 2026-11-11 함께 걷기 서버 주소를 사이트가 알아서 찾기

작성: 산개발 · 지시: 산기획(대표 결정)

## 대표 결정
- 중계 서버는 당분간 대표 맥 + Cloudflare Quick Tunnel.
- 사람들은 그냥 https://engchoon.github.io/gwanak-hiking/ 로 들어와 서버 카드만 누르면 붙어야 한다. 링크에 `?server=`를 손으로 붙이지 않는다.

## 문제
터널 주소는 켤 때마다 바뀌는데 배포본에는 서버 주소가 없어 사이트가 주소를 알 길이 없었다. 11-08판은 기억한 값을 주소창에 붙여 두어서, 터널을 다시 켜면 옛 주소가 링크·기억에 남아 연결에 실패할 수 있었다.

## 바꾼 것
### 실행 스크립트 `npm run multi:up` (`scripts/multi-up.mjs`)
- 함께 걷기 서버(PORT 8787, `ALLOWED_ORIGINS` = `https://engchoon.github.io` + `127.0.0.1/localhost`의 4173·5173) → `caffeinate -i -s -w <pid>` → `cloudflared tunnel --no-autoupdate --url http://127.0.0.1:8787`.
- 터널 주소가 나오고 그 주소로 `/health`가 열리면 공개 파일을 올린다. 5분마다 공개 파일이 지금 주소와 같은지 보고 다르면 다시 올린다(배포로 덮였을 때 대비).
- Ctrl+C·SIGTERM·서버나 터널이 죽음 → 공개 파일을 `{state:'off'}`로 바꾼 뒤 모두 끈다. **'꺼짐'으로 바꾸기로 정한 이유:** 비워 두면 사이트가 기억한 옛 주소로 붙으려다 실패하고, 옛 주소를 남겨 두면 4초 동안 '확인 중'을 보인 뒤 실패한다. '꺼짐'이면 바로 '서버가 꺼져 있어요' + 혼자 하기.
- `cloudflared`가 없으면 brew 설치와 직접 받기 명령을 출력하고 끝낸다. PATH·`~/.local/bin`·`/opt/homebrew/bin`·`CLOUDFLARED=`에서 찾는다. 이 맥에는 brew가 없어 공식 GitHub 배포판(2026.10.7, Cloudflare Inc. 개발자 서명 확인)을 `~/.local/bin/cloudflared`에 두었다.
- 시험용 `--no-publish`.

### 공개 파일 `multi-server.json` (`scripts/multi-publish.mjs`)
- 위치: gh-pages 맨 위(사이트와 같은 출처라 CORS 걱정 없음, `?t=`로 Pages CDN 캐시를 피함). 모양 `{"state":"on","url":"wss://….trycloudflare.com","updated":"…"}`.
- 이 파일 하나만 커밋해 push: `node_modules/.cache/gwanak-pages.git`에 파일 내용 없이 목록만 받는 partial clone(`--filter=blob:none`, 144KB)을 두고, 지금 gh-pages 트리 + 새 파일로 커밋을 만들어 강제 아닌 push. 거절되면 한 번 다시 받아 올린다. 작업 폴더·main은 건드리지 않는다. 사이트 다시 빌드 없음.
- 다른 방법과 비교: Gist·raw.githubusercontent는 캐시(5분)를 쿼리로 못 피하고 다른 계정 인증이 필요, 빌드 변수는 켤 때마다 전체 배포(수십 MB)가 필요. gh-pages가 가장 단순하다. 단점은 Pages 반영에 30초~1분.
- `npm run deploy`는 gh-pages를 새로 만들어 강제 push하므로 배포 직전 지금 파일을 읽어 이어 붙인다.

### 사이트 (`src/server-link.js`·`server-link-pin.js`)
- 고르는 순서: `?server=` → `VITE_MULTI_SERVER_URL` → 공개 파일(매번 새로, 3초 제한) → 기억한 값(파일을 아예 못 받았을 때만).
- 공개 파일 주소가 기억한 옛 터널 주소보다 앞서고, 받은 주소를 기억해 둔다. 파일이 '꺼짐'이면 기억한 값으로 내려가지 않는다.
- `?server=`가 옛 `*.trycloudflare.com`인데 파일에 다른 켜진 주소가 있으면 파일 주소를 쓰고 주소창에서 `?server=`를 뺀다(11-08~10판이 붙여 둔 링크가 돌아다니므로). LAN·직접 연 서버 주소는 그대로.
- 주소창에 `?server=`를 붙이던 것(`pinServerParam`)과 허브 카드 링크에 붙이던 것(`withServer`)은 없앴다. 붙이면 다시 읽을 때 옛 주소가 `?server=`로 앞서게 된다.
- 주소를 읽는 쪽은 `serverReady`를 기다린다: 등산 산 고르기 뒤 서버 카드(`mountain-pick.js`), `main.js`의 함께 걷기 연결, 흡연장 `createLoungeMulti`. `multiServerUrl`은 `?server=`·빌드 변수가 없으면 고른 값(`currentServer()`)을 쓴다.
- 서버 카드: 파일이 '꺼짐'이면 '🌙 지금은 서버가 꺼져 있어요' + 혼자 하기(`serverOff`). 파일이 없으면 예전처럼 '서버 주소가 없어요', `/health` 실패는 '서버에 연결할 수 없어요'.

## 확인하지 못한 것
- 실제 휴대폰(아이폰 사파리)으로는 시험하지 않았다. 휴대폰은 크롬 화면 크기 흉내다.
- 맥 뚜껑을 닫으면 `caffeinate`가 있어도 잠들 수 있다(전원 연결 + 외부 모니터가 없으면).
- 배포(`npm run deploy`)와 공개 파일 올리기가 몇 초 안에 겹치면 파일이 빠질 수 있다. `multi:up`이 5분 안에 다시 올린다.
