# 실제 지형·서울 시가지·하늘 연결

작업: 산개발 / 2026-11-02 / gwanak-hiking. push·배포 없음.

## 바뀐 동작

- 앱이 generated/near.f32·far.f32·route.json·PBR 맵·sky.hdr를 직접 읽는다. 기존 180m 띠 지형·원뿔 산 12개·원뿔 나무·12면체 바위는 제거했다.
- 근경 전체 8m 격자와 보행 주변 64m 청크/2m 시각 격자를 함께 유지한다. 원경은 160m 격자다. 부드러운 정점 노멀을 계산하며 flatShading은 사용하지 않는다. 원자료 해상도는 30m DSM이다.
- 경사와 표고로 granite/soil/grass/leaves의 diffuse·OpenGL normal·roughness를 같은 가중치로 혼합한다. 두 UV 스케일을 혼합해 반복을 낮춘다. 암종·수종 현장 확인은 별개다.
- 새 경로는 337점 수평 위치를 유지하고 generated/route.json의 DSM 정렬 표고를 쓴다. 정상 632m, 길이 약 5066.93m. 저장 경로 ID를 분리해 이전 고도의 진행값을 잘못 복구하지 않는다. 기존 150분 속도 보정과 계단 구간의 1.2걸음/초 분류는 유지한다. 실제 시설 치수 미확보로 합성 계단은 만들지 않는다.
- 정상의 원시 DSM 605.58m와 632m 경로 보정으로 생기는 좁고 높은 둑을 방지하기 위해 경로별 elevationCorrection을 거리 300m 가우스 가중치로 주변 표면에 보간했다. 원본 f32는 변경하지 않는다. 폭 안쪽·2m 어깨를 평탄화하고 24m에 걸쳐 주변 표면으로 복귀한다. 이 렌더 보정은 지형 실측 정확도 검증이 아니다.
- 노면은 0.5m 이하로 세분하고 꺾임에서 miter 연결한다. 발바닥은 실제 노면 메시를 raycast한 지지점을 읽는다. 노면을 100m 단위로 분할하여 매 프레임 검사 비용을 낮췄다.
- OSM 건물 footprint를 실제 높이(없으면 층수×3m, 둘 다 없으면 9m)로 압출해 5,000동 청크별로 병합한다. 기본 파일의 ground 값을 보존한다. 건물 높이·지반이 실측값이라는 주장은 하지 않는다.
- 기존 물 파일의 한강 relation에는 members가 없었다. OSM 공식 relation/full.json 읽기 API로 한강 152336의 4,704노드/28개 member를 보충해 별도 han-river-water.json으로 저장했다. outer 연결 및 16개 섬 hole 처리. 수면 높이는 5m 가정이다.
- config의 승인 방위·거리로 63빌딩·남산타워·롯데월드타워를 배치하고 이름을 붙인다. 형상은 근사값이며 정확한 건축 모델은 아니다. 거리 안개를 적용한다.
- PureSky HDR을 하늘에, 복제/휘도 제한/중성화한 HDR과 PMREM을 환경광에 쓴다. 기존 Neutral·태양 29°/142°·직사/간접광 4:1 교정은 유지했다.

## manifest 전환

- manifest가 있으면 우선 읽고, 없으면 실제 파일 목록으로 만든 inventory를 사용한다. 격자 크기는 파일 바이트와 대조한다. 개발 서버는 파일 목록을 매 요청 확인하며, 빌드는 복사 시 inventory.json을 만든다.
- 30초마다 manifest 생성을 확인하고, 생기면 미로딩 도시 청크와 물을 추가한다. 보충한 한강 자료도 유지한다. 이미 읽은 건물은 중복 로드하지 않는다.
- 정적 dist에는 빌드 시점 자료가 들어간다. 이후 준비된 파일은 다시 build해야 포함된다. models-raw·raw·다운로드 도구는 dist에 복사하지 않는다.
