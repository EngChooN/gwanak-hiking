# 캐릭터 휴식·시점 최종 통합

2026-11-03 · 산개발 · /Users/pc-2311001/gwanak-hiking

산풍경의 양손 스틱·앉기·차 모듈을 기존 이동 상태와 연결했다. 캐릭터 모듈 자체는 수정하지 않았다.

- `src/main.js`: 1인칭 눈높이를 지면 + `hiker.eyeHeight`로 연결했다. 3인칭 주시점도 앉기 전환율에 따라 내려갔다가 복귀한다.
- T 및 차 명령은 앉기 전환 완료 후에만 받는다. 전환 중 차 타이머가 먼저 시작되는 불일치를 막았다. 이벤트의 `teaReady`로 버튼 상태를 알린다.
- 일시정지 중 캐릭터 자세 전환 dt를 0으로 전달한다. 차의 진행률은 이동 상태와 같으며, 저장 복원 시 앉은 자세부터 복구하고 남은 차 시간을 유지한다.
- `src/rest-ui.js`·`rest-ui.css`: C 앉기/일어나기, T 차 버튼, 스테미너 수치와 막대, 전환·차 진행·정지·고갈 안내. 명령 이벤트만 사용해 중복 클릭 처리를 피한다. 기존 `#sit` 버튼이 있으면 패널을 추가하지 않는다.
- `update` 다음 `ground` 순서와 누적 걸음 수 입력을 유지했다. 스틱·컵·보온병은 산풍경의 자체 제작 소품을 그대로 사용한다.

## 검증

테스트 148개와 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있다. `git diff --check` 통과.

실제 Chrome의 키보드/버튼으로 0.8초 앉기 중간 눈높이, 앉기 전 T 거절, 차 3초 완료·회복, 일시정지, 차 진행 중 새로고침 복원, 버튼으로 일어나기, 3인칭 차 마시기, 이동으로 취소를 확인했다. 모바일 390×844 패널 화면 내 배치 확인, 페이지 오류 0건. 이 맥 Chrome headless 1440×900·DPR 1·균형 화질에서 3인칭 이동 종료 후 5초 평균 60.00fps였다. 전체 코스나 다른 기기의 최저 성능 보장은 아니다. 검증 스크립트는 동작 래퍼나 강제 자세 변경 없이 앱 명령을 사용한다. 개발 서버 자동 새로고침만 검증 탭에서 차단한다.

원시 결과: `artifacts/rest-integration/results.json`. 재현: 로컬 Vite 서버 5177에서 `node scripts/verify-rest-integration.mjs`.

날씨·시간 UI는 이번 검증 범위 밖이다. 실제 산행 동작·풍경의 현장 검증을 대체하지 않는다. push·배포·삭제 없음.
