# after12 — 길가 바위 접촉 음영 복구

산개발 / 2026-11-03. 구현 제출, 실행 검수 대기. 9차의 셰이더 0·8조건 성능 통과·계단 접지 통과는 after11의 결과다. after12의 시각·성능 완료 판정은 아직 하지 않는다.

## 수정 사항

- `src/contact-occlusion.js`: 경로 지형 보호 폭을 `노폭/2 + 2텍셀 + 0.35m`에서 `노폭/2 + 0.15m`로 축소했다. 0.72m/텍셀인 9차 지도에서 약 1.8m의 과도한 여유가 길가 rock_09 그늘을 지우던 원인을 제거한다. 지도 크기·해상도·차폐율·셰이더는 그대로다. 상태에 `routeMargin:0.15`를 기록한다.
- 노면·계단 재질은 계속 음영 대상에서 제외한다. 지형·계단 높이와 발 접지 계산은 변경하지 않는다. 선형 필터와 해시 투명 노면 가장자리의 최종 화소 변화는 캡처에서 다시 확인해야 한다.
- 새 `src/contact-footprint.js`: 첫 LOD의 전체 수관 상자 대신 최하단 주변 정점에서 접촉 범위를 얻는다. 밑부분 높이 띠는 모델 높이의 15%, 바위 최대 0.35m·식생 최대 0.2m, 최소 0.08m다. 같은 모델의 범위는 캐시해 청크마다 정점을 반복 탐색하지 않는다.
- 배치 원점 대신 실제 인스턴스 행렬로 변환한 밑부분 상자의 중심에 음영을 둔다. 원점이 옆으로 치우친 GLB, 회전·비균일 배율·embed·supportDrop을 반영한다. 경사진 물체의 정확한 지형 교차면을 계산하는 것은 아니다.
- 바위 반경은 밑부분 수평 범위/2 + 0.5m, 최소 1.2m·최대 4m다. 식생은 +0.35m, 최소 0.9m·일반 나무 최대 2m·understory 최대 1.2m다. 차폐율은 바위 36%·식생 26%, 중첩 최댓값 정책을 유지한다.
- `kind:'understory'`도 접촉 음영 등록에 포함했다. 종류별 등록 개수는 `hiking.landscape().contactOccluderKinds`에 남긴다. 하층 식생의 풀·낙엽·간이 관목 삼각형에는 별도 음영을 추가하지 않는다.

## 넓은 타원·작은 나무 관찰에 대한 확인

9차 `rocks-after.png`와 `rocks-heat.png`를 열어 왼쪽 앞 넓은 타원과 근거리 작은 나무의 음영 누락을 확인했다.

1. 코드상 작은 모델이라도 `kind:'understory'`이면 기존 등록 조건 `rock|tree`에 들어가지 않았다. 따라서 이 분류의 작은 나무에는 음영이 아예 없다. 이번에 포함했다. 일반 `tree` 중 경로에 가까운 개체의 음영은 보호 폭 문제도 있었으며 함께 수정했다.
2. 기존 반경은 수관 전체 폭을 사용하고 최소 1.5m·최대 5m를 강제했다. 음영 중심도 형상이 아닌 배치 피벗이어서 수관이 넓거나 원점이 치우친 모델은 밑동에서 떨어진 얼룩을 만들 수 있었다. 이번에는 밑부분 중심·범위와 더 작은 반경을 사용한다.
3. 왼쪽 타원의 **원인 개체는 기존 결과에 배치별 정보가 없어 확정할 수 없다.** 프레임 밖 개체의 음영 가장자리, 지형에 가려진 개체, 피벗·범위 불일치가 후보이며 해당 타원에 특정 모델이 원인이라고 단정하지 않는다. 정적 지도이므로 개체가 화면 밖이라고 음영을 제거하지 않는다. 밑부분 보정 후에도 남는다면 새 접촉점 진단으로 해당 좌표의 개체를 대조해야 한다.

## 캡처 진단·검증 준비

- `hiking.contactProbes()`는 카메라 수평 거리 35m 안의 접촉점 중 가까운 최대 128개를 반환한다. 종류·모델 id·길가 상세 배치 여부·좌표·접촉 높이·지형 높이·반경·차폐율·LOD 조상 표시 상태·접촉점 NDC·화면 안 여부를 포함한다. 지형/다른 개체의 가림 판정은 포함하지 않는다. 평소 프레임에서는 호출하지 않는다.
- 바위/숲 캡처 JSON의 `comparisons[].contactProbes`에서 원인 개체 후보를 확인할 수 있다. `pixelDifference.roadsideRockContactRegions`에는 표시 상태이며 화면 안에 투영된 길가 바위 최대 24개의 접촉점 주변 48×24px 영역과 평균·최대·15~40단계 화소 수·40 초과 화소 수·변경 화소 수를 별도로 저장한다. 영역은 화면 가장자리에서 잘릴 수 있고 물체 몸체나 UI를 포함할 수 있으므로 이를 단독 합격 근거로 쓰지 않는다.
- 계단 캡처 JSON의 `contacts.first/third.contactProbes`에도 같은 배치 진단을 기록한다. 기존 접지 0.03m 검사·shaderErrors 검사·음영 켬/끔 화면을 유지한다.
- 회귀 테스트에 이전 보호 폭에 지워지던 노폭 밖 0.6m 지점 보존, 수관 제외, 편향된 밑동 및 배치 회전/배율, understory 분류, 빈 형상, 반경·차폐율 상한을 작성했다. 테스트 본문은 실행하지 않았다.
- `git diff --check` 통과. 프로젝트 스크립트·구문 검사·테스트·빌드·캡처·벤치는 실행하지 않았다. 새 결과 화면은 없으며 9차 화면을 after12 결과로 재사용하지 않는다. 커밋·push·삭제·배포·외부 전송은 하지 않았다.

## 가정

기존 CC0 모델과 임시 배치를 이용한 시각 근사다. 밑부분의 수평 상자는 실제 바위와 지형의 교차선을 완전히 재현하지 않는다. 최소 반경은 약 0.72m/텍셀 지도에서도 작은 접촉점이 사라지지 않게 둔 값이다. 나무 그늘 범위를 줄였으므로 기존 숲 개선이 유지되는지도 재확인한다. 추가 드로우콜·추가 GPU 패스·프레임별 지도 갱신은 없지만 understory 추가와 접촉점 계산의 로딩 비용은 실행 전 확정하지 않는다.
