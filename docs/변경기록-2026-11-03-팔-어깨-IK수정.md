# 팔·어깨 IK 수정

2026-11-03 · 산개발 · 프로젝트 /Users/pc-2311001/gwanak-hiking

**원인: 모델의 왼쪽 어깨는 루트 −X인데 팔 IK가 왼손을 +X로 보내, 양팔이 몸통을 가로질러 반대편 스틱을 잡고 있었다.**

## 변경

- `src/hiker-arms.js`: 해부학적 좌우를 앱 루트 좌표에 맞췄다(왼쪽 −X, 오른쪽 +X). 실제 어깨 위치에서 손목 목표를 정한다. 정지 시 손목은 어깨 아래 47cm, 몸 바깥 6.5cm로 내려온다. 보행 시 팔꿈치를 조금 굽히고 원본 보행 클립의 반대 발 앞뒤 위상에 맞춰 흔든다. 달릴 때 진폭은 확대한다.
- `src/realistic-hiker.js`: 위 목표를 팔 IK에 연결했다. 팔꿈치 굽힘 기준을 수평 바깥 방향에서 아래·뒤 방향으로 바꿔 상완이 옆으로 벌어지지 않게 했다. 손가락 축을 아래쪽으로 정렬하고 손바닥에 스틱 그립을 맞췄다. 고정된 폴 길이에 손을 끌어올리는 계산을 제거하고 기존 폴 길이 보정으로 손과 노면 사이를 맞춘다.
- 스틱 접지 위상은 기존 반대 발 교차 모델을 유지한다. 손 흔들기는 접지 앵커 보정 후의 발 좌표가 아닌 원본 보행 클립에서 표본화해 순간적인 발 보정 영향을 받지 않는다.
- 루트 로컬 목표를 월드 좌표로 바꾸므로 몸이 좌우·후방으로 돌아도 팔이 함께 돌아간다. 앞서 수정한 이동 방향·정지 방향 유지·카메라 코드는 수정하지 않았다.
- GLB의 어깨 위치, 뼈 연결, 상완·전완 길이, 형상과 스킨 가중치는 변경하지 않았다. 새 외부 자산이나 라이선스 조건이 없다. 로딩·광장 출발점 관련 파일과 main.js도 이번에는 수정하지 않았다.

## 검증

- `npm test`: **173개 통과**. 새 회귀 테스트 2개: 어깨/손의 좌우 일치와 자연스러운 내림·도달 범위, 반대 발 앞뒤 움직임·달리기 진폭.
- `npm run build` 및 `git diff --check` 통과. 기존 대형 번들 경고 유지.
- 같은 GLB·조명·카메라·위상으로 수정 전후의 정면·측면·뒷면 서기와 보행을 촬영했다. 두 이미지 비교판에 네 장면을 모두 실었다. 수정 전 런타임 복사본은 `artifacts/arms/before-hiker.js`에 보존했으며 앱에는 연결하지 않는다.
- 정면 비교에서 양쪽 어깨 관절의 좌표가 수정 전후 동일함을 자동 대조했다. 어깨가 내려오거나 새 위치에 붙은 것이 아니라 팔의 목표와 굽힘 방향을 고쳤다. 이미지로 소매에서 상완까지 이어짐, 팔 길이·굵기, 몸 옆으로 내린 팔을 확인했다.
- 모델 검증: 네 몸 방향 × 보행 16위상 = **64표본**. 팔꿈치·손목은 각 어깨와 같은 쪽, 팔꿈치는 어깨보다 낮게 유지. 발의 앞뒤 차이가 5cm를 넘는 64표본 모두 손의 앞뒤 차이가 반대 부호로 나와 교차 보행을 확인했다. 스틱 그립·접지 오차 2mm 미만.
- 실제 앱 키보드 검증: 정지 1회와 앞·좌·우·뒤 이동 각 12회로 **49표본 통과**. 팔이 몸통을 가로지르거나 어깨 높이로 벌어지지 않고 루트 회전을 따라갔다. 스틱 접지·그립 오차 2mm 미만, 페이지 오류 0건.
- 이 맥의 전용 Chrome headless, 1440×900·균형 화질에서 이동 검증 후 정지 5초 평균 60.00fps. 코스 전체·다른 기기의 최저 성능은 보장하지 않는다.
- 앉기·차 마시기 장면도 촬영해 팔과 소품 연결을 확인했다. 모든 동작의 모든 위상에서 메시 관통이 전혀 없다는 보장은 아니며, 이번 검증은 명시한 장면과 뼈·소품 좌표 기준이다.
