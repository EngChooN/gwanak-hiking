# after4 원경 도시 병목 후속

산개발 / 2026-11-03. 구현·정적 검사 완료, 실행 검증 대기. 커밋·push 없음.

## after3 근거

산기획 실행의 기존 `artifacts/performance-after3/results.json`과 `breakdown.md`를 읽었다. 균형 CPU4배 W는 24.7fps·50ms 초과17.6%, 원경 도시 기본 패스는 약95만 삼각형·1,396회 호출이다. 높음 정지는 도시 기본 패스1,217,616삼각형·1,774회, 전체 최대4,159,870삼각형이다. 기존512m 칸은 파일 청크마다 따로 만들어져 같은 공간에도 메시가 반복됐다.

## 변경

- `src/city-grid.js`에서 모든 입력 파일을 공유하는 2km 칸을 만든다. 파일 읽기는 기존 `streamCity`, 전체 병합은 `finalizeCities`로 분리했다. 로딩 완료·셰이더 준비 전에 병합을 기다린다. 새 파일이 들어오면 해당 칸만 상세·상자 메시를 다시 만들고 원경 통합 버퍼를 갱신한다.
- 상세: 높음은 칸 AABB까지2km 이내, 균형은1km 이내에 원래 footprint 외피를 사용한다. 중간: 높음5km·균형3.5km 이내는 기존의 건물별 AABB 상자다. 낮음은2km 이내 상자다. 예산이 부족하면 다음 단계로 내려간다.
- 원경: 칸별 원래 건물 바닥·지붕 높이와 방위별 투영 폭을 사용해 최대32열의 계단형 수직 실루엣을 만든다. 8방향 중 관찰 방위에 가까운 평면을 선택한다. 실제 건물이 없는 열은 비워 두며, 2km 전체를 최고 높이의 거대 상자로 덮지 않는다. 선택한 모든 먼 칸의 인덱스를 **공유 메시1개**에 묶는다. 선택이 같으면 GPU 인덱스 버퍼를 다시 올리지 않는다.
- 상세·상자에서는 건물별 XZ 범위와 바닥/최고 높이를 유지한다. 원경 평면에서는 **투영 범위와 최소/최대 높이**를 유지하며 개별 건물의 깊이·지붕 세부를 근사한다. 원본 footprint·height 자료를 삭제하거나 변경하지 않는다.
- 도시 기본 패스 예산은 높음/균형30만 삼각형, 낮음10만이다. 모든 가시 칸의 원경 비용을 먼저 확보하고 가까운 칸부터 상세/상자로 올린다. 상세·상자 메시를 최대49개로 제한하고 먼 도시 통합1회를 더해 기본 패스50회 이하로 제한한다. 높음 SSAO의 기본+법선2패스에서는 도시60만 삼각형 이하가 되도록 구성했다. 이는 코드의 선택 제한이며 **실측 합격 수치가 아니다**. 칸 수가 크게 늘면 원경 열 수를 줄여 최소 예산을 확보하며, 최소2삼각형/칸도 감당하지 못하면 오류로 처리한다.
- 도시 컬링은 건물/과거 파일별 메시가 아니라 칸별로 한다. 카메라 far까지 거리 제곱 비교를 먼저 하고 절두체 검사를 한다. 별도로 같은 메시를 three.js가 재검사하지 않도록 처리했다.
- 식생도256m 상위 칸을 도입했다. 상위 칸의 전체 LOD 경계와 최대 가시 거리를 먼저 검사하고, 통과한 칸의 나무·바위만 개별 검사한다. `chunk-culling.js`의 거리 계산은 벡터 복사·제곱근 없이 제곱 거리로 바꿨다.

## 계측·회귀 검증 준비

`__hikingMetrics.landscape.cityGrid`는 칸 수·거리 제외 수·절두체 검사 수·단계별 칸 수·선택 기본 삼각형/호출 수를 기록한다. `natureBroadPhase`는 식생 상위 칸의 검사 수를 기록한다. 실제 GPU 제출량은 기존 `rendering.breakdown`, `performance.breakdown`을 사용한다.

`performance.categories`를 추가해 같은 프레임에서 종류별 모든 패스를 먼저 합산하고 평균·최대 삼각형/최대 호출을 기록한다. 패스별 최대를 서로 더해 도시 최대라고 잘못 보고하지 않는다. 벤치마크는 도시 최대 높음60만·균형30만, 균형 호출100회 제한도 합격 조건에 포함한다. 모든 패스 전체 최대 높음250만·균형150만, 30fps·50ms초과1% 기준도 유지한다.

노면 경계 분할로 선분 번호가 바뀌어도 벤치마크 시작점은 원래 GPX310번 점을 찾도록 바꿨다. 측정 중 페이지 재로딩을 감지하면 해당 실행은 실패한다. 사본에는 이미 반영한 구간별 노면 코드도 포함한다. after3는 노면 변경 전 사본을 사용했으므로 **보행 속도·재질·이동 거리 차이를 함께 확인해야 하며 완전히 동일한 조건의 전후라고 단정하지 않는다**.

추가 테스트: 파일 경계 통합·추가 로딩 시 노드 수 유지·상세/상자의 건물 범위/높이, 8방향 실루엣의 투영 폭/최저·최고 높이, 거리 우선 컬링과 호출 제한·동일 인덱스 재사용. 계측 테스트는 같은 프레임의 패스 합산 최대를 검증하도록 보강했다. 산기획이 바꾼 하층 식생 꼭짓점15·24 허용 검사는 유지했다.

## 정적 검사와 사본

변경 JS·추가 테스트의 `node --check`와 `git diff --check` 통과. 이는 구문·공백 검사이고 테스트 실행을 대신하지 않는다. npm test·빌드·preview·after4·캡처는 실행하지 않았다.

측정용 로컬 사본: `/private/tmp/gwanak-after4-snap-hhghjQ`. src/assets/public/data/scripts/tests/docs와 고정 의존성 node_modules, package·Vite·index 파일을 복사한다. .git과 기존 대용량 측정 artifacts는 복사하지 않는다. 원본 폴더에서 계속되는 수정과 개발 서버 HMR을 분리하기 위한 것이며 사본에서 빌드·preview를 사용한다.

## 가정

건물 footprint 좌표는 기존 로더와 같은 X/Z 미터 좌표이며 ground+height는 원래 지붕 높이다. 실루엣은 장거리 표현이고 실제 도시의 개별 깊이와 지붕 형상을 근사한다. 2km·1/2/3.5/5km 전환 거리와32열은 검수 전 기본값이다. 8방향 전환의 외형 변화·칸 사이 연결·물 위 중첩·높은 건물의 실루엣 과장이 없는지 북쪽 원경 화면으로 확인해야 한다. 성능 목표는 실측 전 미달 해소를 주장하지 않는다.
