# 변경 기록 — 흡연장 실시간 멀티 연결 (2026-11-08, 산풍경)

상위 업무: 멀티 서버 붙이기(등산·흡연장 함께하기 + 등산 채팅) 3/4단계. 커밋하지 않았습니다.

## 무엇을 했나
흡연장(`/smoking/`)을 함께 걷기 서버(또는 서버가 없으면 같은 브라우저 창끼리)에 붙였습니다. 같은 방 사람이 서로의 동동이·위치·채팅·담배(불·연기)를 봅니다.

- **연결** `src/lounge/multi.js`(새 파일, 산개발 파일과 겹치지 않게 흡연장 쪽은 여기 모음)
  - 전송은 `createWebSocketTransport({experience:'smoking',room,name})`, 서버 주소가 없으면 `createBroadcastTransport`(채널 `gwanak-multi:smoking:방`). 서버 주소 규칙은 등산과 같음(`?server=` → `VITE_MULTI_SERVER_URL`).
  - 위치 `s {q,z:0,x,y,h,v,f}`: 움직이면 10Hz, 서 있으면 1초에 한 번. 자리(난간·벤치) 들고 날 때·멀리 옮길 때 `FLAG.jump`, 달리면 `FLAG.run`, 벤치에 앉으면 `FLAG.sit`.
  - 받은 위치는 등산 `createInterpolator`로 보간. `FLAG.jump`를 받으면 보간 기록을 비우고 바로 옮김(옥상이 좁아 등산의 25m 순간 이동 기준으로는 미끄러지기 때문).
  - 담배: 내 `smoke.js`가 내는 `lounge:smoke`(isPlayer)에서 상태가 바뀔 때만 `{t:'lounge:smoke',id,state,lit}`. 들어올 때 지금 상태를 한 번 보냄. 받는 쪽은 `smokePlan()`이 상대 담배(같은 `smoke.js`, isPlayer:false)에 start·light·puff·flick·trick·dispose를 부르게 함 → 손에 담배·불씨·연기를 받는 쪽이 그림. 중간에 들어와도 꺼내기 → 불 붙이기부터 따라감.
  - 채팅: HUD 입력·이모트가 낸 `lounge:chat {id:'me'}`를 `{t:'c'}`로 보냄. NPC 대화 칩의 각본 대사(`scripted`)는 내 화면 NPC 맥락이라 보내지 않음. 받은 글은 `lounge:chat {id,name,text,remote:true}`. 서버가 되돌려 준 내 글(id = 내 ID)은 다시 그리지 않음. 너무 빠르면(`c-limit`) "잠깐만요, 조금 천천히 말해요", 서버 모드인데 연결 전이면 "아직 연결 전이라 옥상 NPC만 들었어요".
  - 이름: `j`로 주고받음. 비면 `손님XXXX`. 내 컴퓨터 모드는 처음 보는 사람이 생기면 내 이름을 바로 알림.
  - 몸: `ctx.createAvatar`(동동이 그대로) + 회사원 옷. 상대 옷은 hello에 싣지 않고 **ID로 결정적 선택**(`remoteOutfit`, 4종). 몸으로 그리는 사람은 PC 6명·휴대폰 3명(가까운 순), 나머지는 몸 없이 목록에만. 6초 소식이 없으면 뺌.
- **화면** `src/lounge/multi-ui.js`·`multi.css`(새 파일)
  - 위 오른쪽 `👥 같이 피우기` 단추. 참가하면 이 단추가 **연결 상태 칩**이 됨(따로 칩을 두지 않아 HUD 알림·자리 단추와 겹치지 않음). 6종: ⏳ 옥상 문 여는 중… / 🟢 같이 피우는 중 · N명 / 💻 내 컴퓨터 모드 · N명 / 🔄 다시 연결 중…(옥상 NPC랑은 계속 놀 수 있어요) / ⚠ 연결 끊김(눌러서 다시 연결) / 🚪 옥상이 꽉 찼어요(다른 방으로). 좁은 휴대폰 세로·휴대폰 가로는 그림 + 사람 수만.
  - 카드: 방 이름(기본 `옥상-1`)·닉네임(로비 닉네임이 기본, 비우면 손님XXXX)·올라가기/내려가기·상태 줄. 입력 중에는 이동·담배 키와 Enter(채팅 열기)가 먹히지 않음. 휴대폰 키보드가 올라오면 보이는 영역 안에서 스크롤.
  - 이름표: 다른 사람 머리 위. 말풍선이 떠 있는 동안은 말풍선이 이름을 보여 주므로 숨김.
- **기존 파일 작은 수정**
  - `main.js`: 멀티 만들기·루프에서 `multi.update`·`multiUi.update`, `window.lounge.multi`, `status().multi`. `?multi=`가 있으면 바로 참가(처음 온 사람은 로비에서 닉네임을 정한 뒤 — 서버 이름은 접속 때 정해짐; `&name=`이 있으면 바로).
  - `hud.js`: 말풍선이 같이 피우는 사람도 찾게 `avatarOf`에 `ctx.multi.avatarOf(id)` 한 줄, 이름표용 `hasBubble(id)`.
  - `npc.js`: 사람 채팅에도 NPC 한 명이 **가끔** 대답(`REMOTE_REACT` 확률 0.3·12초 쉼, 거드는 NPC 없음, NPC끼리 이어지지 않게 depth 2).
- 공용 파일(`src/multi-*.js`·동동이·카툰)은 고치지 않았습니다. 그래서 등산 쪽 확인은 `npm test`·`verify-multi-chat.mjs` 등산 칸으로 했습니다.

## 가정
- 사람이 들어와도 NPC 4명은 그대로(기획 기본값).
- 상대 옷은 ID로 고름(본인이 고른 옷과 다를 수 있음). 옷을 보내려면 규격에 칸을 더해야 해서 산개발과 정할 일.
- 상대의 앉기·난간 기대기 자세는 아직 그리지 않음(위치만, `FLAG.sit`은 보냄).
- 상대 담배의 맛(꿀모금·콜록)·묘기 종류는 보내지 않음(규격이 `state`·`lit`만). 묘기는 링으로 보임.
- 서버 모드 이름은 접속 때 정해짐. 접속 뒤 로비에서 닉네임을 바꾸면 다음 접속부터 반영(내 컴퓨터 모드는 바로).
- 다른 사람끼리 몸이 겹쳐도 밀어내지 않음(NPC·나와의 충돌은 그대로).
- 캡처 이름은 NPC(미나·지훈)와 헷갈리지 않게 하늘·바다를 씀. 처음 돌린 캡처의 `smoking-*-지훈화면.png` 2장은 지우지 않고 남겨 둠(지금 기준은 `…-바다화면.png`).
