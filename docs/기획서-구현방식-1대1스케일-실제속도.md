# 관악산 온라인 등반 — 구현 방식 · 1:1 스케일 · 실제 속도 기획서

작성: 산기획 · 2026-11-02 · 킥오프 회의(온라인 등산 킥오프)를 보완하는 문서

## 0. 이번에 정한 것 (대표 결정)

| 항목 | 결정 |
|---|---|
| 구현 플랫폼 | **웹 브라우저 3D**. 설치 없이 링크로 체험 |
| 시간 기준 | **실제 시간 + 이어하기**. 빨리 가기 없이 실제 경사에 맞춘 속도로 걷고, 진행 상황은 저장해 나눠서 오른다 |
| 시점 | **1인칭(걷기) + 3인칭(둘러보기) 전환** |
| 조작 | **직접 걷기 + 자동 걷기 켜기**. PC 웹은 키보드, 모바일 웹은 화면 터치 컨트롤러 |
| 화면 비율 | **세로·가로 모두 지원**. 모바일에서 돌려도 문제없어야 한다 |

킥오프에서 정한 내용은 그대로 유지합니다. 랜선 체험자 대상, 서울대 입구(관악산입구, A 서울대 계곡 코스)에서 연주대까지 약 4.6~4.7km, 체크포인트 5곳(제1광장·아카시아동산·제4쉼터·연주샘·제3깔딱고개, 2026-11-02 확정), 공공누리 1·3유형 자료를 씁니다. 이동 방식은 "자동 걷기 + 일시정지"에서 **직접 걷기와 자동 걷기를 둘 다 쓰는 방식**으로 넓혔습니다.

## 0-1. 조작 방식

공통 규칙
- 걷는 속도는 어떤 조작을 해도 **실제 속도(3장 모델)로 고정**합니다. 달리기나 빨리 가기는 없습니다.
- 등산로를 따라 걷습니다. 등산로 폭 안에서는 좌우로 비켜 갈 수 있지만 등산로 밖으로는 나가지 못합니다. 갈림길에서는 방향을 고를 수 있고, 정해진 코스에서 벗어나면 안내합니다.
- 자동 걷기를 켜면 손을 떼도 계속 걷습니다. 앞으로 가기 입력이 들어오면 자동 걷기와 이어지고, 멈춤 입력이 들어오면 자동 걷기가 꺼집니다.
- 입력이 없으면 서 있는 상태가 되고, 걸은 시간도 멈춥니다(쉬는 시간과 같음).

PC 웹 (키보드 + 마우스)
| 동작 | 키 |
|---|---|
| 앞으로 걷기 / 뒤로 | W·↑ / S·↓ |
| 등산로 안에서 좌우 비켜 가기 | A·← / D·→ |
| 둘러보기 | 마우스 드래그(포인터 잠금 선택), Q/E로 몸 돌리기 |
| 자동 걷기 켜기·끄기 | R |
| 일시정지(3인칭 둘러보기) | Space |
| 1인칭·3인칭 전환 | V |
| 지도·진행률 열기 | M |
| 소리 켜기·끄기 | 메뉴 |

모바일 웹 (터치 컨트롤러)
- 왼쪽 아래 **가상 조이스틱**: 위로 밀면 앞으로 걷고, 좌우로 밀면 등산로 안에서 비켜 갑니다. 얼마나 밀든 속도는 실제 속도로 고정합니다(살짝 밀어도 걷기 시작).
- 화면 오른쪽 빈 곳 **드래그**: 둘러보기. 3인칭에서는 두 손가락으로 확대·축소합니다.
- 버튼: 자동 걷기, 일시정지, 시점 전환, 지도. 엄지가 닿는 곳에 두고, 터치 영역은 최소 44×44pt로 합니다.
- 화면을 끄거나 앱을 바꾸면 자동으로 일시정지하고 저장합니다.
- 가능하면 진동(햅틱)으로 걸음을 약하게 느끼게 합니다(선택 기능).

## 0-2. 세로·가로 화면

- 세로와 가로 모두 지원하며, 돌리면 걷는 상태와 위치를 유지한 채 바로 다시 배치됩니다.
- **세로**: 시야각을 세로 기준으로 다시 계산해 위아래가 잘 보이게 합니다(눈높이 1.6m는 유지). 조이스틱은 왼쪽 아래, 버튼은 오른쪽 아래에 두고, 진행률은 위쪽에 얇은 띠로 보여 줍니다.
- **가로**: 조이스틱은 왼쪽, 둘러보기는 오른쪽 영역에 두고, 진행률은 위쪽 모서리에 둡니다.
- 노치·홈 바 같은 안전 영역(safe-area)을 지키고, 주소창이 생기고 사라질 때도 화면이 흔들리지 않게 합니다(dvh 기준).
- 체크포인트 사진·설명과 정상 인증 화면도 두 비율 모두에서 잘리지 않게 설계합니다.
- 확인할 화면 크기: PC 1920×1080·1366×768, 모바일 세로 390×844·360×800, 모바일 가로 844×390, 태블릿 세로·가로.

## 1. 원칙: 체험의 기준은 등산 경험

"실제로 관악산을 오르는 것과 같은 크기, 같은 거리, 같은 시간"이 첫 번째 품질 기준입니다. 화려한 연출보다 스케일과 시간이 정확한지를 먼저 봅니다.

## 2. 1:1 스케일 규칙

| 항목 | 기준 |
|---|---|
| 좌표 단위 | 3D 공간 1단위 = 실제 1m |
| 좌표계 | 원본 EPSG:5186(국토 TM). 서울대 입구를 원점으로 하는 지역 미터 좌표로 바꾼다(4km 범위라 정밀도 문제 없음) |
| 캐릭터 | 키 1.7m, 어깨너비 약 0.45m |
| 1인칭 눈높이 | 1.6m. 걸을 때 머리가 위아래로 2~3cm 흔들린다 |
| 보폭 | 평지 약 0.7m. 오르막에서는 0.5~0.6m, 계단에서는 계단 한 단에 맞춘다 |
| 계단·데크 | 실제 치수(단 높이 약 15~20cm)로 만들고, 발이 단 위에 정확히 놓이게 한다 |
| 바위·이정표·난간 | 사진과 실측 자료로 치수를 맞춘다. 3인칭 화면에서 캐릭터와 비교했을 때 크기가 어색하지 않아야 한다 |
| 발소리 | 소리 길이가 아니라 실제 걸음(발이 닿는 순간)마다 한 번씩 난다. 바닥 재질(흙·바위·데크·계단)에 따라 소리가 달라진다 |

### 지형 자료 해상도 (산리서치가 이용 조건 확인)
- 원거리·산 전체: 국토지리정보원 수치표고모델(DEM) 5m
- 등산로 양옆 약 30m 띠: 5m DEM을 촘촘하게 보간하고, 계단·바위·뿌리 같은 세부 모양은 직접 만든다(1m 이하 체감 해상도)
- 경로 선: 산림청 등산로 공간자료 또는 공개 GPX를 공식 안내도와 대조한다
- 지표 색·질감: 정사영상(항공사진). 공공누리·이용 약관을 확인한 다음에 쓴다

## 3. 실제 속도 · 시간 모델

### 3-1. 경사에 따른 걷는 속도
- 기본식은 Tobler 보행 함수 `v = 6 · e^(−3.5 · |경사 + 0.05|) km/h`를 쓴다
  - 평지 약 5.0km/h, 경사 10% 오르막 약 3.5km/h, 경사 25% 오르막 약 2.1km/h
- 노면 보정 계수: 흙길 1.0, 데크(평탄) 0.95, 돌길·뿌리 구간 0.85, 계단·데크 계단 0.75, 암릉 0.65(시범 구간에서 다시 조정)
- **보정 목표: 서울대 입구에서 연주대까지 걷는 시간이 공식 안내 소요시간의 ±10% 안에 든다.** **확정(2026-11-02): 공식 2시간 30분(서울관광재단 안내, 4.7km) → 허용 범위 135~165분.** 일시정지 시간은 제외한다. 이전 참고값 1시간 50분~2시간은 다른 코스 값이 섞인 것이라 폐기한다
- 거리는 지도상 평면 거리가 아니라 **경사를 따라 실제로 걷는 거리(3D 경로 길이)**로 잰다

### 3-2. 시간 규칙
- 빨리 가기나 순간이동은 없다. 이동은 오직 실제 속도의 자동 걷기로만 한다
- 일시정지(둘러보기)하는 동안에는 걷는 시간을 세지 않는다. 실제 산에서 쉬는 시간과 같다
- 진행 화면에 표시: 걸은 거리 / 남은 거리, 현재 고도 / 누적 상승 고도, 걸은 시간, 실제 속도 기준 남은 예상 시간

### 3-3. 이어하기
- 경로상 위치(m), 걸은 시간, 방문한 체크포인트를 계속 브라우저에 저장한다
- 다시 들어오면 "○○ 지점에서 이어서 오르기"로 그 자리에서 시작한다
- 정상 인증 화면에는 총 3D 거리, 걸은 시간(쉰 시간 제외), 누적 상승 고도, 나눠 오른 횟수를 보여 준다

## 4. 시점
- **걷는 중**: 1인칭, 눈높이 1.6m, 진행 방향을 본다
- **일시정지·둘러보기**: 3인칭으로 바뀐다. 캐릭터 주위를 돌면서 보고, 확대·축소할 수 있다. 1인칭으로 고개만 돌려 보기도 고를 수 있다
- 걷기를 다시 시작하면 1인칭 진행 방향으로 부드럽게 돌아온다(킥오프에서 합의한 내용)

## 5. 웹 기술 방향 (산개발 확정)
- 렌더링: Three.js(WebGL. WebGPU를 쓸 수 있으면 같이 쓴다)
- 지형은 조각으로 나눠 불러온다(LOD). 등산로 근처는 상세하게, 멀리는 단순하게 만든다. 연주대 전망(서울 시내)은 원경용 저해상도 자료로 만든다
- 목표 성능: 일반 노트북 크롬에서 60fps, 처음 로딩 15초 이내
- 모바일 웹: 최근 3년 안의 보급형 스마트폰(iOS Safari·Android Chrome)에서 30fps 이상. 모바일에서는 화질 단계를 자동으로 낮춥니다(원경 거리·그림자·숲 밀도)

## 6. 완료 기준 (킥오프 기준에 더해)
1. **스케일**: 3인칭 화면에서 1.7m 캐릭터와 계단·이정표·난간을 비교한 캡처를 실제 관악산을 아는 사람이 확인하고 통과시킨다
2. **거리**: 3D 경로 총 길이와 공식 안내 거리의 오차가 3% 이내
3. **고도**: 체크포인트 5곳의 고도가 공식 수치와 ±5m 이내(연주대 629m)
4. **시간**: 자동 시뮬레이션으로 전 구간을 걸었을 때 걸리는 시간이 공식 소요시간 ±10% 이내. 시범 구간(정상 접근)도 같은 기준을 구간별로 적용
5. **이어하기**: 아무 위치에서 창을 닫았다 다시 열어도 같은 위치, 같은 걸은 시간, 같은 체크포인트 기록이 유지된다
6. **발소리**: 걸음 수 = 3D 거리 ÷ 보폭과 일치하고, 재질별 소리가 구분된다
7. **조작**: PC 키보드와 모바일 터치 컨트롤러 모두로 직접 걷기, 자동 걷기, 둘러보기, 시점 전환이 된다. 어떤 입력을 써도 속도는 실제 속도를 넘지 않는다
8. **화면 비율**: 0-2의 화면 크기 전부에서 세로·가로 모두 UI가 겹치거나 잘리지 않는다. 걷는 도중 화면을 돌려도 위치·상태가 유지된다

## 7. 진행 순서
1. 자료 확정(산리서치) → 2. 정상 접근 시범 구간에 1:1 지형·캐릭터·속도 모델을 적용(산풍경·산개발·산디자인) → 3. 시범 구간에서 스케일과 시간 검증 → 4. 전체 경로로 확장

## 변경 (2026-11-02, 대표 피드백 반영)
- **계단 속도:** Tobler 식 대신 걸음 기반 모델을 씁니다. 1.2걸음/초, 한 걸음에 한 단(18cm/30cm)이면 수직 약 0.22m/s, 3D 약 0.42m/s입니다. 전체 보정 계수는 계단에 곱하지 않고, 나머지 구간 계수로 전체 135~165분을 맞춥니다.
- **시선과 진행 방향 분리:** 걷는 중에도 자유롭게 둘러보고, 자동으로 정면에 돌아가지 않습니다. 정면 보기는 F 키나 버튼으로만 합니다.
- **3인칭 등반:** 3인칭에서도 걷기·자동 걷기·계단 오르기가 됩니다. 걷기 시작해도 1인칭으로 강제 전환하지 않습니다.
- **실사풍 그래픽:** PBR(CC0) 재질, HDRI 하늘, 그림자, 대기 원근감, 소나무·참나무 숲, 화강암 바위를 씁니다.
- **주변 풍경:** 서울 시가지·한강·N서울타워·63빌딩·롯데월드타워를 실제 방위와 거리로 넣습니다. 지형은 Copernicus GLO-30(국토지리정보원 DEM은 받는 대로 교체), 건물은 OSM(ODbL 출처표시)을 씁니다.
