# 오르막 무릎 IK 보완 — 실행 검증 대기

## 반영
- 현재 애니메이션의 무릎 위치로 굽힘 방향을 추정하던 방식을 몸의 월드 전방을 투영한 pole vector로 교체했다. 반복 접지 보정 중에도 같은 방향을 쓴다.
- 발 목표를 두 관절의 도달 범위 안으로 제한하고 완전 신전을 피하는 여유를 둔다. 영거리와 전방 축 특이점도 처리한다.
- 골반 하강량은 수평 거리를 고려한 수직 도달 범위로 계산한다. 발 목표가 골반 위에 있거나 수평 도달 범위 밖이면 하강하지 않는다.
- 동작 즉시 중단을 없애고 지수 가중치 블렌딩을 적용했다. Walk/Stairs/Rock은 같은 보행 위상으로 샘플링하며 Rock 진입 .47/이탈 .41, Climb 이탈 .12의 경사 히스테리시스를 둔다.
- 회귀 테스트를 추가했다. 여러 방향·목표 높이의 전방 굽힘, 뼈 길이 보존, 영거리·과도한 목표, 골반 보정을 검사한다.

## 검증 상태
코드 반영만 완료했다. 대표 영상 재생, npm test, GLB 실제 자세 검수, 동일 위치 전후 캡처, 커밋은 미완료다. 따라서 시각적 결함 해결과 기존 접지 성능 보존을 아직 확정하지 않는다. 기존 artifacts/hiker-third-* 이미지는 이번 수정 후 증거가 아니다.

## 가정
현재 파일은 11월 2일 23:33 Hiker.glb다. 스틱 포함 새 GLB나 노드 계약의 전달은 확인하지 못했다. 추측한 노드 이름으로 팔을 움직이는 연결은 넣지 않았다. 신규 GLB 수령 후 양손 그립·팁 노드와 좌표계를 확인하고 반대 발 접지 정보를 이용한 교차 보행을 연결해야 한다.

## 대표 확인 필요
읽기 명령 실행 도중 `rejected by user`가 반환됐다. 자율 진행 지시의 스크립트 실행 금지에 따라 테스트·캡처 스크립트는 실행하지 않았다. 아래는 프로젝트 폴더에서 실행할 후속 명령이다.

```sh

```

기존 캡처 스크립트는 실시간 이동 후 찍으므로 엄밀한 동일 위치·위상 비교 도구가 아니다. 검수 시 수정 전후 동일 s·heading·stepPhase·카메라·화질을 고정하고 경사·계단·바위 각각 확인해야 한다. 다른 진행 중 변경은 스테이징 대상에서 제외한다. 푸시는 하지 않는다.
