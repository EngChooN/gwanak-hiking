# 변경 기록 — 함께 걷기 HUD 시작 버튼·연결 상태 칩 (2026-11-08, 산디자인)

## 왜
함께 걷기가 주소(`?multi=`)로만 들어가져 AGENTS.md §3 '모든 기능은 HUD 버튼으로도'에 어긋났다. 서버 연결(산개발)이 끝나 화면 쪽만 남아 있었다.

## 무엇을
- **시작 버튼**: 설정 시트 첫 줄 묶음에 `👋 함께 걷기`(`.me-entry`)를 넣었다. 새 탭은 만들지 않았다(휴대폰 세로 탭 줄이 이미 5칸으로 꽉 참). 누르면 시트가 접히고 참가 카드가 열린다.
- **참가 카드**: 방 이름(기본 `관악산-1`, 한글·영문·숫자·`-`·`_` 24자 — 서버 `sanitizeRoom`과 같은 규칙), 닉네임(12자, 비우면 빈 글자를 보내 연결 쪽이 `등산객XXXX`를 붙임), `참가`. 참가 중에는 방 이름·닉네임을 잠그고 `나가기`를 보여 준다. 마지막 닉네임은 localStorage `gwanak-multi-name`에 기억한다.
- **연결 상태 칩**(`.me-chip`, 누르면 카드가 열림): 연결 중 ⏳ · 연결됨(n명) 🟢 · 다시 연결 중 🔄 · 끊김 ⚠(누르면 다시 참가) · 방 꽉 참 🚪(누르면 `방이름-2`가 채워진 카드가 열림) · 내 컴퓨터 모드 💻(서버 없음).
  - 테두리 색: 연결됨 초록·주의(다시 연결 중·꽉 참) 노랑·끊김 빨강. 수첩 토큰(`--paper2`·`--ink`·`--go`·`--mid`·`--low`)을 써서 낮·노을·밤을 그대로 따른다.
  - 자리: PC는 위 가운데, 휴대폰 가로는 아래 가운데(위쪽이 진행 카드·시점 칩·태그로 가득함), 휴대폰 세로는 시점 칩 아래 왼쪽. z-index 45로 `multi-toast`(40)보다 위라 알림이 HUD에 가려지지 않는다.
- **키보드**: 입력 글자 16px(iOS 확대 방지), `visualViewport`로 카드를 보이는 화면 아래에 붙이고 높이를 줄인다(`--me-kb`·`--me-vh`). 글자 치는 동안 단축키(R·C·F…)가 걷기에 먹히지 않게 키 이벤트를 막는다.
- **이벤트**(연결 코드와는 이것만): 보냄 `hiking:multi-join {room,name}`·`hiking:multi-leave`, 받음 `hiking:multi-status {state,room,count,transport}`. 참가하면 `body.nb-multi`를 켜서 기존 인사 메뉴(배낭 탭 '함께 걷기')가 그대로 열린다. 주소(`?multi=`)로 들어와 참가 이벤트 없이 상태가 오면 참가 중으로 본다. 나가기 뒤에 늦게 온 상태 이벤트는 무시한다.
- 연결 쪽 알림은 `body[data-multi-entry]`가 있으면 띄우지 않게 이미 되어 있어(산개발) 칩과 겹쳐 중복되지 않는다.

## 파일

## 확인
- `npm test` 604개 통과(새 7개 포함).
- `scripts/capture-multi-entry.mjs`: 가짜 상태 이벤트로 6가지 × 3화면(390×844·844×390·1920×1080) + 설정 시트·참가 카드·참가 중 카드. 칩이 진행 카드·태그·탭·도장·칩·시점 칩·출처 줄과 겹치지 않고, 버튼·입력이 44px 이상이며, 콘솔 오류 0건. 결과 `artifacts/multi-entry-2026-11-08/`(+`audit.json`).
- 실제 참가·나가기(내 컴퓨터 모드)로 `hiking:multi-join` → 상태 이벤트 → 칩, `hiking:multi-leave` → 칩 사라짐을 브라우저에서 확인.

## 아직 못 한 것
- 실제 휴대폰 키보드가 올라온 모습(`visualViewport` 처리)은 기기에서 확인하지 못했다. 헤드리스 크롬은 키보드를 띄우지 못한다.
- 서버 모드(`?server=`)의 참가 카드·칩 캡처는 상태를 가짜 이벤트로 만든 것이다. 실제 서버 붙임은 `scripts/verify-multi-server.mjs`가 확인한다.
