# 함께 걷기 서버 호스팅 비교 (지역·비용·https)

작성: 산리서치 · 확인 날짜: **2026-11-08** (이 날짜에 공식 문서를 읽은 값). 실제 가입·결제·배포는 하지 않았습니다.
표기: **미확인** = 공식 페이지에서 값을 못 읽은 것. **(2차)** = 공식이 아닌 자료에서 본 값.

## 0. 결론 (추천 1안)

**1안: Fly.io 도쿄 리전, 컨테이너 1대 (`server/Dockerfile` 그대로)**

| 이유 | 내용 |
|---|---|
| https(wss) 부담이 없음 | 앱을 만들면 `*.fly.dev` 주소와 HTTPS가 자동으로 붙습니다 ([Fly 도메인 문서](https://docs.fly.io/networking/custom-domain), 2026-11-08). 도메인 구입·Caddy 설정이 필요 없습니다. 서버는 ws://로 두고 앞단이 TLS를 맡는 현재 설계와 맞습니다 |
| 초기 비용이 가장 낮은 편 | 상시 1대 $2.19/월 + 볼륨 1GB $0.15/월 + 나가는 트래픽 $0.04/GB. 동시접속(CCU) 10이면 월 약 $4입니다 |
| 한국에서 가까움 | 도쿄 리전이 있습니다. 서울 대비 지연은 측정하지 못했습니다 |
| 이미 준비됨 | `server/Dockerfile`과 환경 변수 설정이 있어 `fly.toml`만 더하면 됩니다 |

**약점과 전환 기준:** 트래픽 단가($0.04/GB)가 고정 포함형보다 비쌉니다. 월 트래픽이 약 0.5TB를 넘는 규모(CCU 50 안팎)가 되면 **Hetzner 싱가포르 또는 Vultr 서울 + 도메인 + Caddy**로 옮기는 편이 쌉니다(서버는 그대로, 주소만 `VITE_MULTI_SERVER_URL`로 바꾸면 됩니다). 아래 **미확인** 3건은 가입 전에 확인해야 합니다: 도쿄 머신 단가, 연결이 살아 있는 동안 자동 중지 여부, 장시간 연결 끊김 시간.

**2안:** Vultr 서울(고정 포함 트래픽이 크고 초과 단가 $0.01/GB로 낮음, 한국 지연 최소). 도메인과 Caddy가 필요하고 플랜 값이 미확인이라 2안으로 뒀습니다.

## 1. 계산 기준 (`docs/멀티-설계.md`)
- 사람당 받는 양 약 3.4KB/s(방 20명 기준). 월 평균 동시접속 1명 ≈ 9GB.
- 설계 문서의 월 트래픽: **CCU 10 ≈ 47GB, CCU 100 ≈ 0.9TB, CCU 500 ≈ 4.5TB** (그 CCU를 한 달 내내 유지하는 상한).
- 서버 코드는 전체 400명 상한이라, CCU 500은 서버 2대 이상이 필요합니다. 아래 CCU 500 비용은 **트래픽 비용만** 본 값이고 서버 대수 증가는 뺐습니다.
- 환율은 적지 않고 각 통화로 둡니다. 프로모션·세금(VAT)은 뺐습니다.

### 후보별 주의
- **Oracle:** 놀고 있는 무료 인스턴스는 회수될 수 있습니다(7일간 CPU 95퍼센타일 20% 미만·네트워크 20% 미만). 우리 서버는 평소 한가해서 **회수 대상이 되기 쉽습니다.** 마이크로 VM은 1/8 OCPU·1GB·인터넷 50Mbps. 서울·춘천을 홈 리전으로 고를 수 있는지는 **미확인**이고, Arm 인스턴스는 춘천에서 만들 수 없다고 문서에 있습니다. 2026년 무료 등급 축소 소문이 있으나 공식 확인 못 함(**미확인**).
- **Cloudflare:** 서버 코드(Node `http`·`crypto`)를 **Workers 런타임용으로 다시 써야 합니다.** 지금 서버는 10Hz 타이머로 스냅샷을 보내는데, 타이머가 있으면 휴면에 들어가지 못해 시간 요금이 계속 붙습니다(문서: `setTimeout`·`setInterval`이 객체를 깨워 둠). 무료 등급은 하루 요청 10만 건이라, 한 사람이 계속 걸으면 하루 약 4.3만 건(초당 10개 ÷ 20 × 86,400초)이라 **한 사람 수준**에서 바닥납니다. 지역 지정(아시아 쪽에 방 두기)은 문서에서 **미확인**.
- **Lightsail:** 서울이라 지연은 가장 유리하지만 초과 단가가 가장 비쌉니다.

## 4. https(wss://) 조건

배포 사이트가 GitHub Pages(https)이므로 브라우저는 `wss://`만 허용합니다. 서버는 ws://만 열고, TLS는 앞단이 맡는 설계입니다.

| 후보 | 인증서 받는 방법 | 도메인 필요? |
|---|---|---|
| Fly.io | 앱 이름으로 만들어지는 `*.fly.dev`에 HTTPS 자동 적용. 인증서 세부 발급 방식은 문서에 없고, `wss` 종단은 TLS 종단 문서를 읽지 못해 **미확인** | 불필요. 내 도메인을 쓰면 인증서 10개까지 무료 |
| VM(Lightsail·Vultr·Hetzner·Oracle) | **Caddy**가 Let's Encrypt 인증서를 자동 발급·갱신. 도메인의 A/AAAA 레코드가 서버를 가리켜야 하고, 80·443 포트가 열려 있으며, 데이터 폴더가 영구여야 함 ([Caddy 문서](https://caddyserver.com/docs/automatic-https)) | **필요**(연 비용은 미조사). Caddy는 IP 주소에는 자체 서명 인증서만 줘서 브라우저가 거부합니다 |
| VM + IP 인증서 | Let's Encrypt `shortlived` 프로필은 IP 인증서가 가능하고 유효기간이 약 6일([프로필 문서](https://letsencrypt.org/docs/profiles/), 갱신일 2026-10-04). 운영 환경 제공 여부와 Caddy 지원은 **미확인**, 갱신 자동화가 필수 | 불필요(단, 실험적으로 보고 추천하지 않음) |
| VM + Cloudflare Tunnel | 이름 붙인 터널은 TLS를 Cloudflare가 처리. 내 도메인이 Cloudflare에 있어야 하는지 등은 이번에 확인하지 못함(**미확인**). Quick Tunnel은 도메인 없이 되지만 주소가 매번 바뀜(`멀티-서버-운영안내.md`) | 이름 터널은 필요 |
| Cloudflare DO | `workers.dev`로 `wss://`가 자동으로 되는지 문서에서 **미확인** | 불필요(추정) |

## 5. 개인정보 — 공개 전 처리방침에 적을 항목 (법적 판단 아님, 모두 **확인 필요**)

1차 설계 기준: 계정 없음, IP는 디스크·로그에 남기지 않고 메모리에만 해시로 둠(접속 중 + 신고 숨김 24시간), 신고 기록은 JSONL로 90일 보관.

| 항목 | 처리방침에 적을 내용 | 상태 |
|---|---|---|
| 수집 항목 | 닉네임(자유 입력), 방 이름, 게임 내 위치·동작(실시간 중계, 저장 안 함), 신고 사유, 접속 중 IP(메모리) | 확인 필요 |
| 수집·이용 목적 | 함께 걷기 중계, 속도 제한·악용 방지, 신고 처리 | 확인 필요 |
| 보관 기간 | 신고 기록 90일 후 서버 시작 때 삭제. IP는 디스크 저장 없음. 설계 문서의 "IP 30일 보관" 안과 실제 구현(저장 안 함)이 다르므로 **문구를 구현에 맞출 것** | 확인 필요 |
| 신고 기록에 무엇이 담기는지 | 신고자·피신고자의 임시 접속 ID, 방, 사유 등 필드를 처리방침과 맞춰야 함. 닉네임이 기록에 들어가는지 코드 확인 | 확인 필요 |
| 제3자 처리·국외 이전 | 호스팅 사업자가 해외(도쿄·싱가포르 등)에 서버를 두면 접속 IP가 그 나라 설비를 지남. 국외 이전 고지 의무 해당 여부 | 확인 필요 |
| 호스팅·프록시 로그 | 플랫폼·부하분산기·Cloudflare가 자체 접속 로그를 남길 수 있음. 우리 설계의 "IP 미저장"은 우리 서버 한정임 | 확인 필요 |
| 이용자 요청 처리 | 계정이 없어 조회·삭제 요청을 누구 것인지 식별할 방법이 없음. 신고 기록 삭제 요청 창구 | 확인 필요 |
| 14세 미만 | 산 체험 서비스 특성상 어린이 이용 가능성. 닉네임 자유 입력 안내 | 확인 필요 |
| 책임자·문의처 | 개인정보 보호책임자 이름·연락처, 신고 처리 담당·기한 | 확인 필요(대표 결정) |
