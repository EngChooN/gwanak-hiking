# after11 — 원경 도시 셰이더 오류 수정·접촉 음영 강화

산개발 / 2026-11-03. 구현 제출. 테스트·빌드·캡처·벤치 미실행. 완료 기준의 실측 충족 여부는 산기획 검수 대기다. 이전 8차 결과는 after10의 성능 근거이며 after11의 성능 보증으로 사용하지 않는다.

## 오류 경로

`src/city-grid.js:62`가 원경 도시 실루엣 통합 메시의 `MeshBasicMaterial`에 `applyAtmosphere`를 적용한다. 기존 `assets/realistic/skyline-reference.js`는 안개 fragment에서 `length(vViewPosition)`을 사용하지만, 설치된 Three.js r180의 `ShaderLib/meshbasic.glsl.js`에는 그 varying이 없다. 기본 도시 재질(Standard)에는 있으므로 원경 도시 Basic 변형에서만 실패한다. 6~8차의 오류와 일치하는 정적 원인이다. 실제 프로그램별 재현·수정 후 오류 0 확인은 실행 검수로 남긴다.

- 대기 감쇠에 전용 `gAtmosphereView` varying을 선언하고 `<project_vertex>` 뒤 `mvPosition.xyz`로 초기화했다. Standard와 Basic 모두 실제 카메라 거리를 사용한다.
- 그림자 깊이 재질 및 SSAO 법선 override는 원재질의 hook을 사용하지 않는다. terrainMaterial의 세 거리 참조는 Standard의 선언을 사용하므로 이번에 변경하지 않았다.
- 오류 콜백에 `SHADER_NAME`과 대기/지형 hook 분류를 추가했다. 오류를 숨기거나 배열을 초기화하지 않는다.
- 실제 Basic·Standard ShaderLib를 입력으로 쓰는 회귀 테스트를 작성했다. 이 테스트는 GLSL 드라이버 컴파일을 대신하지 않는다.

## 접촉 음영 변경

- 전체 DEM 2048² 지도 대신 경로 경계 상자 + 각 방향 24m를 감싸는 직사각형 지역 지도 한 장을 사용한다. 목표 간격 0.5m, 한 변 최대 4096이며 경로가 커서 초과하면 간격을 늘린다. 실제 해상도·m/텍셀·바이트는 `hiking.landscape().contactOcclusion`에 기록된다.
- 지역 타일을 이동 중 교체하는 대신 경로 전체 지도를 로딩 때 고정한다. 추가 장면 렌더·드로우콜·이동 중 업로드는 없다. R8 최대 16MiB의 CPU/GPU 각 한 장이므로 이전 각 4MiB보다 메모리가 늘 수 있다. 외곽 24m 밖에는 적용하지 않는다.
- 직사 확산광과 간접광에 동일 차폐를 적용한다. 바위 중심 최대 36%, 숲 중심 26%. 직사 반사광은 유지한다. 겹침은 최댓값만 취하고 모든 입력을 36% 이하로 제한한다.
- 반경은 첫 LOD 배치 크기 + 0.5m를 기준으로 바위 1~4m, 나무 1.5~5m로 줄였다. `(1-r²)` 감쇠를 사용한다. 새 자산이나 현장 측정치는 없다.
- 노면·계단 재질은 적용 대상에서 제외했다. 지도 업로드 전 경로 선분별 최대 노폭/2 + 2텍셀 + 0.35m를 지워 아래 지형에도 번지지 않게 했다. 높이·계단·발 접지 로직은 변경하지 않았다.
- `contactAO=off` 및 `hiking.contactOcclusion(false/true)` 비교를 유지했다. 토글은 uniform 변경이며 재컴파일하지 않는다. SSAO 자동 조절 정책도 유지했다.
- 36% 광량 감소가 출력 영상에서 정확히 40단계 이하라는 뜻은 아니다. 톤 매핑·안개·일광에 따라 달라지므로 최종 농도는 전후 화소 검수 후 판단해야 한다.

## 검수 보완 및 현재 확인 범위

- 접촉 캡처: rocks/forest 각각 켬·끔 rendering 상태와 shaderErrors를 보존하며, 오류가 있으면 실패한다. 전체 평균·15~40단계 화소 수·40단계 초과 수·밝아진 수·변화가 큰 32px 영역 30개를 JSON에 기록한다. 영역은 후보 목록이며 실제 바위 밑·나무 밑인지 육안 대조해야 한다. 전체 평균만으로 합격시키지 않는다.
- off/normal/full 진단 결과도 shaderErrors가 있으면 실패한다.
- 계단 캡처: 기존 접지 0.03m 검사와 함께 셰이더 오류 검사를 추가하고 두 시점의 contact-off 캡처도 저장한다.
- 8조건 벤치: 각 결과에 shaderErrors와 shaderPass를 추가했다. 빈 배열이 아니면 pass:false다. 기존 FPS·최대 프레임·재컴파일·안정 기준은 유지했다.
- CPU 지도 상한·중첩·노면 보호와 셰이더 토글 테스트를 갱신했다. `git diff --check` 통과. Node 구문 검사·테스트 본문·빌드 등 프로젝트 코드는 실행하지 않았다.
- 화면은 실행 금지로 생성하지 않았다. 이전 캡처를 새 결과로 첨부하지 않는다. 커밋·push·삭제·배포는 하지 않았다. 기존 작업 파일을 보존했다.

## 가정

기존 임시 배치의 폭·위치를 사용한 시각 근사다. 경로 보호는 음영 강도보다 노면·계단 번짐 방지를 우선한다. 목표 부위가 보호 폭 안에 있으면 음영이 사라질 수 있어 실제 캡처 검토가 필요하다. 경로 전체 지역 지도는 타일 스트리밍보다 변경량과 이동 중 비용이 적다고 판단했다.
