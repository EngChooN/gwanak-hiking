# after7 보행 중 전체 장면 재컴파일 제거

산개발 / 2026-11-03. 구현·정적 검사 완료, 실행 검수 대기. 커밋·push·삭제·외부 전송 없음.

## 변경

- `src/main.js`: resize에서 changed 판정과 prepareRendering 호출을 제거했다. shaderJobs에 의한 rAF 대기도 제거했다. 모든 초기 도시·식생 준비 뒤, 첫 rAF 전에만 lighting.prepare를 한 번 호출한다. 창 크기·DPR·그림자 거리·AO 변경은 lighting.resize만 호출한다.
- `src/rendering.js`, `src/rendering-preparation.js`: 로딩 중 낮음·균형·높음의 그림자 경로를 compileAsync와 실제 렌더로 준비한다. 높음에서는 AO 꺼짐의 직접 출력과 켜짐의 후처리를 모두 렌더한다. AO 전환 자체에는 장면 compileAsync를 추가 호출하지 않는다. 완료·실패 시 원래 화질·AO·그림자 거리를 복원한다. 모바일은 AO 준비를 생략한다. 최종 복원 상태도 첫 rAF 전에 렌더한다.
- 기존 programKey는 화질 번호와 AO를 포함해 필요 없는 준비를 유발하므로 제거했다. 보행 중 전체 장면을 순회하는 명시적 compile/compileAsync 경로가 없다. 새 청크·재질의 일반적인 최초 렌더 준비까지 없어진다고 주장하지 않는다.
- `src/adaptive-quality.js`: 높음 목표를 55fps의 18.18ms로 명시했다. 하향은 기존처럼 목표의 105% 초과일 때 수행한다. 복귀는 높음 15ms 미만(다른 화질은 목표의 85% 미만)이 2초 측정창 5회 연속 유지될 때 수행한다. 60Hz의 16.7ms로는 복귀하지 않으므로 AO 꺼짐에서 회복한 뒤 다시 켜져 느려지는 반복을 억제한다. 측정 프레임 제외·필터 변경은 없다.

## 회귀 테스트와 정적 검사

`tests/rendering-preparation.test.mjs`에 4개 테스트를 추가했다. 준비 경로 순서와 AO 추가 컴파일 없음, 모바일 AO 생략·실패 시 복원, 실제 main.js의 resize/보행에서 준비 호출 금지 및 첫 rAF 이전 단일 호출, 60Hz 1분 동안 step 3 유지와 14ms의 충분한 여유에서만 복귀를 확인한다. 기존 adaptive-quality 테스트의 복귀 입력도 14ms로 변경했다.

- 변경 JS·테스트 6개 파일 모두 Node v22.23.4의 `--check` 구문 검사 통과. 이는 파일 실행 없이 구문만 검사한다. 기본 PATH에 node가 없어 설치된 절대 경로로 확인했다.
- `git diff --check` 통과. 새 파일은 구문 검사와 내용 검토를 수행했다.
- 테스트·빌드·캡처·벤치마크는 실행하지 않았다. 새 fps·최대 프레임·접지 오차 결과는 없다. 이전 77/77과 접지 0m는 after6 검수 결과이며 이번 결과로 대체하지 않는다.

## 검수 인계

새 사본: `/private/tmp/gwanak-after7-review.x1fwrH`.

`.git`, `node_modules`, `dist`, `artifacts`를 제외한 현재 작업 내용을 복사하고 원본 node_modules를 링크한다. 기존 미커밋 작업을 포함한 전체 프로젝트 사본이며 이전 변경을 되돌리지 않았다.

검수에서는 8개 조건 모두 pass:true(균형 ≥50fps, 높음 ≥55fps, 최대 프레임 ≤500ms), 계단 접지 ≤0.03m를 확인한다. compileCount는 로딩 준비 완료 횟수이므로 1을 유지해야 한다(내부 compileAsync는 로딩 때 세 경로를 준비한다). 특히 step 2↔3과 창 크기·DPR·그림자 거리 변경 뒤 compileCount 증가나 trace의 renderer.compile 전체 순회가 없는지 확인한다. 60Hz에서 step 3 복귀가 억제되는지도 본다. 20초 기존 검수 외에 경계 진동은 60초 관찰이 유용하다.

대가는 로딩 중 준비량과 후처리 자원 보관량 증가다. 실제 로딩 시간·메모리 영향과 첫 후처리 전환의 GPU 지연은 실행 검수에서 확인해야 한다. 수치 목표 달성은 아직 미확인이다.

## 가정

- 기존 1440×900·DPR1·20초·8개 조건과 측정 방식을 유지한다.
- 보행의 55fps 하한을 우선하며, 60Hz에서 화질 자동 복귀를 보수적으로 제한한다. 수동 화질 변경은 계속 가능하다.
- 화면 구성과 접지 코드는 변경하지 않았고 캡처는 산기획이 사본에서 수행한다.
