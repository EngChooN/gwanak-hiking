# 변경 기록 2026-11-04 — 쌍안경·휴대폰 카메라 화면 (산디자인)

**확인 방법(한 줄):** `npm run dev` 후 1인칭(V)에서 `B`(쌍안경), `P`(휴대폰), 휴대폰에서 `Y`(셀카)·`Space`(촬영), 3인칭에서 `P`.

## 만든 것
- `src/gadget-ui.js`, `src/gadget-ui.css` — 화면 오버레이. 상태는 `hiking:state`(gadget, view, phone{zoom,selfie}, binoculars{zoom})만 읽고, 조작은 `hiking:command`(phone-zoom, selfie, shutter, gadget-off)로 되돌린다. `main.js`는 css·모듈 가져오기와 `installGadgetUI()` 한 줄만 추가했다.
- 오버레이는 `#app` 밖(body 아래)에 있어 H(HUD 가리기)와 충돌하지 않는다. 크기는 HUD와 같은 `--u`(1920×1080에서 1px) 비율을 따른다(산기획 지시문의 `--ui`는 실제 변수명 `--u`).
- 새 테스트 `tests/gadget-ui.test.mjs`, 캡처 스크립트 `scripts/capture-gadget-ui.mjs`.

## 쌍안경 (1인칭만)
- 두 원이 겹친 테두리, 바깥은 검게, 가장자리는 부드럽게 어두워지는 비네트(마스크 그라디언트).
- 배율 표시(`8x`, 상태의 binoculars.zoom 그대로), 렌즈 테두리에 빨강·파랑 색수차를 아주 약하게.
- 켜면 HUD를 자동으로 접고(조이스틱·둘러보기 영역·대화상자만 남김) 아래에 `B 닫기 · 휠로 배율` 칩만 남긴다. 칩을 눌러도 닫힌다.
- 3인칭에서는 테두리 없이 작은 안내 칩만.

## 휴대폰 (1인칭)
- 가운데 둥근 모서리 검은 베젤 + 펀치홀. 위: 시간(현재 시각)·배터리(브라우저가 주면 실제 값, 아니면 80%)·격자/가로-세로/닫기 단추. 아래: 최근 사진 썸네일, 0.5x·1x·2x·5x, 셔터, 셀카 전환.
- 3x3 격자 켜기/끄기, 가로(기본)·세로 전환. 두 설정은 localStorage(`gwanak-phone-grid`, `gwanak-phone-orient`)에 저장.
- 셀카: 3D 캔버스를 CSS로 좌우 반전해 미리 보여 준다(저장 사진은 `toDataURL` 원본이라 반전 없음).
- 촬영: 흰색 번쩍임은 `main.js`가 이미 내는 `.shutter-flash`를 쓰고, 이 화면은 `hiking:photo` 때 썸네일을 방금 찍은 장면으로 갱신하고 튀어 오르는 효과와 셔터 눌림 효과를 준다.
- 3인칭: 테두리 없이 `휴대폰 모드 · P 닫기` 칩과 줌·셀카·촬영·닫기 단추만(HUD는 그대로 보임).
- 터치: 단추는 모두 36~64px 이상이고 세로로 화면을 눌러도 `main.js`의 탭-촬영이 그대로 동작한다(오버레이 빈 곳은 포인터를 통과시킴).

## 한계·가정
- **렌즈 왜곡은 넣지 않았다.** 3D 캔버스를 DOM에서 휘게 할 수 없어(셰이더 후처리가 필요) 색수차만 테두리에 약하게 넣었다.
- 저장되는 사진은 캔버스 전체라서, 베젤 안 화면(특히 세로 모드)과 저장 범위가 다르다. 화면에 보이는 영역만 자르려면 `main.js` `takePhoto()`에서 자르기가 필요하다(산개발).
- 1인칭 휴대폰도 HUD를 접는다(지시문은 쌍안경만 명시, 화면을 가리지 않게 같은 규칙으로 정함).
- 세로 모드는 화면 폭이 좁아 위쪽 단추가 빡빡하다. 실제 휴대폰 크기 확인은 못 했다.
- 터치 기기 실기 확인은 하지 못했다(헤드리스 데스크톱 캡처만).
