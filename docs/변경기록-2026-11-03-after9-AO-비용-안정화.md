# after9 — AO 비용 절감과 복귀 안정화

산개발 / 2026-11-03. 구현·정적 검사 완료. 실행 검수는 산기획 담당이며 새 성능 수치는 없다.

## 변경

6차 검수의 실제 렌더링 AO 해석 정정을 반영했다. after8 문서의 높음 step 0~2·AO 필수 기준은 폐기한다. 높음 55fps, 균형 50fps, 최대 프레임 500ms 이하와 안정성을 기준으로 판단한다.

- 처음 4초의 연속 창에서 예산 초과가 확인된 단계는 활성 시간 5분 동안 재시험하지 않는다. 60초 대기는 연속 8개 조건 도중 왕복을 일으킬 수 있어 5분을 선택했다. 기존 최초 하향 조건은 유지한다.
- 재시험은 최소 8프레임이면서 250ms 이상인 짧은 표본으로 먼저 판정한다. 평균 간격이 목표의 105%를 넘으면 즉시 원래 단계로 내리고 해당 단계를 세션 동안 잠근다. 33ms 표본이면 8프레임·264ms로, 기존 약 4초의 성능 저하를 줄인다. 단발 긴 프레임도 수치에서 제거하지 않는다.
- 화면 크기·기기 DPR 또는 화질 상한 변경 시 잠금과 계측을 초기화한다. 조절 자체의 DPR 변경은 잠금을 초기화하지 않는다. 실패 이력이 없는 가벼운 60Hz 기기는 기존 약 6초 간격의 복귀가 가능하다. 이미 비싸다고 확인한 단계의 개선은 5분 뒤 시험한다.
- SSAOPass의 법선·깊이, AO, 흐림 타깃을 각 변 절반으로 줄였다. 내부 픽셀 수는 1/4이고 원본 컬러 합성과 최종 출력 해상도는 유지한다. 커널 12샘플은 유지하며 준비 중에도 같은 해상도 정책을 쓴다. 장면 법선 제출량 자체는 줄이지 않았으므로 개선 폭과 경계 품질은 실행 확인이 필요하다.

## 벤치마크

`sample`에 `lighting.status.ao`를 전달하여 실제로 그린 프레임의 AO 상태를 집계한다. 벤치마크 시작·끝 `adaptive.*.ao`도 `hiking.rendering().ao`에서 직접 읽는다. `adaptive.*.renderedAO`는 마지막 표본의 실제 상태다. 일반 `hiking.adaptive().ao`는 여전히 요청 설정값이므로 둘을 혼동하지 않는다.

- `aoPass`: 활성 표본이 있고 20초당 단계 변경과 실제 AO 변경이 각각 1회 이하. AO가 꺼진 안정 상태도 통과한다. 단계 왕복은 2회로 집계한다.
- `adaptive.aoCost.on/off`: 측정 구간의 실제 AO별 프레임 수, 전체 작업 시간 합계와 평균(ms). `deltaWorkMs`는 켬 평균−끔 평균이다.
- `adaptive.aoCost.session`: 준비 완료 후 같은 화질·화면 세션의 누적 AO별 프레임 수·작업 합계와 평균 차이. 측정 구간이 모두 AO 끔이어도 앞선 자동 하향 자료를 볼 수 있다. 한쪽 표본이 없으면 차이는 null로 남기며 강제 AO 전환은 하지 않는다.
- 작업 시간은 입력·이동·렌더 제출·UI 등 프레임 전체의 CPU 경과 시간이며 GPU 완료 시간이 아니다. AO별 장면·단계가 다를 수 있어 통제된 동일 장면의 순수 AO 비용으로 단정하지 않는다. 기존 원본 fps·최대 프레임·재컴파일·도시 제출량 판정은 유지한다.

AO를 켠 상태가 예산을 넘으면 자동 하향하여 끈 상태로 유지한다. 개선 후 켠 상태가 높음 55fps를 충족하는지는 새 벤치마크로 판정하며 현재 성공으로 보고하지 않는다.

## 검증과 사본

변경 코드 4개와 테스트 2개의 Node v22.23.4 `--check` 구문 검사 및 `git diff --check` 통과. 테스트 파일 본문은 실행하지 않았다. 단위 테스트에 5분 대기, 264ms 재시험 실패·10분 추가 재시도 없음, 화면 변경 초기화, 가벼운 기기 복귀, 실제 AO별 작업 시간 집계를 추가·수정했다.

검수 사본: `/private/tmp/gwanak-after9-review.8M21Cm`. `.git`, `node_modules`, `dist`, `artifacts`를 제외하고 복사하고 원본 node_modules를 링크한다. 기존 미커밋 작업은 보존한다. 커밋·push·삭제·배포 없음.

## 가정

- 기존 1440×900·DPR1·20초·8개 조건을 유지한다. 높음의 AO 켜짐과 종료 step 상한은 요구하지 않는다.
- 5분은 활성 프레임 시간 기준이며 백그라운드 시간은 제외한다. 실패 잠금은 화면·화질 변경 또는 새 페이지 세션까지 유지한다.
- 재시험이 측정 구간에 걸리면 짧아도 왕복 2회이므로 안정성 판정에서 실패할 수 있다. 측정 프레임을 숨기거나 제외하지 않는다.
