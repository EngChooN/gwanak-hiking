## 자료 확인

`실경자료-조사.md` §5·6에는 시설 치수·확정 좌표·사용 가능한 사진이 모두 미확보다. `현장촬영-계획안.md`의 GPX 참고점은 시설 좌표가 아니다. 따라서 사진 기반 치수 추정을 했다고 주장하지 않는다. 새 모델을 기본 장면에 임의 배치하지 않았다. 산개발의 구간별 노면 변경과 충돌하지 않도록 route/main/load-landscape는 수정하지 않았다.

## 산개발 접지 연결 계약

로컬 +Z가 오르는 방향, +Y 위, 1단위=1m. 생성된 계단/데크의 `group.userData.contacts`에는 각 디딤판의 XZ 경계·상면 y·발소리 재질이 있다. `facilityContact(contacts,x,z)`는 범위 밖 null, 내부 상면을 반환한다. Z 경계는 [시작,끝)이다. 데크는 deck, 목재 계단은 deck_stairs다.

연결 시 월드 XZ를 시설 로컬 좌표로 변환하고 반환 상면을 월드 높이로 되돌려야 한다. 회전은 Y축만 허용하고 비균등 확대·경사 회전을 금지한다. 시각 LOD와 무관하게 근접 충돌 데이터는 유지한다. 기존 지형보다 높은 판만 무조건 선택하면 난간 밖에서도 뜰 수 있으므로 실제 시설 경계와 접근 구간을 함께 검사한다.

현재 `landscape.surfaceHeight`, 카메라 충돌, movement·1인칭 눈높이는 미연결이다. 보행 중심 높이·양발 IK·발소리·계단 cadence·카메라 충돌을 같은 접지 계약으로 연결해야 한다. 기존 코스의 경사와 .18/.30 계단 경사가 다르므로 단수를 경로 길이만으로 채우지 말고 실측 랜딩·고도에 맞춰야 한다.

## LOD·성능

재질별 병합, 시설당 최대 5메시·5재질, 외부 텍스처 0, 그림자 투사 없음. `createFacilityLod`는 40m에서 단순 모델로 전환하며 10% 히스테리시스를 적용한다. 일반 시설은 120m에서 숨기고 응진전·레이더·송신탑·문은 단순 형태를 유지한다. 절두체 컬링은 three.js 메시 기본값이다. 실제 배치 시 32m 청크로 나누고 동일 재질을 공유해야 하며 현재 생성 함수는 시설 간 재질 캐시를 제공하지 않는다.

기본 설정 모델별 1600삼각형 이하·5재질 이하 회귀 검사를 작성했으나 **실행하지 않았다**. 최대 64단 설정은 기본 예산 검사 대상이 아니므로 청크 분할이 필요하다. 최종 예산 문서의 120/400m 상세 LOD는 아직 없다. 전체 장면 250만/150만, fps 목표 준수 여부는 미측정이다.

## 검증·캡처

스크립트 실행 금지 지시로 테스트·서버·모델 렌더링을 실행하지 않았다. 사진이 없어 동일 구도 비교 및 report_image를 수행하지 못했다. 빈 브라우저나 무관한 기존 화면을 결과로 첨부하지 않았다. 실제 사진 확보 후 촬영 위치·시선 방위·높이·FOV를 기록하고, 응진전/레이더 원경 1장과 계단 근경 1장을 실제 사진과 나란히 제작해 report_image로 등록한다.
