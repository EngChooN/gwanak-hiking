# 렌더링 최적화 1단계 — 커밋 전 보고

## 실측 후속 우선 반영 — 산기획 지시

기준: `artifacts/performance-after/results.json`, 성능 문서의 2026-11-03 실측. 높음 약 58fps, 균형 CPU4배 18.6fps·50ms 초과 약 43%, 구간 평균 삼각형 최대 375만. 아래 변경은 이 결과 이후 코드 반영이며 after2 검증은 대기다.

1. `src/static-scene.js`의 `freezeStatic`: 배치 후 `updateMatrix()`를 한 번 수행하고 로컬·월드 자동 행렬 갱신을 모두 끈다. 설치된 three.js의 부모 force 전파를 확인했으며 로컬 자동 갱신만 끄는 것으로는 월드 곱셈이 남아 월드 플래그도 고정했다. 지형 바닥·등산로·청크·숲 LOD/InstancedMesh·바위·풀·원경 지형·도시·수면에 연결했다. 동적 등산객·카메라·태양은 제외한다. 새 스트리밍 청크도 부착 후 고정한다.
2. TerrainStream에서 화질을 로더로 전달한다. 식생 LOD1/2 전환 상한은 높음 10/40m·균형 6/20m·낮음 4/12m, 근경/하층식생은 8/32·5/16·3/10m, 바위는 24/64·12/32·6/16m다. 자산이 더 가까운 전환을 요구하면 원래 거리를 유지한다. 신규 십자판120m·임포스터400m 계약은 유지한다. 현재 식생은 원래부터 castShadow=false였으며 모든 LOD에 이를 명시적으로 유지했다. 따라서 나무 그림자 제외 자체의 추가 성능 이득을 주장하지 않는다.
3. 초기 도시·자연 자산 로딩을 기다린 후 모든 LOD를 순회하는 `renderer.compileAsync(scene,camera)`를 기다린다. 그 뒤 SSAO·출력·그림자 패스 준비 프레임을 그린다. 화질 또는 AO/그림자 사용 여부 전환 시에도 같은 준비를 직렬화하고 보행 렌더 재개 전 기다린다. DPR/창 크기 변경만으로는 다시 컴파일하지 않는다. `compileCount`, `compiling`, `compileError`로 확인할 수 있다.
4. 기존 자동 DPR·그림자 범위·SSAO 조절과 청크 컬링·임포스터 인터페이스를 유지했다. 정적 행렬 보존·부모 강제 갱신 시 재계산 방지·재배치 후 다시 고정·실제 카메라 거리에서 화질별 LOD 전환 테스트를 추가했다.
5. 측정기에 프레임 최대 삼각형을 추가했다. benchmark 통과 조건에 실제 렌더 프레임 fps/지연 비율, 프레임 최대 삼각형 예산, 컴파일 오류 유무를 추가했다. 미달인 경우 스크립트 종료코드도 1로 반환한다. 기존 rAF 수치·시나리오·20초 측정 시간은 유지한다.

### 검증과 가정

`git diff --check` 통과. 코드 검토만 수행했으며 after2 측정·새 npm test·빌드·화질 캡처는 미완료다. 이전 산기획 테스트 40/40은 이번 수정 후 통과를 뜻하지 않는다. 기존 after 원자료는 덮어쓰지 않았다. 커밋·push·배포는 하지 않았다.

가정: 정적 객체의 상위 좌표계는 현재처럼 고정이다. 나중에 원점 이동/재부모화를 도입하면 해당 하위 트리의 freezeStatic을 다시 호출해야 한다. LOD 숫자는 실측 전 후보이며 외형 전환과 예산 충족은 after2로 확인해야 한다. SSAO/그림자 준비 프레임은 현재 위치를 기준으로 하므로 모든 드라이버·이후 신규 재질의 지연 컴파일 제거를 보장하지 않는다. 초기 로딩 시간이 늘어날 수 있다.

### 대표 확인 필요 — after2 실행 명령

이번 요청은 재측정 명령을 지정했으나 마지막 자율 진행 지시에 스크립트 실행을 위험 작업으로 금지했다. 제한을 적용해 서버·테스트·측정 스크립트는 실행하지 않고 아래에 남긴다. 이번 턴에 이 명령을 실행했다가 거부된 것은 아니다.

```sh
cd /Users/joonyoung/gwanak-hiking
export PATH="$HOME/.nvm/versions/node/v24.22.2/bin:$PATH"
npm test
npm run build
npm run dev -- --port 5176
# 위 서버 실행 중 별도 터미널에서 같은 PATH 설정 후
LABEL=after2 HEADED=1 node scripts/benchmark-performance.mjs
BEFORE_LABEL=after AFTER_LABEL=after2 node scripts/compare-performance.mjs
```

after2 결과를 성능 문서 표에 반영하고 균형 CPU4배 30fps·50ms 초과1% 이하, 높음 최대 삼각형250만 이하를 확인한다. 미달이면 프로파일과 장면별 삼각형을 보고 조정·재측정한다. 새 화면은 `artifacts/performance-after2/high-1x-third-w.png`, `balanced-4x-third-w.png` 중 1~2장을 검수 후 등록한다. 실행하지 않은 기존 화면으로 새 결과를 대신하지 않는다.

## 반영

- `src/adaptive-quality.js`: 수동 화질을 상한으로 하는 단계별 DPR·그림자 거리·SSAO 조절. 높음 18ms/균형 33ms 목표, 하향과 복귀 히스테리시스, 숨긴 탭 제외.
- `src/main.js`, `src/rendering.js`: 매 프레임 표본 연결, 실제 설정 진단 값, 카메라 주변 30~60m 폭의 실시간 그림자. 수동 버튼의 ‘고정’은 선택 상한 고정을 의미하며 실제 비용은 자동 조절된다.
- `src/chunk-culling.js`, 지형 로더: 모든 LOD 및 인스턴스 변환을 포함하는 정적 AABB 절두체 컬링. 풀 130m·작은 바위/하층식생/근경 디테일 180m 경계 거리 컬링. 충돌 대상 목록은 유지한다.
- `src/realistic-hiker.js`: 스킨 메시만 `frustumCulled=false` 유지. 정적 부착 메시에는 기본 컬링 복구.
- `src/realistic-models.js`: 선택 자산 계약 `crossboard:{url}` 120m, `impostor:{url}` 400m. 둘 다 기존 청크 placements와 Y-up·밑동 0·스케일 계약을 공유하는 인스턴싱 GLB이며, URL은 기존 nature 기준 상대 경로다. 모든 방향을 포함한 십자판 또는 고정 다면판을 받는다. 카메라 회전형 다각도 아틀라스는 별도 셰이더 계약이 필요하다. 자산이 없으면 기존 LOD를 유지하고 가짜 사진판은 만들지 않는다.
- `tests/adaptive-quality.test.mjs`: 상한·단계 순서·복귀 지연·숨긴 탭·인스턴스 월드 경계·화면 뒤/거리 컬링 검사를 추가했다.

## 검증

`git diff --check` 통과. npm test, 빌드, benchmark, 전후 화면 캡처는 미실행이다. 성능 문서에 평균fps·50ms 초과 비율·드로우콜·삼각형 전후 표를 추가했으며 전부 미측정으로 표시했다. 수치 개선·시각적 합격·완료 기준 충족을 주장하지 않는다. 화면을 실행하지 못했으므로 기존 이미지를 새 검증 자료로 첨부하지 않는다.

IK는 앞선 구현을 보존했으며 실행 검증·동일 위치 전후 자세 비교·스틱 연결은 계속 미완료다. 이번 단계는 IK 완료로 처리하지 않고 코드 작업만 진행했다. 기존 작업 변경이 섞여 있으므로 전체 스테이징과 커밋은 보류한다.

## 가정

- 산풍경 신규 십자판/임포스터 및 스틱 포함 GLB 수령은 확인하지 못했다.
- 목표 높음 18ms에서는 60Hz VSync에서도 복귀할 수 있도록 여유 기준을 목표의 94%로 잡았다. 저주사율 화면에서는 DPR 하향이 효과 없을 수 있어 실제 기기 검수가 필요하다.
- 정적 식생 경계는 생성 후 고정이다. 자산 변형·배치 변경 시 경계를 다시 계산해야 한다.
- 기존 단일 그림자 맵으로 요청 범위를 구현한다. 갱신 간격 최적화·캐스케이드는 화질 비교 후 판단한다.

## 대표 확인 필요

자율 진행 지시의 스크립트 실행 금지 때문에 다음 명령을 실행하지 않았다. 파일 읽기 명령도 한 번 `rejected by user`가 반환됐다. 커밋 전 보고 상태이며 push는 하지 않는다.

```sh
cd /Users/joonyoung/gwanak-hiking
nvm use 24
npm test
npm run build
npm run dev -- --port 5176
# 동일 기기·Chrome·뷰포트에서 이번 단계 직전 소스 서버를 먼저 측정
LABEL=render-stage1-before HEADED=1 node scripts/benchmark-performance.mjs
# 서버를 현재 소스로 바꾼 후 동일 조건 측정
LABEL=render-stage1-after HEADED=1 node scripts/benchmark-performance.mjs
BEFORE_LABEL=render-stage1-before AFTER_LABEL=render-stage1-after node scripts/compare-performance.mjs
```

두 결과의 `results.json`에서 각 run의 frame.fps, frame.over50ms/frame.frames 비율, performance의 드로우콜·삼각형 집계를 성능 문서에 옮긴다. compare-performance에 라벨 선택과 위 집계를 추가했으며 실행 검증은 대기다. benchmark가 저장하는 W 화면 중 높음·균형 1~2장을 검수 후 report_image로 등록한다. IK 캡처는 이전 보고의 동일 s·heading·stepPhase 고정 조건으로 별도 검수한다. 기준본 보존은 스크립트 실행 제한 때문에 수행하지 않았으며 기존 임시 기준본과 혼동하지 않는다.

커밋은 테스트·실측·화질 검수 및 기존 작업과 변경 범위 분리 검토 후 별도 보고를 거친다. 삭제·배포·외부 전송·push는 수행하지 않았다.
