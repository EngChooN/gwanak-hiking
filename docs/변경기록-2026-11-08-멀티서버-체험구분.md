# 변경 기록 — 멀티 서버·클라이언트 체험 구분 (2026-11-08, 산개발)

메타버스 통합 3/3단계. 함께 걷기 서버 하나를 온라인 등산·온라인 흡연장이 같이 쓰도록 방을 체험별로 나눴습니다. 커밋·push·배포는 하지 않았습니다.

## 무엇이 문제였나
- 서버의 방 키가 방 이름뿐이었습니다. 흡연장이 같은 서버를 쓰면 `옥상` 같은 이름이 등산 방과 섞일 수 있었습니다.

## 바꾼 것
- `src/multi-protocol.js`: `EXPERIENCES`(`hiking`·`smoking`), `DEFAULT_EXPERIENCE`, `parseExperience`(비면 `hiking`, 목록 밖 `null`), 체험별 받는 메시지 종류 `EXPERIENCE_MESSAGES`, 예약 `RESERVED_MESSAGES`, `messageAllowed`. 서버 이미지 파일 목록이 바뀌지 않게 이 파일 안에 두었습니다.
- `server/rooms.mjs`: 방 키 `체험:방이름`(`roomKey`). `join({experience,…})`, 목록 밖이면 `{ok:false,reason:'experience'}`. -2 규칙·재배정은 같은 체험 안에서. 체험에 열리지 않은 메시지는 버림(`stats.wrongExperience`). 신고는 같은 체험 사람만, resume 토큰은 같은 체험에서만. 신고 기록 `room`은 방 키. `info().rooms`에 `key`·`experience`.
- `server/multi-server.mjs`: hello의 `exp`를 넘김. 거절이면 `{t:'reject',reason:'experience'}` 뒤 close 1008, 로그 `reject-experience`. `/health`에 `experiences`(체험별 방·접속 수).
- `src/multi-transport.js`: `createWebSocketTransport(url,{experience='hiking',…})`가 hello에 `exp`를 실음. `reject`를 받으면 다시 시도하지 않고 offline.
- `src/multi-client.js`: 등산은 `experience:'hiking'`을 명시.
- 맨 위 `.dockerignore` 추가(`server/Dockerfile.dockerignore`와 같은 내용). Render(`dockerContext: .`)·Fly가 맨 위 것을 읽을 때도 에셋을 올리지 않게.
- 문서: `docs/멀티-서버-운영안내.md` §3-1(체험 구분·흡연장 실시간 설계), 게임 주소 예시를 `/hiking/`으로, 도커 빌드 경로 확인. `AGENTS.md` §6·§7·§8·§10.

## 확인
- `npm test` 668개 모두 통과(새 시험 7개: 단위 5 — 같은 이름 다른 체험 분리, 체험별 -2, 하위 호환·거절, 체험별 메시지 종류, 신고·resume이 체험을 넘지 않음 / 서버 통합 2 — 실제 서버에서 옛 클라이언트·등산·흡연장·거절·`/health`, 전송 계층이 흡연장 방으로 붙음). 기존 hello 시험은 `exp:'hiking'`이 실리도록 고침.
- 도커: 이 맥에 docker가 없어 이미지 빌드는 못 했습니다. 이미지에 들어갈 5개 파일만 빈 폴더에 복사해 서버가 뜨고 `/health`가 체험별 수를 내는 것을 확인했습니다. 통합으로 바뀐 복사 경로는 없습니다.

## 정한 것(가정)
- 목록 밖 체험 id는 등산으로 보내지 않고 거절합니다(빈 값만 등산).
- 끝 번호를 떼는 기존 규칙은 그대로라 `관악산-1`은 `hiking:관악산`입니다.
- 전체 접속·같은 IP 상한, 신고 숨김(IP 해시)은 서버 전체 기준으로 둡니다.
