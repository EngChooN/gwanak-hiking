# 이동 방향에 따른 전신 회전

2026-11-03 · 산개발 · /Users/pc-2311001/gwanak-hiking

## 원인과 수정

기존 main.js는 실제 이동과 무관하게 루트를 경로 heading으로 돌렸다. 좌우 명령은 Sidestep 이름으로 넘겼지만 로더는 이를 Walk로 재생해 정면을 보며 옆으로 미끄러지는 모습이 됐다. 기존 2.5rad/s 회전 제한도 90도 전환에 최소 0.63초가 걸렸다.

- `src/main.js`: advance 전후의 월드 X/Z 변위로 몸 방향을 정한다. 좌우·대각선·후진·자동 중앙 복귀도 같은 원칙을 따른다. 이동이 막히거나 멈추면 회전 명령을 보내지 않아 마지막 방향을 유지한다. Sidestep 분기를 제거했다.
- `src/hiker-facing.js`: 루트 전방 -Z 기준 방향 계산과 최단각 보간. 지수 보간 시간상수 0.05초로 0.15초에 약 95%, 0.2초에 약 98% 회전한다. 정반대 방향도 같은 속도로 몸 전체가 돌아선다. 머리·몸통·다리 모두 같은 루트 회전에 포함된다.
- `src/realistic-hiker.js`: 위 보간을 적용한다. 빠르게 도는 중에는 이전 방향의 발·스틱 앵커를 풀어 다리가 꼬이지 않게 다시 접지한다. 기존 IK는 회전한 몸의 전방을 사용한다.
- 오르기/일반 걷기는 실제 이동 방향의 상승 경사로 선택한다. 하산하며 상행 경로의 오르기 동작을 재생하지 않는다. 길 위 경사는 계단의 불연속 높이 대신 연속 경로 고도로 계산한다.
- 카메라의 경로 heading + look.yaw 계산은 유지했다. 몸 회전값을 카메라 회전에 전달하지 않는다.

별도 CONTEXT·SPEC 파일은 발견되지 않아 README, 1:1 스케일 기획서, 등산객 인계, 휴식·시점 통합 변경 기록을 확인했다. 로딩 화면·광장 출발점 파일은 수정하지 않았으며 main.js도 프레임의 방향·이동 경사 연결 부분만 수정했다. 다른 담당의 기존 수정은 보존했다.

## 검증

- `npm test`: 171개 통과. 새 회귀 테스트는 8방향 실제 변위, 30/60/120Hz 회전 시간, ±π 경계 최단각, 정지·충돌 방향 유지 확인.
- `npm run build`: 통과. 기존 대형 번들 경고 유지.
- 실제 Chrome 1440×900·균형 화질에서 **16장면 통과**, 페이지 오류 0건. 완만한 길 8방향, 약 17.4° 계단 경사와 코스 약 4802m 암릉의 앞·뒤·좌·우를 각각 실제 키보드로 이동했다. 후진도 몸이 돌아서 전진 보행한다.
- 각 방향 전환 후 실제 변위와 몸 루트 방향 차이는 0.001° 미만, 같은 경로 구간에서 몸 방향 변경 전후 카메라의 수평 방위 변화는 0°. 모든 키를 뗀 후 0.3초 동안 마지막 방향 유지.
- 발목→발끝의 3D 축을 몸 전방·옆 방향과 대조해 발 들림과 발의 좌우 뒤틀림을 구분했다. 발끝을 들어 수평 투영이 거의 0이 되는 위상은 수평 각도만으로 판정하지 않았다. 기존 IK가 반환한 표본 발바닥의 최대 관통량 0.001mm 미만, 접지 표시 발의 최대 지면 간격 7.73mm. 전체 메시·코스 전 구간 보장은 아닌 장면별 표본 검증이다.
- 계단 상행은 Climb, 하행·측면은 Walk 선택을 확인했다. 원시 좌표·뼈 방향·접지 값: `artifacts/facing/results.json`.
- 좌우 이동 중 원본 화면: `artifacts/facing/left.png`, `right.png`. 머리·몸통·다리가 각각 왼쪽/오른쪽으로 함께 돌아선 것을 화면으로 확인했다.
- 재현: Vite 5178 포트 실행 후 `node scripts/verify-facing.mjs`. 전용 임시 브라우저 프로필과 저장 상태를 쓰며 검증 탭에서만 Vite 자동 새로고침을 차단한다. 움직임·자세는 테스트용 강제 애니메이션으로 덮어쓰지 않는다.
