## 1. 아이폰에서 5~10초 뒤 다시 로딩 화면이 뜸

### 원인
출발(준비 완료) 직후 뒤에서 서울 도심 건물 JSON 32개(약 70MB, 15만 3,396동)를 받으면서 **2km 칸 148개 전부의 건물 지오메트리(상세 모양 + 상자 두 벌)를 한꺼번에 만들었다.**
- 대부분 칸은 실제로는 원경 실루엣으로만 그려지는데도(입구광장 기준 상세·상자로 그리는 칸 0개) 지오메트리 버퍼 약 630MB를 메모리에 들고 있었다.
- 같은 단계에서 실루엣 계산이 JS 배열·임시 객체를 대량으로 만들어 JS 힙이 한때 약 950MB까지 올랐다.
- 출발 2~16초 사이에 이 둘이 겹쳐 iOS 사파리 탭 메모리 상한(약 1~1.5GB, 기기별 상이)을 넘는 것으로 판단된다. 넘으면 사파리가 탭을 강제로 새로 열어 로딩 화면이 다시 뜬다. 대표가 말한 "5~10초"와 시점이 맞는다.
- 덧붙여 숲 바닥 풀 인스턴스(코스 전체 약 200만 포기분 행렬·색) 약 156MB도 휴대폰 화질에서 그리지 않는 몫까지 들고 있었다.

dist 크기(131MB)는 원인이 아니다. 받는 파일 중 실사 텍스처 등은 카툰에서 내려받지 않는다.

### 바꾼 것
- `src/device-profile.js`(새 파일): 휴대폰 상한 한곳 정리. 도시 칸 동시 보유 8개·상세 모양 생략·숲 풀 25%·도시 JSON 사이 250ms 쉼·DPR 하한 1. PC는 기존과 같다(칸 40개·상세 포함).
- `src/city-grid.js`
  - 칸 지오메트리 **지연 생성·해제**: `finalize()`는 실루엣만 만든다. `update()`가 그릴 거리 안 가까운 칸만 뒤에서(6ms씩 끊어) 만들고, 상한을 넘거나 1.5배 거리 밖으로 멀어지면 버린다. 아직 없는 칸은 실루엣으로 그린다.
  - 원경 실루엣·대표 상자·도로를 늘어나는 typed array에 바로 쓴다(JS 배열 push·건물마다 BoxGeometry 생성 제거). 결과 값은 같다(기존 테스트 통과).
- `forest-layers.js`: 휴대폰은 숲 바닥 풀 포기를 교차 배치 앞 25%만 만들고, 그리는 수는 같은 비율로 맞춘다.
- `src/main.js`
  - 휴대폰 '자동' 화질 기본값 균형 → **낮음**(DPR 1.15 → 1.0, 풀·덤불 거리 축소). 설정 탭에서 올릴 수 있다.
  - WebGL 컨텍스트 손실: 그리기를 멈추고 `webglcontextrestored`를 기다려 다시 잇는다. 6초 안에 복구되지 않으면 저장 지점에서 한 번 새로 연다(1분 안 반복이면 안내만).
  - `hiking.memory()` 진단 함수 추가.

## 2. 1인칭 걸을 때 멀미

1인칭 카메라 상하 흔들림(걸음 위상 sin, ±2.5cm)을 뺐다. 카메라 좌우 롤은 원래 없었다(확인). 걸음 리듬은 발소리만. 3인칭은 그대로.
확인: 입구광장 평지 1인칭 W 걷기 2초(2m) 동안 카메라 높이 변화 0.0000m.

## 3. 모바일 시점 전환 버튼

- 시점 전환(#view)을 배낭 시트에서 꺼내 **진행 카드 옆 칩**으로 늘 보이게 했다(가로·PC는 카드 오른쪽, 세로는 카드 아래). 글자는 "1인칭 보기 / 3인칭 보기".
- 단축키만 있던 기능에 버튼 추가
  - 서울 이름표(L): 배낭 시트 "서울 이름표"
  - 쌍안경 배율(휠·핀치·+/−): 쌍안경 화면 아래 −/＋ 버튼
- 나머지 단축키(M·J·R·F·C·T·B·P·Z·N·H·V·/·Shift·Space·Y·1~3·ESC)는 이미 버튼이 있다. X(인사)·G·K는 함께 걷기 패널 버튼. PC에서 키보드 없이 걷기는 자동 걷기 도장으로 한다(조이스틱은 터치 전용, 기존 설계).
- 확인(`scripts/verify-mobile-buttons.mjs`, WebKit 아이폰 13, 노치·홈 막대 안전 영역 흉내): 세로 390×844·가로 844×390 모두 책갈피 탭 5개·시점 칩·도장·칩 3개가 안전 영역 안에 보이고, 중심을 눌렀을 때 그 버튼이 잡히며, 서로 겹치지 않는다. 시점 칩 탭으로 1인칭↔3인칭 전환 확인. 구간 이동(설정 탭 안)은 8곳 모두 열림. 화면: `artifacts/mobile-buttons/`.

지킨 조건: 일시정지 버튼 없음, 조이스틱은 손가락 댄 자리에 생성, 구간 이동 버튼 유지.

## 확인하지 못한 것
- **실제 아이폰에서 확인하지 못했다.** 측정은 맥의 Playwright WebKit·Chromium 에뮬레이션이다. iOS 탭 메모리 상한과 GPU 프로세스 메모리는 에뮬레이션으로 잴 수 없다. 배포 뒤 대표 아이폰에서 1~2분 걸어 보는 확인이 필요하다.
- 컨텍스트 손실→복구 경로는 코드로만 넣었고 실제 손실을 일으켜 시험하지는 않았다.
- 실제 노치 위치(env(safe-area-inset-*))는 헤드리스에서 0이라 아이폰 13 값을 변수로 넣어 흉내 냈다.
