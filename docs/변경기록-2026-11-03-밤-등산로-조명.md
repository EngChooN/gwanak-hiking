헤드랜턴: 1인칭은 카메라 방향(수평 위로는 안 올림), 3인칭은 등산객 정면에서 앞길 15m까지 비춘다. 3인칭에서는 이마 램프(검은 하우징 + 발광 점 + 글로우)가 보이고, 모자 종류별 위치(맨머리 / 두건 / 캡 / 파나마)를 달리해 모자·두건과 겹치지 않게 했다(`HEADLAMP_MOUNT`).

## 성능 설계 (실제 광원 수 고정)
- 이 기능이 추가하는 실제 광원은 **항상 5개**: 가로등 풀 PointLight 4개(가까운 가로등에 붙어 다님) + 내 헤드랜턴 SpotLight 1개. 기존 태양·반구광 2개와 합쳐 장면 전체 7개. 켜고 끌 때는 `intensity`만 바꾼다(광원 수 변화 → 전 재질 재컴파일 방지). 처음부터 장면에 넣고 `lighting.prepare()`가 함께 컴파일한다.
- **그림자 광원 0개**: 헤드랜턴·가로등 모두 `castShadow=false`. (설계 상한 2~4개 중 0 사용. 가로등 웅덩이는 가짜 빛 데칼, 램프는 발광 재질.)
- 가로등 45개는 InstancedMesh 4번(기둥·전구·바닥 데칼·후광 Points)로 그린다.
- 새 재질은 MeshBasicMaterial을 쓰지 않는다(`rendering.js`가 MeshBasic을 밤 배율로 다시 칠하기 때문). 데칼·글로우는 가산 혼합 ShaderMaterial, 전구는 MeshStandard 발광.

## 멀티플레이 대비 조명 규칙 (네트워크 플레이어를 붙일 때 그대로 적용)
1. **실제 광원은 내 헤드랜턴 SpotLight 1개뿐.** 다른 플레이어·NPC용 광원은 절대 만들지 않는다. 사람 수가 늘어도 `scene`의 라이트 수와 셰이더 컴파일 수는 그대로여야 한다.
2. 다른 사람은 `hiking.setOthers([{x,y,z,heading,color?,lamp?}])`(= `night.setOthers`)에 위치만 넘긴다. 램프를 끄려면 `lamp:false`. 이 목록으로 아래가 자동으로 그려진다.
3. 거리 단계(`OTHERS`, `night-lighting-config.js`): **45m 이내 = 앞길 빛 데칼(4.6m 앞 타원, 2.4×7m) + 글로우**, **45~110m = 글로우만**, **110m 밖 = 그리지 않음**. 한 번에 **가까운 순 32개**까지만 그린다(나머지는 `dropped`로 센다).
4. 데칼은 InstancedMesh 1회, 글로우는 Points 1회로 묶는다. 사람 수가 늘어도 드로우 객체 수는 같다. 몸(자리표시 캡슐)도 InstancedMesh 1회, 가까운 100개까지(진짜 아바타 모델을 쓰면 가까운 몇 명만 모델로 바꾸고 나머지는 이 자리표시를 쓴다).
5. 그림자는 모두 끈다(내 랜턴 포함). 다른 사람 때문에 `castShadow`를 켜지 않는다.
6. 새 조명 재질을 추가할 때는 MeshBasicMaterial을 피한다(밤 배율이 곱해져 꺼짐).
7. 점검: `hiking.night()`가 `realLights`(장면 라이트 수=7), `othersDrawn`(`bodies/decals/glows/dropped`)을 돌려준다. 테스트 `tests/night-lighting.test.mjs`의 "다인원" 항목이 0→1→50→100→300명에서 라이트 수·재질 수·드로우 객체 수가 불변임을 확인한다.

부하 시험: URL에 `?crowd=50`/`?crowd=100`(최대 300)을 붙이면 능선 길을 오가는 가짜 등산객이 생긴다(`scripts/capture-night-lighting.mjs`가 측정).

## 한계·후속
- 나무·원경 도시 등 MeshBasicMaterial은 조명을 받지 않아 헤드랜턴이 숲 줄기를 밝히지 못한다(지형·바위·길만 밝아짐). 숲까지 비추려면 해당 재질 교체가 필요하고 비용이 크다.
- 헤드랜턴 빔은 가시 광선(볼류메트릭)이 아니다. 먼지·안개 속 빛줄기는 없다.
- 램프 위치는 설계 추정이다. 실제 관악산 가로등 위치·간격은 현장 확인 전이다.
- 연주암 보안등은 참고 거리(4,545m) 기준 추정 위치다.
