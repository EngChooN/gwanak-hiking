# 릴스 풍경 장면 — 위치·시선·시간·날씨 (산풍경, 2026-11-11)

상위 업무: 인스타 릴스 온라인 등산 소개 영상 · 2/4단계. 산디자인 콘티(`docs/릴스-콘티.md`)의 풍경 장면 값을 정하고, 세로 화면으로 실제로 찍어 확인했다.

- 장면 값 원본: **`scripts/reels-scenes.json`** (촬영 스크립트가 이 파일을 그대로 읽으면 된다)
- 확인 촬영 스크립트: **`scripts/capture-reels-shots.mjs`** (개발 서버 `npx vite --host 127.0.0.1 --port 5310`을 켠 뒤 `node scripts/capture-reels-shots.mjs [장면,...]`)
- 스크린샷: **`artifacts/reels/shots/<장면>.png`**(휴대폰 HUD 보임), **`<장면>-clean.png`**(HUD 숨김, 풍경만), 실제로 맞춰진 값은 `results.json`
- 7장면 모두 콘솔 오류 0건, 목표 방위·위아래 각과 실제 카메라 값이 0.1° 안에서 같았다(`results.json`의 `wantBearing`·`cameraBearing`).

## 1. 공통 촬영 설정

| 항목 | 값 |
|---|---|
| 화면 | Playwright `viewport 360×640`, `deviceScaleFactor 3`(= 1080×1920), `isMobile:true`, `hasTouch:true`, 아이폰 UA. 휴대폰 HUD가 나오고, 세로라 시야각 78°가 된다. |
| 화질 | 주소에 `quality=high`. 휴대폰 기본은 '낮음'이라 빼면 렌더 배율이 낮아 흐려진다. |
| 주소 | `/hiking/?time=…&weather=…&season=…&quality=high` (+ `start=summit`·`start=plaza`). 자동화 브라우저는 산 고르기·서버 고르기가 저절로 빠진다. 사람이 손으로 찍을 때는 `&pick=off&serverpick=off`를 더 붙인다. |
| localStorage(페이지 열기 전) | `gwanak-sound-enabled=false`(확인 촬영만. 영상 녹화는 소리를 켠다), `gwanak-stick-used=1`(조이스틱 안내 "손가락 댄 자리에 생겨요"를 끈다). 코스 위 장면은 아래 §2의 저장값을 넣는다. |
| 기다리기 | `hiking.started && hiking.landscape().natureReady && !hiking.rendering().compiling` → 1.5초 → 열린 `dialog` 닫기 → 시선 맞추기 → 3.5초 → `scripts/lib/chunk-wait.mjs`의 `waitChunks(page)` → 찍기 |
| 풍경만 찍기 | `window.dispatchEvent(new CustomEvent('hiking:hud-toggle'))`(화면의 HUD 숨기기와 같음) 뒤 CSS `.hud-restore,.hud-hint,#joystick,#source-line,.source-line,#section-jump{display:none!important}`. HUD 숨기기만 하면 '다시 보기·화면 보이기' 단추, 조이스틱 자리, 출처 줄이 남는다. |
| 계절 | 7장면 모두 `season=autumn`(가을 단풍). 촬영 시기(11월)와 맞고 색이 가장 화려하다. 계절 컷(콘티 32–35초)은 같은 자리에서 `hiking.setSeason('spring'|'summer'|'autumn'|'winter',{instant:true})`로 바꾸면 다시 로딩하지 않는다. |
| 날씨 | 모두 `weather=clear`. 실제 날씨를 받지 않고 고정된다. |

### 1-1. 시간은 `HH:MM`만 된다 — 콘티 값 바로잡기

- `?time=`은 `17:10`이나 `1710` 같은 **서울 시각만** 받는다(`src/daytime.js` `parseClock`). 콘티 장면 1의 `time=dusk`는 **먹지 않는 값**이다. 이 값을 넣으면 '지금 시각'으로 찍힌다. 훅은 `time=17:10`으로 바꾼다.
- 해 위치는 **촬영하는 날짜**의 그 시각으로 계산된다. 아래 시각은 11월 11일 기준이다(서울 일몰 약 17:25). 12월 이후에 다시 찍으면 노을 시각이 몇 분 당겨진다. 그때는 자유 설정 이벤트 `window.dispatchEvent(new CustomEvent('hiking:free-settings',{detail:{time:'dusk'}}))`를 쓴다. 이 이벤트는 날짜와 상관없이 해 높이 3°가 되는 시각을 고른다. 다만 장면 ①에서 찍은 노을 색과 똑같지는 않을 수 있으니, 다시 찍을 때는 `results.json`과 캡처를 비교한다.

## 2. 자리 옮기기 — 세 가지 방법

1. **주소만 쓰기** (입구·정상): `start=plaza`(입구 광장 출발, 일주문을 바라봄), `start=summit`(정상석 3.5m 앞, 정상석을 바라봄).
2. **이어하기 저장값 넣기** (코스 위 아무 곳, 촬영 스크립트용 정답): 페이지를 열기 전에 localStorage `gwanak-hiking:v1`에 아래 값을 넣는다. `s`는 코스 3D 거리(m)이고 전체는 5,067m다.
   ```js
   import {initialState,SAVE_KEY} from '../src/movement.js';   // SAVE_KEY = 'gwanak-hiking:v1'
   const seed={...initialState({start:'demo'}),zone:'route',s:1500,lateral:0,view:'third'};
   await context.addInitScript(({seed,key})=>localStorage.setItem(key,JSON.stringify(seed)),{seed,key:SAVE_KEY});
   ```
3. **화면에서 옮기기** (손으로 찍을 때): 설정 탭 → '개발용' 칸 `🧭 구간 이동` → 목록에서 고르기. 콘솔에서는 `hiking.jumpTo(id)`. 목록은 아래 지점뿐이라 원하는 자리까지는 걸어가야 한다(**R** 자동 걷기 또는 **W**).
   | id | 이름 | s(m) |
   |---|---|---|
   | `plaza` | 입구 광장 | (광장) |
   | `gate` | 일주문 | 0 근처 |
   | `plaza-1` | 제1광장 | 1,075 |
   | `acacia` | 아카시아동산 | 1,621 |
   | `shelter-4` | 제4쉼터 | 2,634 |
   | `yeonju-spring` | 연주샘 | 3,248 |
   | `pass-3` | 제3깔딱고개 | 4,664 |
   | `summit` | 정상 구역 | (정상석 앞) |

참고로 코스 노면 구간(m)은 이렇다: 포장 0–753 · 흙 753–1,998 · 바위 1,998–2,612 · 흙 2,612–2,876 · 바위 2,876–3,073 · 돌계단 3,073–3,271 · 흙 3,271–3,435 · 바위 3,435–3,709 · **나무계단 3,709–4,484** · 바위 4,484–4,527 · 돌계단 4,552–4,691 · 바위 4,691–4,795 · **능선 4,795–5,001** · 바위 5,001–5,067.

## 3. 시선 맞추기

- 방위는 **북 0°·동 90°**(시계 방향)이다. `hiking.orientation().cameraHeading`(라디안)은 **−방위**와 같다. 위아래는 `hiking.orientation().pitch`(라디안, +는 위)다.
- 맞추는 법: 화면 오른쪽(x 72%, y 45% — 조이스틱이 안 생기는 곳)을 마우스로 끈다. **가로 1px = 0.004rad**이고 오른쪽으로 끌면 오른쪽으로 돈다. **세로 1px = 0.003rad**이고 아래로 끌면 위를 본다. 한 번 끌고 `orientation()`을 다시 읽어 남은 차이를 한 번 더 끈다. 두 번이면 0.1° 안으로 맞는다(`capture-reels-shots.mjs`의 `drag` 참고).
- **`?bearing=` 주소 옵션은 쓰지 않는다.** 카메라 방위가 그 값에 고정되어 드래그로 훑는 장면(훅의 좌→우 패닝)을 찍을 수 없다.
- 1·3인칭: 저장값의 `view:'first'|'third'`, 또는 시점 칩 탭이나 **V** 키. `start=` 출발은 1인칭으로 시작한다.
- 3인칭에서 위아래 각(pitch)은 숫자는 바뀌어도 화면 변화가 작다. 카메라가 동동이 뒤에서 궤도를 돌기 때문이다. 3인칭 구도는 주로 방위로 잡는다.

모두 **세로 1080×1920**으로 찍어 확인했다. "지평선"은 1920 높이 기준 y값이다. 자막 안전 영역은 콘티 §5 기준 x 64~912, y 250~1500이다.

## 5. 주의할 점

- **출처 표기:** 휴대폰 HUD 아래에 `날씨 정보: Open-Meteo.com (CC BY 4.0) · © OpenStreetMap contributors · ODbL` 줄이 있다. 인스타 캡션 영역(아래 20%)에 가려지니, HUD가 보이는 컷을 쓰면 캡션에 **OSM 출처**를 넣는다(콘티 §6에 이미 있음). `weather=clear`로 고정하면 날씨를 받아 오지 않지만 줄은 그대로 보이니 Open-Meteo도 함께 적는 것이 안전하다. HUD 없는 `-clean` 컷을 쓰면 줄이 안 보이므로 캡션 출처 문장만 남긴다.
- **흐린 근경 덩어리:** 정상 1인칭 방위 320~330°, 능선 s=4950 방위 253° 쪽에서는 카메라 바로 앞 물체가 흐린 검은 덩어리로 보인다. 위 표의 방위를 지키면 들어오지 않는다. 패닝 범위를 넓힐 때 확인한다.
- **동동이 그림자:** 낮 시각을 오전으로 당기면 11월 해가 낮아 그림자가 길어진다. ②는 12:30 이후를 쓴다.
- **화면 위치는 촬영 날짜를 탄다:** §1-1.
- **실제와 비교하지 않음:** 지형·코스·도심 원경만 실제 자료이고, 정자·나무·단풍 색은 게임 속 설정이다(AGENTS.md §3). 캡션의 "상상 설정" 문구(콘티 §6)와 맞는다.
