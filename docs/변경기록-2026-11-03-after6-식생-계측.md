## 1회성 멈춤 근거

기존 after5 프로파일 8개 모두 가장 긴 timeDelta가 첫 샘플이다. 균형은 2,096.714ms, 높음은 402.483~550.431ms다. 기존 벤치마크는 rAF·앱 프레임 집계를 켠 뒤 Profiler.enable/start와 Tracing.start를 호출한다. 프로파일러 시작 구간이 보행 프레임 집계에 포함되는 구조다.

기존 trace의 tick FunctionCall 시각 간격을 조회한 결과:

단, 높음 S와 A는 trace 내부에도 긴 간격이 있다. S는 tick 간격 index=1, A는 index=29에서 발생했다. 해당 FireAnimationFrame은 541.989/536.931ms지만 앱 프레임 FunctionCall은 33.275/32.760ms다. A의 앱 함수 반환 후 구간에 MinorGC가 12회 있으나 합계 5.479ms여서 나머지 약 0.5초를 설명하지 못한다. 셰이더 컴파일·청크·숲 생성으로 단정할 근거는 없으며, 이 두 조건의 잔여 원인은 확정하지 못했다. 새 trace에서 추가 확인해야 한다.

## 수정

1. createChunkCuller.planeMask가 부모 상자의 바깥·안쪽·교차 평면을 판정한다. 식생 칸을 완전히 포함하는 평면은 자식 식생에서 재검사하지 않는다. 자식 경계는 부모 경계를 만들 때 사용한 동일한 Box3다. 화면 바깥 식생·거리 예산·LOD 전환 거리는 유지한다.
2. 식생 경계와 최대 거리를 로딩 때 보관한다. 정렬 비교마다 반복하던 위치 거리 계산을 보이는 식생마다 프레임당 한 번으로 줄인다. 사진판 400m 제한도 같은 제곱거리로 확인한다.
3. 벤치마크에서 계측을 먼저 시작하고 1.5초 준비 후 rAF 경계에서 앱 통계와 독립 프레임 집계를 초기화한다. 측정 종료 때 먼저 결과를 고정한 다음 trace 전송·Profiler.stop을 실행한다. 초기화·종료 비용이 측정에 섞이지 않는다. 준비 시간 instrumentationSetupMs와 instrumentationWarmupMs, 실제 measuredWindowMs, durationPass를 JSON에 기록하고 trace에 hiking-measure-start/end 마커를 남긴다. 시작·종료 사이에는 프레임을 선별하거나 삭제하지 않는다. 균형 50fps·높음 55fps·최대 500ms 기준을 유지한다.
4. 평면 마스크가 Three.js 원래 절두체 판정과 일치하는지 확인하는 테스트 2개를 추가했다. 카메라 회전·부모/자식 경계·거리·빈 상자를 포함한다. 미실행이다.

계측을 제외한 실행의 개선 폭과 8개 조건 pass 여부는 아직 알 수 없다. 기존 48.4fps에서 시작 정지만 산술 제거해 합격이라고 선언하지 않는다. 실제 실행 결과로 확인해야 한다.
