# after10 — 접촉 음영 시안·법선 패스 비용 분리

산개발 / 2026-11-03. 구현 및 구문·정적 검사 완료. 실행 검수·전후 캡처는 미실행이며 품질 개선 완료 판정은 보류한다. after9의 7차 성능 완료 판정은 유지하되 이 변경의 성능은 별도 검수가 필요하다.

## 관찰과 원인 확인 범위

7차 검수는 AO 켬/끔의 CPU 작업 차이 21~23ms를 기록했다. 절반 해상도로도 크게 개선되지 않았고 `SSAOPass.render`가 `_renderOverride`에서 장면의 법선·깊이를 다시 그린다는 코드 구조는 확인했다. 기존 `render-breakdown`은 이 제출량을 `SSAO 깊이·법선`으로 구분한다. 하지만 이 자료만으로 재렌더가 시간 대부분을 차지한다고 확정할 수는 없다. GPU 비용·드라이버 대기·CPU 제출 비용을 새 진단으로 구분해야 한다.

진단을 위한 세 모드를 추가했다. `aoMode=off|normal|full`에서만 적응형 조절을 정지하고 높음의 같은 DPR·그림자 조건을 고정한다. 일반 실행은 after9 정책을 유지한다.

| 모드 | 수행 내용 | 확인 목적 |
|---|---|---|
| off | 직접 기본 장면만 출력 | 기준 비용 |
| normal | 직접 기본 장면 출력 + SSAOPass와 같은 법선·깊이 렌더, AO 합성 없음 | 장면 재렌더의 증가 비용 |
| full | 기존 전체 SSAO·합성 | 후처리 포함 비용 |

`aoProfile=1`에서만 CPU 단계 계측과 `EXT_disjoint_timer_query_webgl2` 질의를 켠다. 기본 장면, 법선 장면 재렌더, AO 후처리 합계를 각각 기록한다. GPU 질의는 중첩하지 않고 비동기 완료 결과만 읽는다. `gl.finish`나 동기 대기를 추가하지 않았다. 미지원은 `gpuSupported:false`, 값 없음은 null, disjoint 대기 표본은 폐기 횟수로 표시한다. GPU 결과 도착이 늦으면 표본 구간 경계에 걸칠 수 있다. 전체 출력 패스 등 미계측 부분도 있으므로 단계 평균 합을 전체 GPU 시간으로 표현하지 않는다.

`normal`은 AO를 합성하지 않으므로 실제 `rendering.ao`는 false이며 `normalPass`만 true다. 일반 벤치마크에 진단 쿼리 인수를 넣지 않는다.

## 값싼 대안 시안

`src/contact-occlusion.js`는 로딩 중 바위·나무 배치로 2048² R8 접촉 음영 지도를 만든다. 약 4MiB의 CPU 데이터와 GPU 텍스처 각각 한 장이며, mipmap·추가 장면 렌더·추가 드로우콜이 없다. 기존 근경 지형과 노면 셰이더에 텍스처 조회 한 번을 추가한다. 처음 셰이더 준비 전 지도 갱신을 마치며 걷는 동안 갱신하지 않는다. 동일 재질을 쓰는 새 지형 청크도 같은 지도를 사용한다.

- 보호 구역 필터를 통과한 실제 모델 배치와 첫 LOD의 폭·배율을 사용한다. 도시·하늘·원경에는 적용하지 않는다.
- 바위 접촉부 반경은 2~6m, 나무 아래는 3~9m로 제한했다. 근경 지도 약 1.79×2.39m/텍셀 해상도에 맞춘 **넓은 근사 음영**이다. 작은 바위의 정확한 접촉 윤곽을 구운 것이 아니다.
- 바위는 중심 최대 72%, 나무는 56%의 간접광 차폐를 부드럽게 감쇠한다. 겹침은 최댓값만 취해 숲이 누적해서 검어지는 것을 막는다. 직접 태양광·안개·노면 높이·접지는 바꾸지 않는다.
- 지형과 노면의 간접 확산·간접 반사광에만 곱한다. 바위 자체의 오목한 틈, 수목 높이별 차폐·회전 윤곽·동적 물체는 표현하지 못한다. 그림자나 광선 추적 AO를 대체하는 정확한 물리 모델은 아니다.
- 기본값은 켬이고 `contactAO=off`로 비교할 수 있다. `hiking.contactOcclusion(false/true)`는 uniform만 갱신하며 셰이더를 재컴파일하지 않는다. 최종 농도·반경은 캡처 검수 후 판단한다.

## 전후 비교와 성능 검수

`scripts/capture-contact-occlusion.mjs`를 준비했다. GPX 315번 부근 바위와 250번 부근 숲길에서 1인칭·55도 시야·정지 상태로 촬영한다. 한 페이지에서 음영 uniform만 바꾸므로 전후 카메라·DPR·LOD·일광이 같다. SSAO는 비교 양쪽에서 끈다. 촬영 후보 위치는 현장 검증 지점이 아니며 실제 화면에 충분한 바위·숲이 있는지 확인해야 한다.

실행 시 생성될 파일(현재 미생성):

- `artifacts/contact-occlusion/rocks-before.png`, `rocks-after.png`
- `artifacts/contact-occlusion/forest-before.png`, `forest-after.png`
- `artifacts/contact-occlusion/results.json`: 카메라·배치 지도 상태와 세 진단 모드의 원본 누적 계측·10초 차분 `phases`, 앱 성능 집계

법선 모드−기본 모드 전체 render CPU 평균, 전체 SSAO−기본 모드 평균과 `법선 장면 재렌더` CPU/GPU 평균을 함께 비교한다. 법선 추가분이 전체 추가분 대부분인지 확인한 뒤에만 원인을 확정한다. 진단 결과는 계측 오버헤드가 있으므로 합격 벤치 수치로 사용하지 않는다.

전후 이미지와 8개 조건 결과가 없어 음영 가시성·성능 유지·GPU 병목은 아직 확인하지 않았다. 화면 캡처가 없는 상태를 완료로 보고하지 않는다.

## 정적 검사·사본

변경 JS 및 새 테스트의 Node v22.23.4 `--check`와 `git diff --check` 통과. CPU 지도 범위·중첩·uniform 토글, 기존 셰이더 hook 보존, 비동기 GPU 질의·disjoint 폐기·확장 미지원 테스트를 작성했다. 테스트 본문 실행은 산기획 담당이다.

검수 사본: `/private/tmp/gwanak-after10-review.QFfmtb`. `.git`, `node_modules`, `dist`, `artifacts`를 제외하고 복사하며 원본 node_modules를 링크한다. 기존 작업을 보존했고 커밋·push·삭제·배포는 하지 않았다.

## 가정

- 현장 측정 자료 없이 기존 임시 배치만으로 시각 보완한다. 새 자료·외부 자산은 사용하지 않는다.
- 낮은 추가 비용이 예상되지만 새 8개 조건 통과 전에는 성능 보장을 하지 않는다.
- 기존 높음 55fps·균형 50fps·최대 프레임 500ms 이하·재컴파일 0·화질 안정 기준과 접지 검수를 유지한다.
