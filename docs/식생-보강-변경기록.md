# 실제 수종 기반 숲·하층 식생 업무 — 부분 구현

작성: 산풍경 · 2026-11-03

## 결과

실제 수종·임상 기반 숲 교체는 미완료다. 산리서치의 `실경자료-조사.md`를 다시 확인했으며 임상도·정사영상 확보는 0건이고 수종별 구간 비율도 없다. 현재 스캔 나무를 한국 수종으로 재명명하지 않았다. 항공사진 경계 배치 및 `forest-density.json` 원자료 교체도 하지 않았다.

확보 자료 없이도 가능한 하층 식생 보강 코드는 반영했다. 기존 2m 간격 작은 돌 배치를 유지하고, 길 양옆 3개 띠에 풀·낙엽·낮은 관목을 고정 난수로 배치한다. 최근접 등산로 반폭 + 0.15m 안쪽은 비운다. 600m 위에서는 새 관목을 제외한다. 진달래·철쭉·조릿대의 실제 분포를 재현한 것으로 표시하지 않는다.

## 성능 계약

| 항목 | 높음 | 균형 | 낮음 |
|---|---:|---:|---:|
| 근거리 기본 밀도 | 100% | 50% | 25% |
| 근거리 범위 | 24m | 16m | 10m |
| 표시 종료 거리 | 65m | 45m | 28m |
| 중거리 밀도 | 기본의 35% | 기본의 35% | 기본의 35% |

64m 청크·형상별 InstancedMesh와 공유 geometry/material을 사용한다. 풀·낙엽은 인스턴스당 5삼각형, 관목은 8삼각형이며 새 텍스처는 0바이트다. 인스턴스 행렬은 생성 시 한 번만 작성하고 런타임에는 count만 변경한다. 경계 상자·구체를 생성하고 기존 청크 가림 판정을 적용한다. 원경 하층 식생은 표시하지 않으며 기존 나무의 LOD·crossboard·소나무 임포스터 경로는 유지한다. 새 한국 수종 임포스터는 만들지 않았다.

기존 통합 장면은 성능 문서의 after2 기록상 균형 CPU 4배에서 23.8fps로 기준 30fps 미달이다. 이번 변경 이후의 성능 충족 여부는 미측정이며 위 수치는 성능 보장이 아니다. 생성 비용·추가 드로우콜·통합 삼각형 상한도 후속 측정이 필요하다.

## 확인

- `git diff --check`: 통과.
- `tests/ground-cover.test.mjs`: 결정적 배치·길 비움·인스턴싱·거리/화질 밀도 검사 작성, 미실행.
- 앱 실행·npm test·빌드·Chrome 성능 측정: 스크립트 실행 금지에 따라 미실행.
- 계곡 숲길·중턱·연주대 직전 암릉의 동일 위치 전후 캡처: 미확보. 과거 이미지를 새 결과로 재사용하지 않았다. report_image 제출도 하지 않았다.

## 가정

- 하층 식생은 계절·수종 미확정의 임시 시각 표현이다. 600m 구분과 풀/낙엽/관목 비율은 배치용 가정이며 조사 결과가 아니다.
- 수관 밀도·나무 수는 검증되지 않은 상태에서 늘리지 않는다. 대표 핵심 요구인 자동 걷기 경관은 실행 검수 후 판단한다.
- 기존 동시 변경을 보존하며 이번 작업에서 커밋·삭제·배포·push·외부 전송을 하지 않았다.

## 대표 확인 필요

스크립트 실행 금지 해제 뒤 다음 명령으로 확인해야 한다.

```sh
cd /Users/joonyoung/gwanak-hiking

npm run dev -- --port 5176
# 위 서버 실행 중 별도 터미널에서
LABEL=vegetation-after HEADED=1 node scripts/benchmark-performance.mjs
```

수정 전 소스 보존본과 현재 소스를 각각 실행해 세 지점의 거리·카메라·화질·뷰포트를 고정한 전후 캡처를 만들어야 한다. 기존 `scripts/capture-nature.mjs`는 요청된 세 지점 구성과 다르므로 그대로 실행해 완료 처리하면 안 된다.

실제 수종 교체에는 사용 허용 임상 구획 데이터·정사영상 숲 경계·식생 원문·한국 수종 형상 검토가 필요하다. 회원가입·신청·외부 문의·자료 전송은 수행하지 않았다. 자료 확보 뒤 수종별 자산과 비율을 확정하고 성능 예산 내에서 기존 나무를 교체한다.
