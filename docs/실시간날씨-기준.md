# 실시간 날씨 기준 (1차본) — 산리서치, 2026-11-03

표기: ✅ 페이지·실호출로 직접 확인 / ⚠️ 제안값(설계 기준, 산디자인이 조정 가능) / ❌ 확인 못함

## 1. 결론
- **API: Open-Meteo 무료 API (키 없음, 가입 없음).** 이 맥에서 `curl`로 실제 호출해 CORS 헤더와 값 반환을 확인했습니다.
- **기상청 API는 1순위로 쓰지 않습니다.** 서비스키가 필수이고(공공데이터포털 가입·키 신청), 키를 브라우저 코드에 넣으면 노출되며, CORS 허용 여부를 문서에서 못 찾았습니다.
- **⚠️ 가장 큰 조건: Open-Meteo 무료 API는 비상업 전용입니다.** 구독·광고가 없는 개인·비영리 앱만 해당합니다. 이 앱을 유료화하거나 광고를 붙이면 유료 플랜이 필요합니다. → 대표 확인 사항.

## 3. Open-Meteo 이용 조건과 출처 표기
- 데이터 라이선스 **CC BY 4.0**, 서버 코드는 AGPLv3 ✅. 적절한 크레딧, 라이선스 링크, 변경 여부 표시 필요 ✅.
- 표기 방식(공식 예시): 데이터가 표시되는 위치 옆에 링크 ✅.
  ```html
  <a href="https://open-meteo.com/">Weather data by Open-Meteo.com</a>
  ```
- **앱 표기 문구 제안 ⚠️:** 화면 하단 또는 정보 창에 `날씨 정보: Open-Meteo.com (CC BY 4.0)` + 링크 `https://open-meteo.com/`. 수동 지정(`?weather=`)이나 맑음 대체일 때는 API 데이터가 아니므로 표기 없어도 되지만, 항상 보이게 두는 편이 안전합니다.
- 무료 한도는 이 앱 방식(10분마다 1회 = 하루 144회/사용자)이면 사용자 1명당 한도의 약 1.4%. **한 IP에서 다수 접속 시(회사망 등) 일 10,000회 공유**이므로 사용자 수가 늘면 유료 플랜을 검토해야 합니다.
- 상업 이용 시 별도 `customer-api.open-meteo.com` 주소와 `apikey`가 필요하며 요금은 ❌ 확인 못함.

## 4. 호출 방법 (실호출로 확인)
```
https://api.open-meteo.com/v1/forecast
  ?latitude=37.4453&longitude=126.9640
  &current=weather_code,cloud_cover,visibility,wind_speed_10m,wind_gusts_10m,precipitation,rain,snowfall,is_day,temperature_2m
  &wind_speed_unit=ms
  &timezone=Asia%2FSeoul
```
- 실제 응답(2026-11-03 14:00 KST): `weather_code 2, cloud_cover 76, wind_speed_10m 2.52 m/s, wind_gusts_10m 8.7, visibility 15560 m, is_day 1`. `visibility`는 문서의 current 목록에는 없지만 **실제로는 반환됩니다** ✅ (다만 모델에 따라 null일 수 있으므로 null이면 코드·구름량만 쓰도록 처리).
- 풍속 단위는 기본이 km/h라서 **반드시 `wind_speed_unit=ms`** 를 붙입니다 ✅.
- **`models=kma_seamless`/`kma_ldps`는 쓰지 마세요.** current 값이 전부 null로 옴 ✅(실호출). 모델 지정 없이 기본(best match)을 씁니다.
- `ecmwf_ifs025`는 값은 오지만 visibility가 null, 격자가 0.25°라 쓰지 않습니다.
- `elevation=629`를 붙이면 기온 보정에 반영됩니다(기본은 553 m, 격자 평균 고도) ✅. 날씨 코드·구름량·풍속은 이 값에 따라 바뀌지 않았음 ✅. 기온을 화면에 쓸 일이 없으면 생략해도 됩니다.
- **시각 처리:** 응답 `current.time`은 `Asia/Seoul` 기준 문자열입니다. 오래된 값(예: 1시간 이상 전)이면 무시하고 대체 처리합니다 ⚠️.
- 실패·타임아웃(⚠️ 8초)·HTTP 오류·값 null이면 **현재 맑은 하늘(맑음)로 대체**. 재시도는 다음 10분 주기에 합니다. 연속 실패 시 마지막 성공값을 30분까지 유지하는 안은 산디자인 판단.

## 6. 날씨 코드 → 6단계 대응표 (WMO 코드, Open-Meteo)

### 6-1. 코드 표 ✅ (Open-Meteo 문서의 WMO 코드)
| 6단계 | WMO 코드 | 세부 강도 |
|---|---|---|
| 맑음 | 0 (맑음), 1 (대체로 맑음) | — |
| 구름 | 2 (부분 구름) | — |
| 흐림 | 3 (흐림) | — |
| 안개 | 45 (안개), 48 (서리 안개) | 45: 보통, 48: 짙음 |
| 비 | 51·53·55 (이슬비 약·보통·강), 56·57 (어는 이슬비), 61·63·65 (비 약·보통·강), 66·67 (어는 비), 80·81·82 (소나기 약·보통·강), 95·96·97·99 (뇌우) | 약: 51·56·61·66·80 / 보통: 53·63·81 / 강: 55·57·65·67·82·95·96·97·99 |
| 눈 | 71·73·75 (눈 약·보통·강), 77 (싸락눈), 85·86 (소낙눈 약·강) | 약: 71·77·85 / 보통: 73 / 강: 75·86 |

- 표에 없는 코드(예: 4, 10~44)는 **구름량으로 판정**: ≤25% 맑음, ≤70% 구름, 그 이상 흐림 ⚠️.
- 우선순위 ⚠️: 눈 > 비 > 안개 > 흐림 > 구름 > 맑음. 어는 비(66·67)는 "비"로 묶고 얼음은 표현하지 않음. 뇌우는 "비 강"으로 묶고 번개·천둥은 이번 범위 밖.
- 보정 규칙 ⚠️(코드와 모순될 때): `snowfall > 0`이면 눈, `rain > 0.1 mm`이면 비, 코드가 0~3인데 `visibility < 1000 m`이면 안개(약).
- ❌ 이 코드 해석은 문서 표 기준입니다. 한국 실황과 어긋나는 사례(예: 안개를 코드 45로 잘 내는지)는 확인하지 않았습니다. 안개 발생 빈도는 모델 특성상 낮을 수 있어, 안개는 `?weather=fog` 수동 확인이 필요합니다.

### 6-2. 단계별 기준치 ⚠️ (제안값 — 코드 표 외 수치는 설계 기준이며 출처 없는 값입니다)
| 항목 | 맑음 | 구름 | 흐림 | 비 | 눈 | 안개 |
|---|---|---|---|---|---|---|
| 구름량 (0~1) | 0.05 | 0.45 | 0.85 | 0.95 | 0.9 | 1.0 |
| 구름량 판정 범위 (cloud_cover %) | 0~25 | 25~70 | 70~100 | 90~100 | 80~100 | 100 |
| 연무(안개) 거리 — 이 거리에서 거의 보이지 않게 (m) | 15,000+ | 12,000 | 7,000 | 약 4,000 / 보통 2,500 / 강 1,200 | 약 4,000 / 보통 2,500 / 강 1,000 | 보통 400 / 짙음 200 |
| 직사광 세기 (맑음=1) | 1.0 | 0.75 | 0.30 | 0.15 | 0.25 | 0.10 |
| 환경광(하늘빛) 세기 (맑음=1) | 1.0 | 1.00 | 1.12 | 1.00 | 1.00 (눈 반사) | 1.05 |
| 그림자 | 선명 | 약간 흐림 | 거의 없음 | 없음 | 없음 | 없음 |
| 비 입자 양 (최대=1) | 0 | 0 | 0 | 약 0.3 / 보통 0.6 / 강 1.0 | 0 | 0 |
| 눈 입자 양 (최대=1) | 0 | 0 | 0 | 0 | 약 0.3 / 보통 0.6 / 강 1.0 | 0 |
| 입자 낙하 속도 | — | — | — | 약 8~9 m/s | 약 1 m/s | — |
| 바람 (평소 구간, 풍속 m/s) | 0~3 | 1~5 | 1~6 | 2~10 | 0~6 | 0~3 |

- 비·눈 입자는 "최대"를 성능 허용 한도(45fps 기준)로 잡고 비율로 지정합니다. 절대 개수는 산디자인이 프레임 측정 후 정합니다.
- 연무 거리는 서울 원경(롯데타워 약 20 km 이상 등, `data/서울원경-기준표.md`)이 맑음에서만 보이게 하는 값입니다. 서울시 보도자료에 "남산에서 관악산이 20 km 이상 보이는 날이 월 2~3일"이라는 근거가 있어(기록표 §7-3) 보통 날은 맑아도 원경이 흐릿합니다. API의 `visibility`(예: 15,560 m)가 오면 그 값을 맑음·구름의 연무 거리에 그대로 써도 됩니다 ⚠️.

### 6-3. 바람 소리 세기 (풍속 m/s → 0~1) ⚠️
풍속 구간은 보퍼트 풍력 계급의 일반적 경계값을 따랐습니다. 소리 세기 수치는 제안값입니다.
| 풍속 (m/s) | 표현 | 바람 소리 세기 | 숲·풀 흔들림 |
|---|---|---|---|
| 0 ~ 0.5 | 고요 | 0.05 | 거의 없음 |
| 0.5 ~ 3.3 | 실바람~지각풍 | 0.20 | 잎 살랑 |
| 3.4 ~ 7.9 | 연풍~화풍 | 0.50 | 가지 흔들 |
| 8.0 ~ 13.8 | 질풍~강풍 | 0.80 | 큰 가지 흔들, 옷자락 |
| 13.9 이상 | 폭풍 | 1.00 | 최대 |
- 바람 소리는 날씨 단계가 아니라 `wind_speed_10m`로 직접 정합니다. 10분마다 값이 바뀌므로 소리 세기는 5초 정도에 걸쳐 부드럽게 바꾸세요 ⚠️.
- 돌풍(`wind_gusts_10m`)은 소리 세기에 쓰지 않고 참고만 합니다. ❌ 산 능선의 실제 풍속이 10 m 격자 값과 얼마나 다른지는 확인하지 못했습니다.

## 7. 구현 쪽 정리 (산디자인·산개발 참고)
- 호출 주기 10분 ✅ 지시. API 데이터는 15분마다 바뀌므로 10분 호출은 같은 값을 받을 때가 있습니다(문제 없음, 한도도 여유).
- 수동 지정 `?weather=clear|cloud|overcast|rain|snow|fog`와 약·보통·강은 `?weather=rain&level=heavy` 등으로 따로 둘 것을 제안합니다 ⚠️(이름은 산디자인 결정).
- 테스트에 넣을 항목: 코드 → 6단계 전부(위 §6-1의 모든 코드), 우선순위·보정 규칙, null/오류 → 맑음, 풍속 구간 경계(0.5, 3.4, 8.0, 13.9).
