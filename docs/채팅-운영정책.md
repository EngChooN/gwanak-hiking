## A. 금칙어

### A-1. 서버가 하는 일 (✅ 코드 확인)
- 목록 = `server/chat-banned-words.txt`(한 줄 하나, `#` 주석, 쉼표 여러 개 가능) + 환경 변수 `BANNED_CHAT_WORDS`.
- `sanitizeChat`이 **글자가 그대로 들어 있으면** 그 부분만 `***`로 바꿉니다(대소문자 무시, 부분 일치). 문장 전체를 막지 않아 대화는 계속 됩니다.
- 목록 파일이 없으면 빈 목록으로 뜹니다(서버는 안 죽음). 목록을 고치면 서버를 다시 켜야 합니다.
- 이름 금칙어(`BANNED_WORDS`)는 따로입니다. 이름에 걸리면 이름을 익명으로 바꿉니다.

### A-2. 기본 목록의 구성 (127개, 2026-11-08)
욕설 / 성적 표현 / 혐오·차별 표현 / 담배 판매·구매 유도 네 묶음입니다. 출처는 **제가 쓴 목록**입니다. 외부 금칙어 사전·공개 목록을 가져오지 않았습니다(이용 조건 문제를 피하려고). 그래서 완전하지 않습니다. 운영하면서 신고 기록을 보고 늘립니다.

### A-3. 부분 일치라서 **일부러 뺀 말** (오탐 예시)
부분 일치는 정상 낱말 속의 글자도 가립니다. 아래는 목록에 **넣지 않은** 말과 이유입니다.

### A-4. 예외 처리 제안 (서버 코드를 고쳐야 해서 이번엔 안 함, 산개발 후속 🟡)
오탐을 줄이면서 `시발` 같은 흔한 욕을 **막을 수 있게** 하는 방법입니다.
1. **보호 단어(허용) 목록:** 파일에 `!시발점`처럼 `!`로 시작하는 줄을 두고, 가리기 전에 그 낱말을 임시 표시로 바꿔 두었다가 가린 뒤 되돌립니다. 그러면 `시발`을 목록에 넣고도 `시발점`·`시발역`·`시발택시`는 살아납니다. (지금 `parseWordList`는 `!`를 그냥 낱말로 읽으니, 현재 파일에는 `!`를 쓰지 마세요.)
2. **글자 정규화:** 비교 전에 공백·기호(`. - _ * ~`)를 지우고 비교 → 변형 대부분을 잡음. 단, 가릴 위치를 원문에 되돌려야 해서 구현이 조금 어렵습니다.
3. **낱말 경계 규칙(선택):** 짧은 욕은 앞뒤가 한글이 아닐 때만 가림. 한국어는 조사가 붙어서 오히려 놓치기 쉬워 **추천하지 않습니다.**
4. 필요하면 채팅 금칙어 시험에 "오탐 문장 모음"(A-3의 정상 문장들)을 넣어 목록을 고칠 때마다 자동으로 확인.

### A-5. 목록 운영 규칙 🟡
- 추가·삭제는 이 파일만 고치고 서버 재시작. 바꾼 날짜와 이유를 `docs/` 변경 기록에 한 줄.
- 신고 기록(`reports.jsonl`)의 `chat` 칸에서 가려지지 않은 나쁜 말이 보이면 그 낱말을 목록에 추가. 가려진 정상 말이 신고되면 뺌.
- 목록 파일의 낱말 자체가 불쾌한 표현이므로 화면·보고서에 그대로 옮겨 적지 않습니다.

### A-6. 흡연장의 담배 판매·구매 유도 문구 🟡⚖️
흡연장은 **금연 중이거나 원래 안 피우는 사람이 가상 담배로 쉬는 곳**입니다. 실제 담배·전자담배 액상을 사고파는 말이 오가면 서비스 취지와 어긋나고, 미성년자가 있을 수 있어 위험합니다.
- **정책:** 실제 담배·전자담배·액상·니코틴의 판매·구매·소분·택배·대행을 권하는 문구는 금지입니다.
- **구현:** `담배 팝니다`·`담배 삽니다`·`담배 구해`·`액상 팝니다`·`니코틴 구해` 등 22줄을 금칙어에 넣었습니다(띄어쓰기 한 칸 형태와 붙인 형태). 이 문구에 걸린 부분은 `***`로 가려집니다.
- **한계:** `담배 한 갑 사실 분`처럼 변형은 못 잡습니다. 신고 사유에 "불법 거래·판매 권유"가 필요합니다(§D).
- **정상 대화는 막지 않음:** "담배 피우러 왔어요", "담배 안 피운 지 3일째", "담배 생각나네요" 등은 시험에서 가려지지 않았습니다. 금연 이야기는 이 서비스의 핵심이라 막으면 안 됩니다.
- ⚖️ 법무 확인: 담배·전자담배 판매 권유와 청소년 대상 제한에 관한 법령상 의무(운영자 책임 범위, 신고 의무 여부)는 제가 판단하지 않았습니다. 확인 전까지는 "취지에 맞지 않아 가림" 수준으로만 운영하세요.

### 신고 3줄과 "채팅 비저장" 원칙의 관계
- 원칙은 **"일반 채팅은 안 남기고, 신고된 사람의 최근 3줄만 신고 처리 목적으로 남긴다"** 입니다. 모든 채팅을 저장하는 것이 아니라 신고 사건의 증거 최소치입니다.
- 3줄이 판단에 충분하지 않을 수 있습니다(괴롭힘이 3줄 이전부터). 대신 개인정보 최소화에 유리. 늘리려면 대표 결정(예: 5줄)과 처리방침 수정이 함께 필요합니다.
- **신고한 사람의 글은 안 남김**(대상의 글만). 반대 입장 맥락이 없어 오신고 판단이 어려울 수 있음 → 운영자 판단은 "여러 명의 신고가 겹쳤는가"를 함께 봅니다.
- 3줄 안에 전화번호 등이 있으면 그대로 남습니다 → §B 가림 규칙 권고의 이유.

## D. 신고와 24시간 숨김 규칙 (✅ 동작) + 제안
**지금 동작:** 신고 → 기록(대상 최근 3줄 포함) 한 줄 추가 → 같은 사람이 같은 대상을 반복 신고해도 한 번만 인정 → **서로 다른 신고자 3명**이면 대상의 이름표를 24시간 숨기고 다른 방으로 옮김(같은 접속 해시도 24시간 이어짐). 사유는 `부적절한 이름 / 방해·괴롭힘 / 기타`.

**채팅과의 관계(빈칸) 🟡**
1. **채팅 자체는 숨겨지지 않습니다.** 신고로 이름표가 익명이 된 사람의 채팅도 계속 전달됩니다(산개발 가정). 이름만 숨는 것이라, 심한 채팅을 하는 사람이 3명 신고 → 이름 숨김 → 방 이동 후 다시 채팅할 수 있습니다. 🟡 제안: **숨김 중에는 채팅을 막는** 옵션(24시간 채팅 금지). 이 정도가 "최소 운영"에 맞습니다. 구현은 서버에서 `hidden()`이면 `c`를 버리는 한 줄.
2. **신고 사유에 채팅 맞춤 항목 추가:** `욕설·혐오 채팅` / `성적 표현` / `개인정보 노출` / `불법 거래·판매 권유`. 지금 사유 목록은 이름 중심입니다.
3. **신고가 자동으로 3줄을 남기므로** 신고 UI에 "신고하면 이 사람의 최근 채팅 3줄이 운영자에게 전달됩니다"를 한 줄 알려야 합니다(처리방침과 같은 내용).
4. **악용 방지:** 3명이 짜고 신고하면 아무나 숨길 수 있음. 숨김은 24시간뿐이고 영구 제재가 아니라서 1차는 수용. 같은 방 안의 사람만 신고 가능한지, 신고 횟수 제한은 현재 확인하지 않음.
5. **운영자 처리 기한·담당**은 대표 결정 사항(예: 영업일 2일, `멀티-설계.md` 제안과 같음). 지금은 `reports.jsonl`을 사람이 읽는 것이 전부입니다. 검토 방법은 서버 기록 파일을 열어 보는 것이라 **배포 환경에서 파일에 접근할 수단**(예: Fly 볼륨)이 필요합니다.
