# 변경 기록 — 서버 주소 늘 붙이기 · 라디오 버그 2건 (2026-11-08, 산기획)

## 1. 같은 링크인데 상대가 안 보임 → 서버 주소를 늘 주소에 붙임
- **원인:** 배포본에 함께 걷기 서버 주소(`VITE_MULTI_SERVER_URL`)가 없다. 주소에 `?server=`가 없으면 같은 브라우저 창끼리(BroadcastChannel)로 조용히 떨어져 다른 기기 사람이 안 보였다. 허브 카드로 들어오거나 주소를 다시 쳐서 들어오면 `?server=`가 빠졌다.
- **고친 것:** `src/server-link.js`(새 파일)
  - `?server=`가 있으면 localStorage `gwanak-multi-server`에 기억한다(`off`·`local`은 기억하지 않음).
  - 체험 페이지(`/hiking/`·`/smoking/`)는 맨 먼저 `src/server-link-pin.js`를 실행해, `?server=`가 없으면 빌드 변수 → 기억한 값 순으로 골라 주소창에 붙인다(replaceState). 주소를 복사해 보내면 같은 서버로 들어온다.
  - 허브(`/`)는 자기 주소에는 붙이지 않고(옛 주소 규칙으로 `/hiking/`에 넘어감) 체험 카드 링크에만 붙인다.
- **남은 것:** 처음 오는 사람이 허브부터 들어오면 기억한 값이 없다. 그래서 배포할 때 `VITE_MULTI_SERVER_URL=wss://<터널 주소>`로 서버 주소를 빌드에 넣어야 한다. Quick Tunnel 주소는 cloudflared를 다시 켜면 바뀌니, 그때마다 다시 배포하거나 고정 주소(Fly.io 등)로 옮긴다.
- 확인: `tests/server-link.test.mjs` 5개, 브라우저(허브 카드 → 흡연장·등산, 주소만 쳐서 들어감)에서 `?server=`가 붙는 것을 확인.

## 2. 라디오: 채널을 맞춰도 볼륨을 한 번 눌러야 소리가 남
- **원인:** 채널 파일을 받는 동안(loading)은 방송 0·잡음 크게로 두는데, 받기가 끝나 `playing`이 되어도 음량을 다시 계산하지 않았다(`emit`만 함). 그래서 볼륨을 건드릴 때까지 잡음만 들렸다.
- **고친 것:** `src/radio-audio.js` `startDeck`의 `onState`에서 상태가 바뀌면 `apply()`를 부른다.
- 확인: 헤드리스 크롬에서 볼륨을 건드리지 않고 91.9·99.1을 맞춤 → 고치기 전 −30dB(잡음), 고친 뒤 −22dB(방송, 잡음 0).

## 3. 라디오 95.5(산 날씨·등산 안내)가 아무 소리도 안 남
- **원인:** 녹음 파일이 없어 자막과 아주 작은 낮은 톤만 나왔고, 멘트 간격도 40~60초라 거의 무음처럼 들렸다.
- **고친 것:**
  - 녹음 파일이 없으면 기기에 깔린 한국어 목소리(`speechSynthesis`)로 대본을 읽는다. **기기 안 목소리(`localService`)만** 쓴다(크롬 'Google 한국의' 같은 온라인 목소리는 대본이 밖으로 나가므로 안 씀, AGENTS.md §5). 한국어 기기 목소리가 없으면 예전처럼 자막만.
  - 목소리 크기 = 또렷함 × 라디오 볼륨. 채널을 바꾸거나 끄거나 소리 꺼짐이면 바로 멈춘다.
  - 아이폰은 사용자 입력 안에서 한 번 말해 둬야 하므로 95.5에 맞출 때 빈 말을 한 번 한다.
  - 멘트 간격 40~60초 → 15~25초(`assets/radio/manifest.json` `gapSeconds`).
- 확인: 헤드리스 크롬(목소리 가짜로 끼움)에서 95.5 → 0.7초 뒤 기기 목소리(Yuna)로 대본을 읽고 자막이 같이 뜸, 91.9로 바꾸면 멈춤. 실제 아이폰 목소리는 아직 못 들어 봄.

시험: `npm test` 800개 통과, `npm run build` 통과. 커밋·push·배포 안 함.
