## 좌표·경로 계약

src/gpx-data.js는 data/GPX추출-계곡코스-상행.csv의 [위도, 경도, 고도_평활_m] 337개를 담습니다. npm test가 모든 점을 원본과 대조하므로 CSV 변경 시 함께 갱신해야 합니다.

원점은 첫 점 **관악산공원 입구: 위도 37.46803, 경도 126.946528**입니다. 첫 점 x=z=0, y=99.1m이며, y는 출발점 상대 높이가 아닌 GPX 평활 표고입니다. WGS84 타원체의 원점 위도에서 동·북 곡률 반경을 계산한 국소 접평면 근사를 사용합니다.

- x = (경도−원점 경도) × π/180 × N(φ₀)cosφ₀
- z = −(위도−원점 위도) × π/180 × M(φ₀)
- y = 고도_평활_m
- a=6378137m, e²=0.0066943799901413165. 1 Three.js 단위=1m, 북쪽은 −z.
- 경로 길이를 공식 4.6~4.7km에 맞춰 줄이지 않습니다. 3D 길이는 변환 좌표와 평활 고도로 다시 계산해 원본 누적 경사거리 5136.2m와 약 1.24m 차이가 납니다. 원본의 경사거리 계산 방식·반올림과 국소 투영 차이가 있으므로 원본 누적값을 그대로 쓰지 않습니다.
- 기존 EPSG:5186 변환 함수 projectedRoute/toLocal/toProjected는 명시한 투영 원점을 전달할 때만 사용하는 별도 인터페이스입니다. 현재 GPX 경로에 가상의 EPSG:5186 앵커를 사용하지 않습니다.

**연주대 기준은 629m**(SUMMIT_REFERENCE_ELEVATION)입니다. GPX 끝점 평활 고도는 **654.5m**로 25.5m 차이가 납니다. 모든 점의 평활값 보존 지시에 따라 끝점도 629m로 덮어쓰거나 전체 고도를 이동시키지 않았습니다. 지도 안내에 두 값을 함께 표시합니다. 실제 고도 정확성은 DEM 대조 전입니다.

## 합성 지형·캐릭터·발 접지

src/terrain.js는 실제 지형 로더의 어댑터입니다. 64m 지형 청크와 원경·식생 LOD를 유지하며, 등산로는 100m 이하·재질 경계별 메시로 나눕니다. 추정 계단의 디딤판·챌면은 같은 청크 메시 안에 병합해 단별 Object3D를 만들지 않습니다. 캐릭터·눈높이는 실제 노면 삼각형 조회를 따르고 이동 거리·속도 계산은 DSM 정렬 중심선을 따릅니다.

**옛 경로의 summit-approach-lod1.glb는 현재 게임에서 로드하지 않습니다.** 고정 합성 경로에 제작되어 GPX와 위치·높이가 맞지 않기 때문입니다. 기존 자산과 로더는 보존하고, 전체 경로 합성 청크로 대체했습니다. hiker-170-lod0.glb 및 createHiker/loadHiker·발바닥 지지 높이·두 관절 보정은 유지합니다. 기존 자산 패키지 문서와 112단 검사 기록은 옛 경로 기록입니다.

과거의 “17구간 × 5동작 × 8위상” 검증은 이번 구간별 배정의 검증 결과가 아닙니다. 새 테스트는 20~25% 상승·하강 경사의 디딤판 수평성·폭·단차와 raycast 높이를 확인하도록 추가했습니다. 실행과 1·3인칭 화면 검수, 실제 계단 치수·보행 모양의 경험자 확인은 남았습니다.

## 조작·저장·소리 인터페이스

W/S·↑/↓ 전후, A/D·←/→ 좌우, 드래그·Q/E 둘러보기, R 자동 걷기, Space 일시정지, V 시점, M 지도입니다. 터치 모드는 왼쪽 조이스틱·오른쪽 드래그·3인칭 두 손가락 확대를 사용합니다. 지도는 GPX 전체 점의 범위로 비율을 유지해 그립니다.

키보드·터치 공통 이동 명령을 쓰며 대각선도 속도 한도를 지키고 캐릭터 반경 .25m를 포함해 길 경계를 제한합니다. 후진은 자동 걷기를 해제합니다. 일시정지·지도·안내·탭 이탈 시 시점을 유지한 채 시간이 멈추고, 화면 회전 시 위치·상태를 유지합니다. 머리 높이 1.7m, 눈높이 1.6m, 흔들림 진폭 2.5cm이며 prefers-reduced-motion에서 흔들림을 끕니다.

localStorage['gwanak-hiking:v1']에 경로 ID·위치·시간·이동 거리·상승·걸음 위상·방문 장소 ID·접속 횟수를 약 .7초마다 저장합니다. lifecycle 이탈 이벤트에서도 저장·일시정지합니다. 경로 ID는 **gpx-valley-up-337-v1**로 바꿨습니다. **옛 합성 경로 저장은 새 경로와 대응하지 않아 기본 시범 시작점으로 초기화**합니다. 새 경로 저장은 위치·시간·장소 방문을 복구하고 멈춘 상태로 시작합니다. 저장소 사용 불가 시 세션만 유지합니다.

발소리는 기존 hiking:step 이벤트를 유지합니다.

```js
window.addEventListener('hiking:step', ({detail}) => {
  // {step, material, position:[x,y,z], distance, s, slope, elapsed}
  // 앱의 FootstepAudio가 기본 재생하며, 다른 소비자는 진단용으로 사용.
});
```

실제 발소리 재생을 연결했습니다. `src/footstep-audio.js`가 실제 `hiking:step` 이벤트마다 한 번 재생합니다. 별도 박자 타이머·이벤트 큐는 없습니다. 첫 포인터/키 입력에서 AudioContext를 생성하고 시작합니다. 헤더 ♪ 버튼으로 켜기/끄기, `localStorage['gwanak-hiking:sound:v1']`에 상태를 저장합니다. 일시정지·화면 이탈·음소거는 현재 소리도 짧게 페이드해 중단합니다.

계단은 직전 2개 파일, 그 외는 직전 1개 파일을 제외하며 재질별 순환 주머니에서 선택해 전부 사용합니다. 음높이 0.96~1.04배·음량 ±1.5dB·좌우 팬 ±0.08, 3인칭은 -3dB, 경사 10% 이상은 +1dB·저역 +1.5dB입니다. 출력 합산 후 -6dBFS 이하 소프트 리미터를 둡니다. 파일 끝은 짧게 페이드하며 암릉은 최대 0.5초로 제한합니다.

`public/sounds/` 35개는 design 원본의 동일 바이트 복사본입니다. 앱 조작 안내의 ‘소리 출처’ 및 `public/sounds/CREDITS.md`에 CC0와 암릉 CC BY 3.0(Blender Foundation, Yo Frankie!, 수정 내용)을 구분해 표시했습니다. 데크 3·암릉 2개는 설계 목표 수보다 적습니다.

디버그: 콘솔 `[발소리]`, 읽기 전용 `window.hiking.audio()`, 화면 `?audioDebug=1`. 로그에는 재질·파일/변형 번호·걸음·이동 접지 시각·AudioContext 시각·피치·음량·팬을 기록합니다. 재질은 이전 프레임 시작점이 아니라 걸음 접지 위치에서 결정합니다.

검증: `BASE_URL=http://127.0.0.1:4173 node scripts/capture-audio.mjs`, `node scripts/report-audio.mjs`. `artifacts/audio-verification.json`에 actual AudioContext·분석기 신호·12걸음 간격·13개 변형·재질 전환·음소거/복구를 기록하며 `발소리-검증-보고.html`에는 캡처·변형 로그·13개 미리 듣기를 포함합니다. 통나무는 GPX에 deck_stairs가 없어 재질 이벤트 하네스로 검사합니다. 실제 스피커·모바일 귀 검수는 대기 중입니다. 평지 보폭 .7m, 오르막 .55m, 계단은 3D 거리 약 .349857m당 한 걸음으로 계산합니다.

화질은 FPS에 따라 DPR 1.6/1.15/.8, 청크 반경 5/3/2, 숲 밀도 100/65/35%를 자동 조정합니다. 보급형 실기기 성능은 미검증입니다.

## 대표 확인 필요

삭제·외부 배포·push·프로젝트 업로드는 수행하지 않았습니다. 명시적으로 요청된 로컬 실행·테스트·빌드·화면 검증 명령만 실행했습니다. 위험 작업 대기 명령은 없습니다.

보급형 모바일 실기기 30fps, 실사 자산 적용 후 성능, 실측 DEM·고도 급변·정상 고도 편차·체크포인트 좌표·폭·노면·계단 치수·경험자 승인은 별도 확인이 필요합니다. 이용 조건 자료는 data/자료-출처-이용조건-기록표.md와 public/environment/출처-이용조건.md에 보존했습니다.
