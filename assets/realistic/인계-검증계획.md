# 산풍경 → 산개발: 실제 자료 기반 풍경 교체

2026-11-02. 상태: **준비·로더 소스 작성 / 실행·자료 생성·렌더 검증 미완료**.

## 변경 범위

`assets/realistic/`를 추가했다. `src/`, 기존 GLB, 기존 검증 기록은 변경하지 않았다. 이 코드를 아직 게임에 연결하지 않는다. `generated/manifest.json`은 다운로드와 전처리가 모두 성공해야 생성된다. 로더는 해당 파일이 없으면 명시적으로 실패한다.

## 가정

- 좌표는 현재 게임과 같은 관악산공원 입구 37.46803, 126.946528, +X 동쪽, −Z 북쪽, Y 표고(m).
- 근경은 전체 경로의 외곽 1km 버퍼(폭 약 2km)이며 격자 간격 8m. 30m DSM을 보간한 값으로 현장 해상도를 높였다는 뜻은 아니다. 원경은 북한산 24.1km를 포함하도록 원점 기준 동서남북 30km, 160m 격자로 갱신했다. 원경은 스트리밍 대상이다.
- 원경 범위가 동경 127도를 넘으므로 N37 E126 및 N37 E127 두 타일을 쓴다. Copernicus는 지표면이 아니라 수목·건물도 포함한 DSM이다.
- 보행은 중심 DSM 고도로 정렬하고 정상 끝점 632m와의 잔차를 수평 누적거리 비율로 보간한다(2026-11-02 후속 지시). 입구는 중심 DSM을 잠정 유지하며 실제 입구 표고 ±10m는 미검증이다. 종전 횡단 최저점·8cm 절삭은 폐기했다. 횡단 방향은 수평이며 기존 GPX 평활 고도는 originalY로 보존한다. 원시 DSM 격자는 유지하므로 보정된 경로 주변 법면·접지는 렌더 확인이 필요하다. 보행 폭 2.2m/정상부 1.8m는 현장 미확인 임시값이다. 상세는 `고도점검-수정보고.md` 참조.
- 실제 시설 치수가 없어 계단·데크를 새로 임의 배치하지 않는다. 목재 PBR 후보와 기존 키트는 남겨 두었다.
- 랜드마크는 산기획이 지정한 연주대 기준 방위·거리로 배치한다. 원본 위경도는 참조 메타데이터로 보존한다. 형상과 일부 높이는 검토용 근사값이다. N서울타워의 지반 243m, 롯데월드타워 지반 20m 등은 기준표·보충값을 따른다. 건물 높이는 OSM height → 층수×3m → 9m 순으로 추정 근거를 기록한다.
- `rock_face_03`은 갈색 풍화 암벽 후보이며 화강암 확인본이 아니다. 기존 모델을 회색으로 바꾸어 관악산 화강암이라고 표시하지 않는다.

## 첫 로딩과 원경

생성기는 근경 float32 격자, 512px PBR 7종×3맵, 1K HDRI, 경로 JSON의 실제 파일 바이트를 합산하고 런타임·캐릭터용 2MB를 더해 30,000,000바이트를 넘으면 중단한다. 압축 전 GPU 메모리·프레임 속도·JS 번들 실측을 대신하지 않는다. 현재 바이트 실측은 없다.

`loadLandscape()`는 원경을 받지 않는다. `streamFar()`는 낮은 해상도 지형·랜드마크만 받고, `streamCity(id)`는 OSM 건물 청크를 하나씩 받는다. `streamWater()` 전에는 `streamFar()`가 필요하다. 공개 API를 게임 실행 중 호출하지 않는다. 원경은 아직 LOD/임포스터로 축약하지 않은 압출 메쉬다. 청크 해제·시야 기반 요청 우선순위도 게임 통합 때 보완해야 한다.

## 산개발 연결 예제 — 미실행

```js
import {loadLandscape} from './assets/realistic/load-landscape.js';
const landscape = await loadLandscape({base:'/assets/realistic/generated/'});
scene.add(landscape.group);
const restoreEnvironment = landscape.applyEnvironment(scene, renderer);
// landscape.route의 x/y/z/s를 이동·ETA·카메라의 새 기준으로 일관되게 사용한다.
// 높이: landscape.floorHeight(x,z). 원본 GPX와 새 높이를 섞지 않는다.
landscape.update(camera); // 프레임마다 호출. 64m 청크, 2m 시각 격자.
await landscape.streamFar();
// 첫 장면 이후 화면 방위에 맞춰 요청. 모든 파일의 동시 로드를 피한다.
for (const chunk of landscape.manifest.cityChunks) {
  await landscape.streamCity(chunk.id);
}
await landscape.streamWater();
// 교체/종료: restoreEnvironment(); landscape.dispose();
```

원경을 모두 받는 위 루프는 API 사용 예시다. 모바일 제품에서는 시야·메모리 예산에 맞춰 필요한 청크만 요청해야 한다. 기존 `npm run build` 복사 스크립트는 새 폴더를 보장하지 않으므로 산개발이 배포 복사 목록에 추가한다. 기존 높이·계단·발 접지·속도 계수·저장 위치는 새 경로의 누적거리로 다시 검증한다.

식생·바위 API는 `addInstances({levels,placements})`다. 최대 128m 범위로 나눠 청크 중심 기준 LOD를 적용한다. 각 level에 `{url,distance}`를 주며 `placements`는 `{x,z,scale,yaw}` 배열이다. 밑동/바위 바닥 Y=0, Y-up, 단위 m인 모델이 필요하다. 모델을 실제로 확보하지 않았으므로 호출 예시용 경로를 실재 파일처럼 적지 않았다. 기존 캐릭터는 그대로 남아 있고 이번 실사 인체 교체는 미완료다.

## 화면 검증 절차

세 지점의 깔딱고개·계곡 명칭은 기존 임시 체크포인트 가정이다. 동일 x/z, 새 지면 위 눈높이 1.6m, 세로 FOV 64°, 북쪽 시선과 발밑 길이 함께 보이는 화각으로 비교한다. 기존 게임 화면을 먼저 3장 저장한 뒤 새 로더 화면을 같은 카메라 설정으로 3장 저장한다. 고도 기준이 달라지므로 눈높이는 각 버전의 지면을 기준으로 한다. 이전 PNG 5장을 이번 지점의 이전 캡처로 재사용하지 않는다.

확인할 것: 서울 방향(−Z), 63빌딩 북서쪽·남산 북동쪽·롯데월드타워 동북쪽의 상대 방위, 능선에 가려지는 부분, 한강 폭·섬·교량, 1.7m 인체와 1.8/2.2m 길, 계단 접지, 노멀 방향, 반복 대비, 근경/원경 경계, 390×844 모바일 구도. 계곡에서 시야가 숲·능선에 가려지는 것은 실제 지형에 맞춰 유지한다. 원경이 보여야 한다는 이유로 가림을 제거하지 않는다.

## 대표 확인 필요 — 실행하지 않은 명령

현재 지시는 스크립트 실행을 위험 작업으로 금지하므로 아래 명령을 실행하지 않았다. 네트워크가 되는 허용된 환경에서 실행 및 결과 검토가 필요하다.

```sh
cd /Users/pc-2311001/gwanak-hiking/assets/realistic/tools
export PATH=/Users/pc-2311001/.nvm/versions/node/v22.17.1/bin:$PATH
npm install --ignore-scripts
# sharp 사용 가능 여부 확인 후 필요한 경우, 패키지 설치 후속 스크립트는 별도 검토.
node prepare.mjs
node verify.mjs
```

산개발 통합 이후에만 다음을 실행한다. 현재 코드에 대한 통과 주장이나 캡처 명령은 아니다.

```sh
cd /Users/pc-2311001/gwanak-hiking
export PATH=/Users/pc-2311001/.nvm/versions/node/v22.17.1/bin:$PATH
npm test
npm run build
npm run dev -- --port 5173
```

실행 결과가 없으므로 새 화면 캡처를 첨부할 수 없다. 맥 화면·입력 권한이 없는 상태에서 컴퓨터 조작을 시도하지 않았다. 배포·push·외부 전송·삭제는 수행하지 않았다.
