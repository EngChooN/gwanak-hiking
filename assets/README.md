GLB는 외부 텍스처 없이 자체 제작 형상과 단색 PBR 재질을 포함합니다. 캐릭터는 저폴리 관절 노드 방식이며 스킨/스켈레톤 리타게팅 대상이 아닙니다. 원본 생성 스크립트는 `source/build-assets.mjs`입니다. 수정 후 재생성하면 GLB·manifest·데이터를 덮어쓰므로 현장 자료 교체 시 생성기 입력부터 바꿔야 합니다.

## 산개발 연결 방법

Three.js GLTFLoader로 각 GLB를 직접 불러올 수 있습니다. Vite 개발 서버에서 `/assets/검토.html`을 열면 검토 화면이 나옵니다. `source/load-assets.js`는 게임에 가져다 쓸 로더 예제입니다.

```js
import { loadApproach, loadHiker } from './assets/source/load-assets.js';
const area = await loadApproach('/assets/', 1);
scene.add(area.scene);
const hiker = await loadHiker('/assets/', 0);
scene.add(hiker.scene);
// scene 위치·방향은 게임의 현재 위치와 진행 방향으로 매 프레임 갱신.
hiker.update({clip: 'Walk', distance: walkedDistance, stride: .7});
```

배포 시 GLB·manifest·data 폴더를 정적 `/assets/` 아래 복사하고 로더 코드는 게임 번들에 포함하세요. **기존 앱의 `npm run build`는 이 새 패키지를 자동 복사하지 않습니다. 기존 게임에는 아직 새 모델을 연결하지 않았습니다.** 검토 화면은 Vite 개발용이며 정적 보고서는 `제작-검증-보고.html`입니다.

### 좌표·보행 폭·계단

- 1단위=1m, Y 위, 캐릭터 전방 -Z, 원점은 발바닥 중앙입니다. 캐릭터 신장에는 모자를 포함합니다.
- 지형 GLB는 `manifest.anchor` 상대 좌표입니다. `loadApproach`가 앵커를 한 번 더해 기존 세계 좌표에 놓습니다. 수동 로드 시에도 앵커는 한 번만 더합니다. 서울대 입구 EPSG:5186 원점 자체는 기존 임시값이며 측량 검증되지 않았습니다.
- `walkable-corridor.json`의 `start/end`는 기존 경로의 3D 누적 거리 `s`입니다. 각 단면은 중심선·좌우 가장자리 좌표와 폭을 제공합니다. 좌표 배열은 GLB와 같은 앵커 상대 좌표입니다.
- 캐릭터 반경 .25m를 고려한 중심 제한은 `width/2-.25`입니다. 기존 이동 구현의 여유 폭 .225m는 이 패키지에 연결할 때 .25m로 맞춥니다. 시각 메쉬 자체가 보행 제한이나 충돌 처리를 하지는 않습니다.
- `steps`는 112단의 `start/end/top/width/tread/rise`를 제공합니다. `top`은 앵커 상대 Y입니다. 윗면은 기존 `floorHeight`의 18cm 단과 정렬했습니다. 첫·마지막 단 길이는 구간 경계에서 잘립니다. 이것은 현장 계단 수가 아닙니다.
- 계단 보행 시 루트 Y를 단 윗면에 놓고 한 단 중심에서 다음 단 중심까지의 거리를 보폭으로 사용합니다. 다음 단 도착마다 발소리 1번을 발생시킵니다. 연속 경사 거리로 발소리만 계산하면 계단과 발이 어긋날 수 있습니다.

### 동작과 소리

각 동작의 길이는 정규화된 1초이며 한 주기에 두 걸음입니다. `Idle`, `Walk`, `Climb`, `SidestepLeft`, `SidestepRight`를 제공합니다. 실제 속도에 맞춰 `timeScale=v/(2*stride)`로 설정하거나 제공 로더처럼 실제 누적 거리로 위상을 고정합니다. 평지 .7m, 오르막 .55m, 좌우 .5m를 사용하고 계단에서는 위 단 중심 간 거리를 사용합니다. 애니메이션은 제자리 동작이므로 게임 위치를 움직이지 않습니다.

`source/load-assets.js`는 동작 선택과 거리 동기화 예제입니다. 발바닥 IK는 포함하지 않아 계단에서 발 관통·뜨는 현상을 최종 검증해야 합니다. 자동 검사에서는 관절 트랙 변화와 루트 고정까지 확인했습니다.

| 노면 ID | 속도 계수 | 발소리 이벤트 키 |
|---|---:|---|
| soil | 1.0 | soil |
| rock | .85 | stone |
| stairs | .75 | stair |
| deck | 미정(null) | wood |
| ridge | .65 | ridge |

`speedFactor`는 기획서의 이동 속도 보정 계수입니다. 물리 마찰계수는 별도 `friction:null`로 남겼습니다. `footstep`은 오디오 연결 키이며 녹음 파일을 제공한 것은 아닙니다. 기존 `hiking:step` 이벤트의 material과 연결하고 위상마다 중복 재생하지 않도록 한 군데에서만 소리를 발생시키세요. 데크는 계수가 결정되기 전 보행 경로에 넣지 않습니다. 현재 데크·흙·돌길은 비교용 시설 키트에만 있고 정상 접근의 기존 노면을 임의로 바꾸지 않았습니다.

가까운 계단과 보행 범위는 단계가 달라도 유지합니다. 지형 횡방향·종방향 간격과 숲·바위 밀도를 낮춰 경량화했습니다. LOD0 종방향 간격 약 1m, LOD1 약 3m, LOD2 약 8m이며 DEM 대비 정밀도 주장이 아닙니다. 첫 모바일 로드는 LOD1을 제안합니다. 3개를 동시에 로드하지 말고 교체 시 이전 geometry/material을 해제하세요. 전환 거리 45m/110m와 히스테리시스 10m는 튜닝 시작값이며 자동 LOD 제어기는 포함하지 않습니다. 전 구간 통짜 파일이므로 전체 코스 확장 시 청크 분할이 필요합니다.

`portrait-sky.glb`는 자체 생성 그라데이션 하늘과 구름입니다. 위치를 카메라에 따라가게 놓고 보행 충돌·그림자 대상에서 제외하세요. 검토 화면의 세로 FOV는 64도이며 발밑 지형을 유지합니다. 실제 게임 카메라·성능 조정은 산개발 통합 단계에서 확인해야 합니다.
